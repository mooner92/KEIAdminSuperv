# 24. 표 복원 검수 화면 + 수치 스토어 (지렛대 ①·③ 운영화)

> docs/23의 후속 구현. ① 복원 제안 7건을 SSH 없이 검수·반영하는 관리자 화면,
> ③ 검수 완료된 표의 값을 결정적으로 조회해 근거로 주입하는 수치 스토어.

## 1. 표 복원 검수 화면 (관리자 탭 `🔧 표 복원`)

**원칙**: 반영은 **사람의 명시적 클릭**(=사람 검수 행위)으로만. 자동 반영 없음.
`검수상태` 프론트매터는 건드리지 않는다(문서 전체 검수는 별도 — 표 반영과 구분).

- 백엔드(`app_api.py`, 관리자 전용):
  - `GET /app/corpus/table-restore` — 제안 목록: 문서별 {복원 표(행 데이터), 판정(✅구조복원/⚠원본병합),
    볼트 매칭 가능 여부, 반영 이력}. 소스 = `01p`가 md와 함께 내는 `<문서>.json`(스테이징).
  - `POST /app/corpus/table-restore/{name}/apply` — **결정적 교체**: 볼트 md에서 연속 `|` 표 블록 중
    ⓐ헤더 행이 복원 표와 일치(공백 무시)하고 ⓑ`_table_broken` 판정인 블록만 복원 표로 교체.
    매칭 없으면(평탄화 등) 아무것도 바꾸지 않고 "수동 반영 필요" 반환.
    교체 전 원본을 `tools/index/table_restore/backup/`에 보존 + `CorpusAudit(action=table_restore)`.
  - 반영 후 재색인은 기존 코퍼스 탭의 재색인 버튼(P2) 재사용 — needs_reindex로 표시됨.
- 프론트(`AdminTableRestore.tsx`, admin 탭 추가 — 탭 셸 확장 규약):
  - 문서 카드: 손상 표본(01o 인용) ↔ 복원 표(실제 `<table>` 렌더) 대비, 판정 배지,
    [이 문서에 반영] 버튼(확인 대화상자 → apply), 반영됨/수동 필요 상태.
  - 플래그 `table_restore`(release, off 배포, /admin 토글).

**수용 기준**: ⓐ 목록·대비 렌더(Playwright) ⓑ apply 유닛(임시 볼트 픽스처): 헤더 매칭 교체·백업 생성·
비매칭 무변경 ⓒ ⛔실볼트 자동 반영 없음(E2E는 확인 대화상자까지만 — 실제 반영은 사람)
ⓓ 반영 후 needs_reindex 표시.

## 2. 수치 스토어 (지렛대 ③)

**원칙**: ⛔ **검수 완료 문서의, 손상 아님 판정 표**만 적재(미검수 값 서빙 금지). 스토어가 비면
전 기능 무동작(no-op) — 인프라를 먼저 깔고 검수가 채워지는 대로 활성화되는 구조.

- 적재(`tools/01q_table_store.py` → `tools/index/value_store.json`, gitignore):
  볼트 md의 `|` 표에서 (규정명, 표 라벨, 행 라벨, 열 라벨, 셀 값) 행 단위 추출.
  조건: 프론트매터 `검수상태: 검수완료` + `_table_broken` None + 셀에 수치 존재.
- 조회(`rag_core.retrieve` 확장, `RAG_VALUE_STORE` 기본 on):
  값 질문(얼마·며칠·한도·상한 등) 감지 → 질문 핵심 토큰(`_rw_core_tokens` 재사용)과
  (규정명+행+열 라벨) 토큰 겹침 점수 상위 ≤2행을 `[규정명 표N · 수치 스토어]` 블록으로 첨부,
  srcs 마커 `value_store: true`. LLM은 조회 결과를 **인용만**(생성 아님) — P0-1 게이트와 정합
  (스토어 블록 값은 허용집합에 자연 포함).
- UI: 근거 칩 "📊 수치 스토어"(기존 `source_type_badges` 플래그에 편입 — 출처 성격 배지와 동일 성격).

**수용 기준**: ⓐ 유닛(픽스처 스토어): 값 질문 매칭·비값 질문 무첨부·빈 스토어 no-op
ⓑ 미검수 문서 표가 스토어에 안 들어감 ⓒ 첨부 블록 값이 수치 게이트 허용집합에 포함(경고 없음).
