# docs/58 — 일일 자가평가 루프 (Daily Self-Eval) Spec

> 매일 새벽 **임의 생성 50문항(중복 없이)**을 실서비스 구성으로 답하게 하고, **원문 대조로 채점**해
> 정답률을 **게시판에 공개**하며, 오답은 **원인 분류→개선**으로 잇는 자기개선 루프.
> 사용자 요구(2026-07-22): "테스트셋을 계속 확보 + 틀린 답(문서 대조로 증명되면) 고치고 원인
> 파악·개선 + 오전 6시 테스트 결과 ' 오늘의 정답률 N%' 정보공개(질문·답변·정오 열람)".

## 0. 전체 그림

```
[06:00 cron]
  ① 질문 생성(신규 30 + 회귀 20)  ← 청크에서 생성, 질문은행에 누적(중복 차단)
  ② 실서비스 답변                  ← prod 동등 구성(리랭커 on, /v1 API)
  ③ 3단 채점                       ← 결정적 수치대조 + LLM 원문대조 + 오답 적대재검
  ④ 리포트 저장                    ← eval/daily/YYYY-MM-DD.json + 질문은행 갱신
  ⑤ 게시판 공개                    ← /quality "오늘의 정답률 N%" + 문항 전체 열람
  ⑥ 개선 루프                      ← 오답=원인 분류 → 검수 큐 가중치 → 회귀셋 편입
```

기존 자산 재사용: `eval/pms_audit.py`(원문 대비 채점·refusal 처리·표기 강건성 교훈),
`eval/run_eval.py`(Hit@k), `tools/review_queue.py`(+`.feedback_signals.json` 소비 패턴),
`tools/obs.py`(MaintNotice 알림), PM2 `cron_restart` 관례(피드백 분석기와 동형).

## 1. 질문 생성 (①) — `eval/daily_gen.py`

### 1.1 원천과 방법 (⛔ 창작 0의 응용)
- **원천 = 인덱싱된 청크**(Chroma 5,578개)와 그 원문. 질문은 항상 **특정 청크에서** 생성 —
  그 청크가 곧 **정답 근거(golden)**가 된다(487문항 감사·pms_audit과 같은 원리).
- 생성기(로컬 Qwen, temp 0.7): 청크 원문을 주고 "이 내용만으로 답할 수 있는 실무형 질문 1개"
  생성. 유형 쿼터:
  | 유형 | 비중 | 설명 · 채점 방식 |
  |---|---|---|
  | 값형 | 40% | 금액·일수·기한·비율(예: "국내출장 일비 얼마?") — 결정적 수치대조 가능 |
  | 절차형 | 30% | 절차·서식·경로(예: "연장근로 신청 절차는?") — LLM 원문대조 |
  | 조건형 | 20% | 자격·조건·범위(예: "누가 신청할 수 있나?") — LLM 원문대조 |
  | 거부형 | 10% | **코퍼스에 없는** 주제(주차장·구내식당류) — "확인되지 않습니다" 계열이면 정답 |
- 생성 게이트: 질문 속 숫자는 청크에 있어야(01m2와 동일 게이트) · 질문에 답이 그대로 들어가면 폐기
  ("일비 2만원인가요?" ✗) · 청크 밖 지식 요구형 폐기.

### 1.2 중복 차단 + 질문은행 — `eval/question_bank.jsonl`
- 스키마: `{id, 질문, 유형, 출처{규정명,조,청크id}, 생성일, 최근판정, 판정이력[], 상태}`
- **중복 판정 2중**: ⓐ 정규화 텍스트(공백·조사 제거) 해시 일치 ⓑ KURE-v1 임베딩 코사인 ≥0.92
  → 기존 문항과 유사하면 폐기·재생성(최대 3회 시도 후 그 청크 스킵).
- **커버리지 라운드로빈**: 규정 40% · 가이드 25% · 시스템(ERP/PMS) 25% · 용어 10%.
  청크별 `마지막 출제일`을 은행에 기록 — 미출제 청크 우선(코퍼스 전체를 순환).
- 일일 구성 **신규 30 + 회귀 20**: 회귀 = ⓐ 과거 오답(고쳐질 때까지 매일 재출제) ⓑ 최근 코퍼스
  변경(재색인) 관련 문항 ⓒ 무작위 재검(안정성 표본). 오답 0이면 회귀 몫도 신규로.

### 1.3 문항 태깅(2축) — 약점 지도용 (결정적, LLM 불필요)
- **업무 카테고리**: ⓐ 출처 청크의 규정 분류(볼트 분류 폴더: 인사·복무·여비·회계·보안… — 이미
  존재하는 결정적 값) ⓑ 주제 키워드 사전 매칭(출장·여비·휴가·연차·기안·결재·계약·구매·보안·
  개인정보·연구비… — APPROVAL_KW·여정 13종 재사용, 다중 태그 허용).
- **정량/정성**: 유형에서 유도(값형=정량, 절차·조건·거부형=정성).
- 은행 스키마에 `분류`, `주제[]`, `정량여부` 저장 — 리포트·게시판·추이 전부 이 축으로 집계.

## 1.4 평가 축 레지스트리 — 새 데이터의 자동 편입 (2026-07-26, specs/07 B)

**문제**(사용자 지적): 개정영향·금액전결 같은 **새 데이터 기능이 생겨도 평가는 옛 축(청크 1개)만** 봤다.
기능이 늘 때마다 사람이 문항을 손으로 붙이는 방식은 지속되지 않고, 실제로 그 기능들은
자가평가에서 **한 번도 검증된 적이 없었다**.

**설계** — `eval/axes.py`: 축 = (파생 인덱스, 표본 추출기, **결정적 채점기**, 최소 쿼터).

| 축 | 인덱스 | 문항 | 정답 산출 |
|---|---|---|---|
| `amount` | `amount_rules.json` | "○○ 건 607만원이면 전결권자는?" | 룰 조회(`amount_judge`) |
| `impact` | `graph_analytics.impact_by_article` | "제N조 개정 시 함께 볼 조문은?" | 참조 그래프 |
| `defterm` | `defterms.json` | "'결재권자'란?" | 정의 원문 |
| `deadline` | `deadlines.json` | "귀국일로부터 언제까지?" | 오프셋 값 |

- 질문 = **템플릿 + 인덱스 실값**(LLM 0회) ⟹ 상황 창작이 원천 불가.
- 정답을 인덱스가 이미 가지므로 **채점에 LLM이 없다** — 채점기 오판이 개선 방향을 오도한
  T7·T9 계열 사고가 이 축들에서는 구조적으로 발생하지 않는다.
- 인덱스가 없으면 그 축은 조용히 생략(크론 무중단). 쿼터는 축별 2문항/일(신규 40 중 8).
- 채점은 **보수적**: 기대값도 경합값도 없으면 오답이 아니라 '검토필요'.

**출제 게이트(첫 표본에서 실제로 걸러진 결함 3종)**
① 조사 오류 — '공사･수리은', "'관리'이란" → `_josa` 받침 판정
② 잘린 anchor — "날부터 얼마 이내에?"(질문 불성립) → anchor 6자+기준 어미 요구
③ 역산 조항 — "…역산하여 5년 이내"는 **소급 요건**이지 마감이 아님 → 배제
④ 미완결 정의 — 파서가 중간에서 끊은 정의('…법 제3조')는 정답이 없음 → '말한다' 종결만

**전결권자 대조는 라벨이 아니라 직급 원자로** — 별표 실값이 `부서장`/`부서장/센터장`,
`팀장`/`실･팀장`처럼 같은 직급의 다른 표기라서, 라벨 비교는 정상 답변을 오답으로 만든다.
'부원장'이 '원장'으로 새는 부분문자열 함정도 **긴 표기부터 소비**해 막는다.

**E2E 실측(2026-07-26)**: 축 8문항 생성→실서비스 답변→결정적 채점 = **8/8 정답**.
100%는 난이도가 낮다는 뜻이 아니라 이 축들이 **회귀 트립와이어**로 동작한다는 뜻이다 —
결정적 라우팅(defterm·impact·amount)이 깨지면 다음 날 바로 축 정답률이 떨어진다.
회귀 = `eval/test_axes.py`(판정키↔인덱스 일치 · 정답/오답/거부문 왕복 · 출제 게이트 · 스키마).

**다양성 지표**(specs/07 §4-2) — 측정하지 않으면 문항은 다시 정형화된다. 리포트에 상시 기록:
평균 질문 길이 · 말미 패턴 top5·집중도 · 출처 문서 수 · 축 비중.
2026-07-26 기준선(A트랙 전): 평균 41.9자 · 말미집중도 16.7% · 출처문서 39 · 축비중 0%.


## 1.5 복합 시나리오 문항 — 여정 기반 다중 근거 (2026-07-26, specs/07 A)

**문제**(사용자 지적): "매일 비슷한 질문만 나온다." 원인은 프롬프트가 아니라 **구조**였다 —
`gen_one()`이 청크 **1개**를 주고 "그 원문만으로 답할 수 있는 질문"을 요구한다. 채점 근거를
단일 청크로 고정하려던 설계의 대가로 복합 질문이 원천 차단됐다(실측: 은행 200문항 전부 단일 청크).

**설계** — `eval/scenarios.py`: 골격은 이미 있었다. `90_관리/_journeys/*.json`(여정 13종)은
한 업무의 노드·근거가 구조화돼 있고, 사용자 예시("세종→런던 세미나 — 항공사? 항공비? 숙소비?
귀국시간? 정산?")가 곧 해외출장 여정이다.

```
① 여정 선택(라운드로빈 — 최근 출제 적은 여정 우선)
② 그 여정의 조문 근거 2~4개를 청크로 회수(= 다중 골든의 원천)
③ LLM에 [근거 N개 + 업무 상황]을 주고 "근거를 모두 봐야 답할 수 있는 질문 1개 + 근거별 골든"
④ 게이트 통과분만 채택
```

**게이트(실측 결함이 만든 것)**
| 게이트 | 이유 |
|---|---|
| 골든 verbatim 실존(2그램 80%) | 요약·창작 골든 차단 |
| 질문 속 숫자는 근거에 실존 | 상황 창작 차단 |
| **질문에 값 토큰 금지** | 실측: 골든만 대조하면 근거의 *다른 문장*에 있는 정답이 질문에 샌다 ("복명서는 귀국 후 30일 이내(임원 14일)에 …하며, 마일당 20원을 초과하면…?") |
| 한국어만(한자 혼입 폐기) | 실측: qwen이 후속 질문에 중국어를 섞음("임원 기준도有什么不同吗?") |
| 골든 2개 미만 폐기 | 복합이 아님 |

**멀티턴**: 2턴(`턴[]`)을 **서비스와 같은 경로**로 이어 묻는다(`rag_answer(history=)`) — 그래야
`condense_query`(맥락 유지) 회귀가 평가에 편입된다. 후속 턴이 거부로 새면 정답이라도 '부분' 강등.

**채점**: 골든별 개별 대조(**결정적, LLM 없음**) — 전부 충족=정답 · 일부=부분 · 0건=검토필요(보수적).
LLM 판정을 안 쓰는 이유는 근거가 여러 개면 판정자가 "어느 근거를 봤는지" 흔들려 채점기 오판
(T7·T9 계열)이 되돌아오기 때문이다. 대조는 **2그램 + 어간** 2축 — 어형 그대로 비교하면
'금지한다'와 '금지됩니다'를 다른 말로 보고 정상 의역 답변이 '반영 0건'으로 떨어진다(실측).

**쿼터**: 신규의 25%(`DAILY_EVAL_SCEN`). 단일을 남기는 이유는 코퍼스 전체를 도는
**청크 커버리지 순환**이 복합만으로는 달성되지 않기 때문(여정 13종은 코퍼스의 일부만 덮는다).

**근거가 조문이 아닌 여정도 살린다**: 법인카드사용정산·육아시간사용·도서구입은 근거가 전부
**조 없는 가이드**라 조문만 받으면 흔한 업무가 통째로 빠졌다(출제 가능 9/13). 조가 비면 그 문서의
청크 중 **노드 설명(action)과 2그램이 가장 높은 것**을 결정적으로 고른다(임베딩·LLM 없음,
유사도 0.15 미만이면 폐기) → **12/13**. 골든 verbatim 게이트가 뒤를 받친다.

**실측(2026-07-26)**: 복합 3건 생성 — 물품구매(3근거)·해외출장(2근거)·괴롭힘신고(2근거·멀티턴).
질문 예: "성희롱·성폭력 사건 조사 기간은 어떻게 되며, 피해자에 대한 불이익 조치와 신원 누설에는
어떤 규정이 있나요?" → 근거 2개 전부 반영, 후속 턴 맥락 유지. 회귀 = `eval/test_scenarios.py`.

## 3. 채점 (③) — 3단 판정, "증명" 기준
> 교훈 반영: 이전 감사에서 **채점기가 틀리고 모델이 맞은 사례**(공백 표기·질문 모호성)가
> 실재 — 오답 선언은 보수적으로, "문서 대조로 증명"된 것만.

- **ⓐ 결정적 수치대조**(값형): 답변의 값 토큰(정규화: 공백·콤마 제거, 단위 통일) vs **출처 청크
  원문**. 원문에 없는 값 주장 = 오답 후보(증거=원문 스니펫+어긋난 값 자동 첨부).
- **ⓑ LLM 원문대조**(전 유형): 판정자(로컬 Qwen, temp 0)에게 [질문, 답변, 정답근거 청크 원문]을
  주고 `{판정: 정답|부분|오답|판정불가, 근거문장, 어긋난점}` — 원문에 있는 문장만 근거로 인용
  가능(인용문이 원문에 실존하는지 결정적 검증, 없으면 판정불가로 강등).
- **ⓒ 적대 재검**(오답 후보만): 별도 프롬프트로 "이 오답 판정을 반박하라"(관점: 표기 변형·

- ❌ **부정형 불일치**("해당하지 않는" 질문 + 긍정 골든) — 4건 중 3건이 오탐(정밀도 25%) → 미채택.
  문제 문항 1건만 개별 retire.

**남은 뿌리**: 재채점 후 오답 3건이 **전부 출제 결함 계열**이었고, 셋 다 PMS·ERP **화면 캡처

## 6d. 코호트 분리와 실패유형 분류 (2026-07-30, 사용자 질문 "뭐가 낫지?"에서 출발)

**ⓐ 코호트 2분할** (`daily_grade.cohort_of`, 문항 필드 `코호트`)

  오답 **7 → 1**(618만원 매각·연구윤리 제6조 인용·ERP 화면 2건·수의계약 등). 합산 숫자에서는
  이 신호가 신규 51건에 묻혀 보이지 않았다.
- **신규** = 오늘 처음 출제 → **커버리지 신호**(표본 구성에 크게 흔들림).
- ⚠ 판정은 **오늘 `판정이력`을 append하기 전에** 해야 한다(후에 하면 전부 '재시험'이 된다).
- ⛔ 합산 `정답률` 계산식은 **바꾸지 않는다**(과거 일자와 비교 가능해야 한다). 코호트는

**ⓑ 실패유형 자동 분류** (`daily_grade.classify_failure`, 문항 필드 `실패유형`)

## 8. 코퍼스 개정 대응 — 골든 자가검증 동기화 (2026-07-22, 사용자 논의)
"개정·재색인 시 골든 정답을 연쇄 수정하려면 관계그래프가 필요한가?" → **불필요**가 결론.
골든문장은 **원문 verbatim 인용**이라 그 자체가 검증 키(content-addressed)이고, 연결 정보는
은행의 `출처{규정명,조,청크id}`로 이미 존재(외래키). 별도 그래프는 이중 관리만 늘림.

`daily_gen --sync`(재색인 후 + daily_run 0단계, LLM 0회·결정적):
  ① (규정명,조)의 새 청크에 골든 실존(2-그램 80%) → **청크id 재바인딩**(개정 무관 문항)
  ② 조는 있는데 골든 소멸 → **stale**(조문 개정 의심 — 회귀 풀 제외, 재출제 대상 목록 출력,
     재색인으로 복원되면 active 자동 복귀)
  ③ 조 소멸 → **retire**(삭제)
연쇄 수정 = 그래프 탐색이 아니라 **검증 실패 목록**으로 자동 도출. Track A 개정 인덱스와
자연 정합(같은 규정명·조 축).
