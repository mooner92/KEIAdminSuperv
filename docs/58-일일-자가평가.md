# docs/58 — 일일 자가평가 루프 (Daily Self-Eval) Spec

> 매일 새벽 **임의 생성 50문항(중복 없이)**을 실서비스 구성으로 답하게 하고, **원문 대조로 채점**해
> 정답률을 **게시판에 공개**하며, 오답은 **원인 분류→개선**으로 잇는 자기개선 루프.
> 사용자 요구(2026-07-22): "테스트셋을 계속 확보 + 틀린 답(문서 대조로 증명되면) 고치고 원인
> 파악·개선 + 오전 6시 테스트 결과 ' 오늘의 정답률 N%' 정보공개(질문·답변·정오 열람)".

## 0. 전체 그림

```
[06:00 cron]
  ① 질문 생성(신규 30 + 회귀 20)  ← 청크에서 생성, 질문은행에 누적(중복 차단)
  ② 실서비스 답변                  ← prod 동등 구성(리랭커 on, /v1 API)
  ③ 3단 채점                       ← 결정적 수치대조 + LLM 원문대조 + 오답 적대재검
  ④ 리포트 저장                    ← eval/daily/YYYY-MM-DD.json + 질문은행 갱신
  ⑤ 게시판 공개                    ← /quality "오늘의 정답률 N%" + 문항 전체 열람
  ⑥ 개선 루프                      ← 오답=원인 분류 → 검수 큐 가중치 → 회귀셋 편입
```

기존 자산 재사용: `eval/pms_audit.py`(원문 대비 채점·refusal 처리·표기 강건성 교훈),
`eval/run_eval.py`(Hit@k), `tools/review_queue.py`(+`.feedback_signals.json` 소비 패턴),
`tools/obs.py`(MaintNotice 알림), PM2 `cron_restart` 관례(피드백 분석기와 동형).

## 1. 질문 생성 (①) — `eval/daily_gen.py`

### 1.1 원천과 방법 (⛔ 창작 0의 응용)
- **원천 = 인덱싱된 청크**(Chroma 5,578개)와 그 원문. 질문은 항상 **특정 청크에서** 생성 —
  그 청크가 곧 **정답 근거(golden)**가 된다(487문항 감사·pms_audit과 같은 원리).
- 생성기(로컬 Qwen, temp 0.7): 청크 원문을 주고 "이 내용만으로 답할 수 있는 실무형 질문 1개"
  생성. 유형 쿼터:
  | 유형 | 비중 | 설명 · 채점 방식 |
  |---|---|---|
  | 값형 | 40% | 금액·일수·기한·비율(예: "국내출장 일비 얼마?") — 결정적 수치대조 가능 |
  | 절차형 | 30% | 절차·서식·경로(예: "연장근로 신청 절차는?") — LLM 원문대조 |
  | 조건형 | 20% | 자격·조건·범위(예: "누가 신청할 수 있나?") — LLM 원문대조 |
  | 거부형 | 10% | **코퍼스에 없는** 주제(주차장·구내식당류) — "확인되지 않습니다" 계열이면 정답 |
- 생성 게이트: 질문 속 숫자는 청크에 있어야(01m2와 동일 게이트) · 질문에 답이 그대로 들어가면 폐기
  ("일비 2만원인가요?" ✗) · 청크 밖 지식 요구형 폐기.

### 1.2 중복 차단 + 질문은행 — `eval/question_bank.jsonl`
- 스키마: `{id, 질문, 유형, 출처{규정명,조,청크id}, 생성일, 최근판정, 판정이력[], 상태}`
- **중복 판정 2중**: ⓐ 정규화 텍스트(공백·조사 제거) 해시 일치 ⓑ KURE-v1 임베딩 코사인 ≥0.92
  → 기존 문항과 유사하면 폐기·재생성(최대 3회 시도 후 그 청크 스킵).
- **커버리지 라운드로빈**: 규정 40% · 가이드 25% · 시스템(ERP/PMS) 25% · 용어 10%.
  청크별 `마지막 출제일`을 은행에 기록 — 미출제 청크 우선(코퍼스 전체를 순환).
- 일일 구성 **신규 30 + 회귀 20**: 회귀 = ⓐ 과거 오답(고쳐질 때까지 매일 재출제) ⓑ 최근 코퍼스
  변경(재색인) 관련 문항 ⓒ 무작위 재검(안정성 표본). 오답 0이면 회귀 몫도 신규로.

### 1.3 문항 태깅(2축) — 약점 지도용 (결정적, LLM 불필요)
- **업무 카테고리**: ⓐ 출처 청크의 규정 분류(볼트 분류 폴더: 인사·복무·여비·회계·보안… — 이미
  존재하는 결정적 값) ⓑ 주제 키워드 사전 매칭(출장·여비·휴가·연차·기안·결재·계약·구매·보안·
  개인정보·연구비… — APPROVAL_KW·여정 13종 재사용, 다중 태그 허용).
- **정량/정성**: 유형에서 유도(값형=정량, 절차·조건·거부형=정성).
- 은행 스키마에 `분류`, `주제[]`, `정량여부` 저장 — 리포트·게시판·추이 전부 이 축으로 집계.

## 2. 답변 (②) — 실서비스 동등 구성
- `POST 127.0.0.1:{port}/v1/chat/completions` — **평가 전용 env 금지**, 서비스 그대로
  (리랭커 on — docs/55 교훈: rerank off 평가는 6%p 저평가). 대상 서버는 인자(`--api`)로:
  dev 검증기는 9001, 운영 등록은 prod 9000.
- 문항당 독립 단발(멀티턴 없음). `x_sources` 저장(검색 실패 분류에 사용).

## 3. 채점 (③) — 3단 판정, "증명" 기준
> 교훈 반영: 이전 감사에서 **채점기가 틀리고 모델이 맞은 사례**(공백 표기·질문 모호성)가
> 실재 — 오답 선언은 보수적으로, "문서 대조로 증명"된 것만.

- **ⓐ 결정적 수치대조**(값형): 답변의 값 토큰(정규화: 공백·콤마 제거, 단위 통일) vs **출처 청크
  원문**. 원문에 없는 값 주장 = 오답 후보(증거=원문 스니펫+어긋난 값 자동 첨부).
- **ⓑ LLM 원문대조**(전 유형): 판정자(로컬 Qwen, temp 0)에게 [질문, 답변, 정답근거 청크 원문]을
  주고 `{판정: 정답|부분|오답|판정불가, 근거문장, 어긋난점}` — 원문에 있는 문장만 근거로 인용
  가능(인용문이 원문에 실존하는지 결정적 검증, 없으면 판정불가로 강등).
- **ⓒ 적대 재검**(오답 후보만): 별도 프롬프트로 "이 오답 판정을 반박하라"(관점: 표기 변형·
  질문 모호성·부분 정답). 반박 성공 → `검토필요`로 강등(오답 아님).
- 거부형: `확인되지 않|확인할 수 없` 계열이면 정답(pms_audit ⓓ 재사용).
- **최종 상태**: `정답 | 오답(증거 첨부) | 검토필요 | 판정불가`. 정답률 = 정답/(전체−판정불가).
  ⛔ 오답이라도 **콘텐츠 수정은 사람 확정 후**(절대 규칙 — 자동 판정은 신호일 뿐, 게시판에도
  "자동 평가·검수 전" 상시 명시).

## 4. 저장 (④)
- `eval/daily/YYYY-MM-DD.json`: `{date, 정답률, 상태별 수, 문항[]:{id, 질문, 답변, 판정, 증거,
  출처, x_sources, 소요}}` (gitignore — 답변 전문 포함).
- `eval/question_bank.jsonl` 갱신(판정이력 append).
- 웹 공개용 요약 `web/public/quality/daily/YYYY-MM-DD.json` + `index.json`(최근 90일 추이):
  server.js가 직서빙(재빌드 불필요 — forms-pdf와 동일 패턴).

## 5. 게시판 공개 (⑤) — `/quality` (flag `quality_board`)
- **내부 서비스라 로그인 뒤 공개**(테스트 질문은 합성이라 개인정보 없음 — k-익명 불필요.
  단, 실사용자 질문은 절대 미포함).
- 구성:
  - 히어로: **"오늘의 정답률 N%"** (M문항 중 K정답 · 오답 J · 검토필요 L) + 실행 시각.
  - **추이 차트**(최근 30일 라인·CSS) + 유형별 정답률 미니바.
  - **약점 지도**: 카테고리×유형 정답률 매트릭스(히트맵) + "최약 영역" 자동 하이라이트
    (예: "여비×값형 60% — 최약"). 표본 5문항 미만 셀은 회색(통계 미성숙 표시).
  - **문항 테이블**: 질문 · 판정 배지(✅/❌/🔍검토필요) · 펼치면 [모델 답변 전문 · 정답 근거
    원문(하이라이트) · 오답 증거 · 근거 조문 링크(드로어)].
  - 오답 상세엔 **원인 분류 칩**(§6)과 처리 상태(개선 전/후) — "틀린 건 이렇게 고치고 있다"까지
    공개해 신뢰 형성.
  - 면책 고정: "자동 생성 문항·자동 채점(검수 전)입니다. 서비스 품질의 지표이며 개별 답변의
    보증이 아닙니다."
- 진입: 추가 기능(/now) 허브 카드 "📊 품질 게시판 — 오늘의 정답률 N%".

## 6. 개선 루프 (⑥) — 오답의 소비
- **원인 자동 분류**(오답·검토필요마다): 
  | 원인 | 판정 신호 | 자동 액션 |
  |---|---|---|
  | 검색 실패 | x_sources에 정답 청크 없음 | Hit@k 회귀 기록(run_eval 연계) |
  | 생성 환각 | 근거엔 정답 있는데 답변이 다름 | 프롬프트/모델 이슈 목록 |
  | 원문 결함 | 근거 청크 자체가 깨짐(표 등) | **검수 큐 가중치**(review_queue 신호 파일에 `daily_eval` 소스 추가) |
  | 채점 오류 | 적대 재검에서 반박됨 | 채점기 개선 백로그(검토필요로 공개) |
- 오답 문항은 **회귀셋 자동 편입** — 상태 `open`으로 매일 재출제, 3일 연속 정답 시 `fixed`.
- **FAQ 브리지 노트(질문-정답 세트의 RAG 환류)** — '검색 실패' 오답 전용 개선책:
  질문 문체 청크는 질문↔질문 임베딩 유사도로 회수돼 검색 실패를 직접 개선한다(구어↔조문 문체
  간극 해소). ⛔ **순환 환각 가드**(모델 생성물이 코퍼스에 들어가 자기 인용되는 것 차단):
  ① FAQ 노트의 답 = **원문 문장 그대로 인용 + `[[규정명#제N조]]` 링크만**(모델 문장 편입 금지)
  ② 파이프라인은 **후보 초안 생성까지만**(`eval/faq_candidates/`) — 볼트(`10_업무가이드/FAQ/`)
    편입은 **사람 검수 후**(corpus 승인 관례와 동일, 자동 편입 금지)
  ③ `type: faq` 별도 신분 + 근거 패널 "💬 FAQ(참고)" 배지 — 진실원천(규정원문)과 구분,
    답변의 출처 표기는 여전히 원문 조문.
  효과 측정: 편입된 FAQ와 연결된 회귀 문항의 fixed 전환율을 리포트에 표기(개선이 실제로
  먹혔는지 폐루프 검증).
  **✅ 구현(2026-07-22, flag `faq_bridge`)**: /admin 🌉 FAQ 브리지 탭 — `GET/POST /app/faq-candidates(/apply|/dismiss)`
  (current_admin). 후보 파싱(같은 질문은 최신 날짜만, id=sha1(질문)[:12]) → 카드에서 질문·인용 다듬기
  (인용 비면 편입 거부 — 답 생성 금지 강제) → [편입] 시 `10_업무가이드/FAQ/FAQ-<질문>.md` 기록 +
  `_mark_stale`(⟳ 재색인 필요) + CorpusAudit(faq_apply/faq_dismiss, 상태 영속). E2E 12/12
  (`web/verify-faq-bridge.mjs`). ⚠ 신분은 §설계의 `type: faq` 대신 **`type: guide` + `분류: FAQ`**
  채택 — 02 청킹·근거 배지(📘가이드(참고))가 이미 guide를 처리, 전용 faq 타입·💬배지는 후속.
- 주간 요약: 오답 상위 규정·원인 분포를 관리자 대시보드(/admin 신뢰 탭 옆)에 1카드.
- ⛔ 검수상태 변경·원문 수정은 계속 **사람만**. 루프는 우선순위와 증거를 공급할 뿐.

## 6b. 개선 루프 실증 — 첫 완주 (2026-07-24, 사용자 논의 "측정만 하면 무의미")

   확인된"·정답 뒤 꼬리 부가안내를 거부로 집계)을 냄이 실측돼, `tools/refusal_detect.py`
   **단일 정본**(결론부 스코프+부정형 한정+능동형 변형)으로 교체 — daily_grade·regress_refusal·
   ab_model_test·pms_audit·app_api 5곳 공용, 유닛 12종(`tools/test_refusal_detect.py`).
   ⛔ 이후 거부 판정 정규식을 개별 파일에 다시 복제하지 말 것(복제가 T7→T9 재발의 뿌리).
2. **근본 원인 수정** — 진짜 오답(거부형 과잉응답)의 기전: 규정 밖 사안(구내식당)에 검색이 표면
   단어 겹치는 무관 조문(여비규정 출장 초청)을 회수 → 모델이 억지 답. **SYSTEM 규칙17**: 근거
   조문 중 어느 것도 질문 사안을 직접 규율하지 않을 때만 거부(시설·편의 이용은 코퍼스에 대개
   없음), ⚠단 근거가 실제 규율하면 정상 답(과잉 거부 금지).
3. **골든셋 회귀 검증**(`eval/regress_refusal.py`) — ⛔골든을 답변에 주입하는 게 아니라, **프롬프트
   개선의 안전망**: MUST_REFUSE(규정 밖 → 거부해야) + MUST_ANSWER(골든 보유 정상 질문 → 거부
   안 하고 골든 핵심 토큰 보존해야)를 실호출 대조. **1차 규칙안이 정상 질문 2건을 과잉 거부 →
   회귀 하네스가 잡아냄 → 규칙 완화**. 결과: 규정밖 5/5 거부·정상 12/15(잔여 3=샘플링 노이즈
   1[재실행 시 정답]·모호 질문 1·골든 표현차 1 — 조사 결과 체계적 회귀 아님).

**골든셋의 올바른 활용(사용자 오해 교정):** "골든셋을 만들면 답변에 적용해 정답률을 올린다"는
직관은 **순환 환각**(모델 관여 콘텐츠가 코퍼스로 들어가 자기 인용) 때문에 ⛔직접 주입 불가.
골든셋의 진짜 쓸모 = ⓐ 채점 기준(원문 대조) ⓑ **프롬프트 변경의 회귀 안전망**(§6b-3). 검색 실패
오답의 환류는 별도로 **FAQ 브리지**(§6, 원문 인용만·사람 승인)가 담당 — 단, 현재 검색은 튼튼해
검색 실패 오답이 ~0이라 대기 중(오답은 대부분 '생성환각'·'채점오류').

**표준 절차로 승격:** 프롬프트/게이트를 바꿀 때는 `regress_refusal.py`를 돌려 회귀를 확인한다
(측정→진단→수정→회귀검증의 폐루프). 하네스가 flag하면 **자동 반려가 아니라 사람이 조사** —
일일 평가와 동일 철학(신호 공급, 확정은 사람).

### 7c. 골든 보존 판정의 노이즈 제거 (2026-07-25)
회귀 하네스(`regress_refusal.py`)의 `golden_hit`이 순수 2-그램 보존률(≥0.55)만 봐서, **답변이 정확한데도**
표현을 다듬으면 임계 근처에서 거짓 회귀가 났다 — 실측: "임금피크 적용 시 연차유급휴가" 문항이
근거·결론 모두 정확한데 **54% vs 임계 55%**로 탈락(MUST_ANSWER 7/10).

⟹ **두 축 중 하나만 만족하면 보존**으로 판정:
① 2-그램 보존률 ≥ 0.5 ② **핵심어 보존** ≥ 0.8(골든의 숫자·2자+ 내용어, 불용어 제외)

## 8. 코퍼스 개정 대응 — 골든 자가검증 동기화 (2026-07-22, 사용자 논의)
"개정·재색인 시 골든 정답을 연쇄 수정하려면 관계그래프가 필요한가?" → **불필요**가 결론.
골든문장은 **원문 verbatim 인용**이라 그 자체가 검증 키(content-addressed)이고, 연결 정보는
은행의 `출처{규정명,조,청크id}`로 이미 존재(외래키). 별도 그래프는 이중 관리만 늘림.

`daily_gen --sync`(재색인 후 + daily_run 0단계, LLM 0회·결정적):
  ① (규정명,조)의 새 청크에 골든 실존(2-그램 80%) → **청크id 재바인딩**(개정 무관 문항)
  ② 조는 있는데 골든 소멸 → **stale**(조문 개정 의심 — 회귀 풀 제외, 재출제 대상 목록 출력,
     재색인으로 복원되면 active 자동 복귀)
  ③ 조 소멸 → **retire**(삭제)
연쇄 수정 = 그래프 탐색이 아니라 **검증 실패 목록**으로 자동 도출. Track A 개정 인덱스와
자연 정합(같은 규정명·조 축).
