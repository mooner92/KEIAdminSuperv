# docs/61 — 상위 법령 레이어 (설계안, 2026-07-22)

> 상태: **설계만 · 구현 미착수**(사용자 승인 후 착수). 코드 변경 없음.
> 배경 조사: NRC/공공 규정 코퍼스(이전 턴), `korean-law-mcp` 등 MCP 저장소 비교(이 턴).
> 관련: [[data-separation-security]] · CLAUDE.md 절대규칙 1·3·5 · `50_대외업무`의 "(운영 통계)" 라벨 선례.

## 0. 한 줄 정의
KEI 사내 규정에 **없는** 질문(휴가 기안·연구비 카드 조건 등)에, 사내 규정의 **상위 규범**
(연구개발비 고시·혁신법·복무예규 등)을 **별도 레이어**로 두고, 거부(“규정에서 확인되지 않습니다”)를
**약화시키지 않은 채 그 뒤에** `(상위 법령)` 라벨로 참고를 덧붙인다.

## 1. 왜 — 문제와 목표
- 현상: 사내 규정에 항목이 없으면 챗봇은 "확인되지 않습니다"로 끝난다(절대규칙대로, 옳음).
  하지만 그 답의 상당수는 **상위 법령에는 명확히 존재**한다(연구비 카드 = 「국가연구개발사업
  연구개발비 사용 기준」 고시, 휴가·복무 = 인사혁신처 예규).
- 목표: **빈손 거부의 UX 약점만 보완**하되, 사내 규정과 일반 법령의 경계를 항상 사용자에게
  보이게 유지(절대규칙 1·3 불변). 사내 근거가 있으면 그게 정본, 상위 법령은 **보조**로만.

## 2. 왜 MCP를 쓰지 않는가 (조사 결론)
`korean-law-mcp`(chrisryugj, TS/Node, MIT)·`mcp-kr-legislation`(ChangooLee, **Python/FastMCP**, MIT)·
`seo-jinseok/korean-law-mcp`(Python) 모두 결국 **law.go.kr(법제처) DRF Open API를 감싼 래퍼**다.
MCP는 "런타임에 에이전트가 도구를 실시간 호출"하는 모델이라 우리 구조와 **세 가지가 어긋난다**:

1. **오프라인 원칙 위반**(절대규칙 5) — 질문마다 외부 정부 API를 때리면 사내망 격리가 깨지고,
   API 점검·장애 시 답변이 멈춘다.
2. **의미 검색 우회** — API는 "법령 문서 하나"를 줄 뿐, 그 안 **어느 조문이 근거인지**는 못 찾는다.
   그 일을 하는 게 우리 임베딩(KURE-v1)+리랭커(bge-v2-m3)다. 실시간 호출은 이 파이프라인을 건너뛴다.
3. **로컬 Qwen 함수콜 한계** — MCP 클라이언트가 붙으려면 안정적 tool-calling이 필요한데
   Qwen3.5-9B로는 신뢰도가 낮고, 우리 답변 파이프라인은 애초에 "검색→주입→생성"(툴콜 아님)이다.

⇒ **MCP 서버는 도입하지 않는다.** 대신 위 저장소(특히 Python인 `mcp-kr-legislation`이
레포에 **법제처 API 173개 JSON 메타 + 크롤러**를 포함)의 **API 매핑·파라미터·별표 추출 로직만
설계 참고**로 쓰고, 수집은 우리 파이프라인 도구(아래 §4)로 흡수한다.

## 3. 왜 cron 미러링인가 (용량·속도 검토 — 사용자 논의)
- **용량**: 전체 법령 DB(수십만 건)가 아니라 **KEI에 실제 적용되는 상위 규범 allowlist 30~50건**만
  받는다. 전부 텍스트 → **총 10~30MB**(우리 볼트와 동급). "엄청 크다"는 전체 미러링 가정일 때 얘기.
- **속도(호출식)**: law.go.kr 호출당 수백ms~1s로 "못 쓸" 정돈 아니지만, 위 §2의 오프라인·의미검색·
  함수콜 문제가 속도보다 크다. → 런타임 호출 기각.
- **cron 증분**: 매일 allowlist의 **시행일자 메타만 싸게 조회 → 우리 버전과 diff → 바뀐 것만 본문
  재수집·재임베딩**. 평상시 "변경 없음"으로 수 초 종료. 우리 골든 `--sync`·코퍼스 재색인과 동형.

## 4. 구조 (빌드타임 수집 → 별도 레이어 → 라벨 회수)

### 4-1. 볼트 레이어
- 신규 폴더 **`25_상위법령/`** (20_규정원문과 병렬, 그러나 **사내 규정 아님**을 폴더·라벨로 구분).
  분류 예: `연구개발비고시`·`복무예규`·`혁신법령`·`NRC공통규정`.
- 프론트매터: `type: uplaw`(신규 신분), `법령명`, `공포일자`, `시행일자`, `소관부처`, `출처URL`,
  `검수상태: 미검수`, `적용강도(직접|준거|참고)`. ⛔ 원문 의역 금지(절대규칙 2 동일 적용).

### 4-2. 수집 스크립트 `tools/01h_law_fetch.py` (가칭)
- law.go.kr **DRF Open API 직접 호출**(MCP 없음):
  - 목록: `http://www.law.go.kr/DRF/lawSearch.do?OC=<키>&target=<법령종류>&type=XML&query=…`
  - 본문: `http://www.law.go.kr/DRF/lawService.do?OC=<키>&target=…&type=XML&…`
  - `target` 확인 필요: 법령=`law`/`eflaw`, **행정규칙(고시·훈령·예규)=`admrul`**, 해석례=`expc`.
    (고시·예규가 실제 어느 target으로 나오는지는 OC 키 발급 후 실호출로 검증 — §6 미검증 항목)
- **인증**: 법제처 OC 키(무료, `open.law.go.kr/LSO/openApi/guideList.do`). env `LAW_OC`.
  사내망 대비 `LAW_API_PROTOCOL=http`·`LAW_REFERER`(law.go.kr은 Referer 요구) 참고(korean-law-mcp env에서 확인).
- 변환: XML → 조문 단위 마크다운(우리 `제N조` 구조 유지) → `25_상위법령/`. 별표·서식은 기존
  별지 파이프라인(`01p_byeolji_pdf.py`) 재사용 가능.
- **증분**: allowlist(`tools/law_allowlist.json`)의 각 항목 `시행일자`를 조회해 저장분과 diff,
  변경분만 재수집. 산출 로그로 "갱신 N건 / 무변경 M건" 표기.

### 4-3. 임베딩
- **별도 Chroma 컬렉션**(예: `kei_uplaw`) — 사내 규정(`kei_regs`)과 물리 분리. 재색인 독립.
- 청킹은 규정원문과 동일(제N조 단위).

### 4-4. 회수·답변 (라벨 게이트)
- `rag_core.retrieve`가 사내(`kei_regs`) 회수 결과가 **비거나 신뢰도 낮을 때만** `kei_uplaw`를
  보조로 조회(플래그 `RAG_UPLAW_LAYER`, 기본 off). 사내 근거가 있으면 상위 레이어는 첨부 안 함.
- 근거 블록에 **`(상위 법령 — 사내 규정 아님, 적용강도: 직접|준거|참고)`** 라벨(‘운영 통계’ 라벨과
  동형, `rag_core.SYSTEM` 신규 규칙으로 처리).
- **SYSTEM 신규 규칙(초안, 규칙15 예정)**: "[근거]에 '(상위 법령)' 라벨이 붙은 블록은 KEI 사내
  규정이 **아니라 상위 법령**이다. ⓐ 먼저 '사내 규정에서는 확인되지 않습니다'를 유지하고, ⓑ 그
  뒤에 '일반적으로 상위 법령(<법령명>)은 …'으로 **구분해** 안내한다. ⓒ 적용강도가 '참고'(예:
  공무원 복무예규)면 'KEI에 직접 적용되는지는 규정·담당 부서 확인이 필요합니다'를 반드시 붙인다.
  ⓓ 수치·한도는 그 상위 법령 원문에 있을 때만 인용(기존 수치 게이트 동일 적용)."
- UI: 근거 패널에 **📜 상위 법령** 칩(기존 source_type_badges 게이트 재사용).

## 5. 절대규칙 정합성 체크
| 규칙 | 준수 방법 |
|---|---|
| 1 지어내기 금지 | 상위 법령도 **원문 인용 + 출처URL**만. 수치는 원문에 있을 때만(수치 게이트 적용). |
| 2 원문 의역 금지 | `25_상위법령/`도 원문 보존, 조 구조 유지. |
| 3 출처 표기 | `[법령명 제N조]` + 출처URL. `(상위 법령)` 라벨로 사내와 구분. |
| 4 가드레일 불변 | 거부 문구를 **덮어쓰지 않고 뒤에 덧붙이는** 구조 — 거부는 사내 규정 층에만 적용, 유지. |
| 5 인터넷 미공개 | 수집은 **빌드타임만** 인터넷 접촉. 런타임은 오프라인 임베딩만 사용. |

## 6. 미검증(구현 전 반드시 확인)
1. **law.go.kr Open API 이용약관·재배포 조건** — 온프레미스 대량 임베딩·재배포가 허용되는지.
   (⚠ 절대규칙 관점 최우선 — 적재 전 약관 검토 필수.)
2. 고시(`admrul`)·해석례(`expc`) target으로 "연구개발비 사용 기준"·"복무예규"가 실제 조회되는지
   (OC 키 발급 후 실호출).
3. NRC 공통 규정(`rule.nrc.re.kr`)의 공개/로그인 여부(law.go.kr 미수록분은 별도 경로 필요).

## 7. allowlist 초안 (KEI 적용 강도순)
| 법령 | target(추정) | 적용강도 |
|---|---|---|
| 국가연구개발사업 연구개발비 사용 기준(과기정통부 고시) | admrul | 직접 |
| 국가연구개발혁신법 + 시행령 + 시행규칙 | law/eflaw | 직접 |
| 공공기관의 운영에 관한 법률 + 관련 지침 | law | 직접(운영층) |
| NRC 공통 규정(정관·예산회계·인사·연구윤리) | (별도 경로) | 준거 |
| 국가공무원 복무·징계 관련 예규(인사혁신처) | admrul | 참고(직접 적용 아님 명시) |
| 국가공무원법 · 국가공무원 복무규정 | law | 참고 |

## 8. 단계 (승인 후)
- **U1** OC 키 발급 + 약관 검토 + target 실호출 검증(§6). 산출: 검증 메모.
- **U2** `01h_law_fetch.py` + `law_allowlist.json` — 고시 1~2건 PoC 수집·마크다운 품질 눈검증.
- **U3** allowlist 확장 + `kei_uplaw` 컬렉션 임베딩 + cron 증분(`daily`엔 얹지 않고 별도 주기).
- **U4** `rag_core` 라벨 회수 + SYSTEM 규칙15 + 📜 칩 + flag `RAG_UPLAW_LAYER`/`uplaw_layer`.
- **U5** 골든셋에 상위법령 문항 추가 → 지표 불변(사내 답변 회귀 없음) 검증.
