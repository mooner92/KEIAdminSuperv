# 22. 신뢰 게이트 (P0) — 수치·적용대상·표 무결성·시스템 귀속

> 배경: 페르소나 시뮬레이션(2026-07-09, 6 에이전트 ~30턴 라이브 사용 + 로그 채굴)에서 실측된
> 오답 5건(전부 볼트 원문 대조로 확인)을 **구조적으로 차단**하는 결정적(deterministic) 장치 묶음.
> 원리 = `_ensure_disclaimer`(면책 문구 100% 보장)와 동일: 모델 확률을 올리는 게 아니라,
> 모델이 실수해도 틀린 숫자·틀린 권리 안내가 **신뢰된 채로 사용자에게 도달하지 못하게** 한다.
> ⛔ 절대 규칙 1(값은 근거에만)·4(가드레일 약화 금지)의 서버측 강제판. 재임베딩 불필요.

## 0. 실측 오답과 담당 게이트

| # | 실측 오답 (dev, 원문 대조 확인) | 기전 | 차단 게이트 |
|---|---|---|---|
| 1 | "연간 근무일수 총 248일 [복무규정 제11조]" (조문에 없는 수치) | 무근거 계산 환각 | **P0-1 수치 게이트** |
| 2 | 연말정산 "회계 증빙 마감 1월 18일(목)" (근거 어디에도 없음) | 무근거 날짜 생성 | **P0-1** (날짜 검증) |

한계(정직하게): 수치 게이트는 **조작(fabrication) 차단기**다. 값이 근거 어딘가에 *있으면* 통과하므로,
"다른 문서의 값을 가져다 답함"(숙박비를 수탁 가이드라인 값으로)류 **오귀속**은 P0-3(깨진 표 제외)과
P1 검색 보강(별표 동반 회수)의 몫이다. #4처럼 관계("이상↔미만")가 뒤집힌 오답도 수치 매칭으론 못 잡는다
— 그래서 P0-2가 별도로 존재한다.

## 1. P0-1 — 수치 검증 게이트 (`rag_core.numeric_guard_note`)

**정책**: 답변의 위험 수치(화폐·%·일수·개월·년·시간·날짜)가 ⓐ근거 컨텍스트 ⓑ사용자 질문
ⓒ답변 내 명시적 계산식(피연산자가 전부 검증된 경우의 결과) 어디에도 없으면, 답변 끝에
**⚠️ 미검증 수치 경고를 결정적으로 부착**하고 해당 수치를 나열한다.

- 정규화: 콤마 제거, 한글 단위 승수(억/만/천), `X만Y천원` 복합, "10분의 N"→백분율, 날짜 (M,D)쌍.
- 제외(인용 번호): 제N조/항/호, 별표·별지 N, 개정 연월일(YYYY. M. D.), 내선·전화, ERP 메뉴코드.
- 계산식 허용: `A × B = C`/`A + B = C` 꼴 라인은 피연산자 검증 + 산술 일치 시 결과 C 허용
  (SYSTEM 규칙 10의 "계산식을 보여라"와 정합 — 식 없이 던진 합계는 경고 → 식 제시를 유도).
- **스트리밍 제약과 선택**: 이미 방출된 토큰은 회수 불가 → "문장 삭제"가 아니라 **사후 경고 부착**
  (스트림 말미 delta로 경고 방출 + 저장본에 포함). 비스트리밍·`/v1`(OpenAI 호환) 경로도 동일 부착.
- 배선: `app_api.post_message`(stream/비stream) + `04_rag_api`(/v1) — 생성 직후 공통 헬퍼 호출.
- 토글: `RAG_NUM_GATE`(기본 on). 실패는 무경고 강등(게이트 오류가 답변을 막지 않음).

## 2. P0-3 — 표 무결성 격리 (`tools/01o_table_integrity.py` → `tools/index/table_integrity.json`)

**정책**: 구조가 무너진 표(한 셀에 여러 항목·금액이 뭉친 것 — 상조회규약 별표가 전형)를 색인해,
그 청크가 근거로 쓰일 때 ⓐ블록 라벨에 `⚠ 표 구조 손상 — 수치 인용 금지` ⓑSYSTEM 규칙으로 수치
인용 금지·원문 표 확인 안내 ⓒ**P0-1 허용 수치 집합에서 그 블록의 수치를 제외**(깨진 표의 '실존 값'도
오결합 위험이므로 경고 대상) ⓓ근거 카드에 "⚠ 표 확인" 배지 ⓔ검수 큐 가산(위험 문서 우선 검수).

- 탐지 휴리스틱(재임베딩 불필요, article_status와 같은 오버레이 방식·`규정명#조` 키):
  표 셀 하나에 화폐 금액 ≥5개(라벨 짝 살아있는 상한 3종류는 정상), 무공백 병합 숫자('51'=5/1), 평탄화 표(| 없이 카테고리 라인 뭉치+금액 라인 뭉치 분리).
- 오버레이: `retrieve()`에서 srcs에 `표깨짐: true` + 블록 헤더 마커. UI 배지는 기존 flag `article_integrity`에 편입(조문 무결성 배지류와 동일 성격).
- 검수 큐: `review_queue.py`가 index를 읽어 깨진 표 문서에 가산점(검수상태 자동변경은 없음 — 사람만).

## 3. P0-2 — 적용범위 앵커링 (`retrieve` 확장 + SYSTEM 규칙 12)

**정책**: 근거로 인용된 규정(상위 2개)의 **제1~2조(목적·적용범위) 청크를 자동 동반 첨부**(pin)하고,
"자격·수급·적용 여부는 적용범위/대상 조항 근거로만 답하고, 지급 기준·계산식 조항에서 자격을
추론하지 않는다. 적용범위 근거가 없으면 '적용 여부는 규정에서 확인되지 않습니다'"를 프롬프트에 명시.

- 인덱스: 전 컬렉션 1회 스캔으로 `규정명 → 제1·2조 청크` 맵(_state 캐시, byeol 인덱스와 동일 패턴).
- srcs 마커 `scope_anchor: true` → 기존 🔗 자동첨부 배지 라인에 편입. 토글 `RAG_SCOPE_ANCHOR`(기본 on).
- 기대: 트랙 B '신분 적용렌즈'의 보류 사유(관례 의존) 해소 — 적용범위 **조항**이 근거라 규정 기반.

## 4. P0-4 — 시스템 귀속 규칙 (프롬프트 + 라벨 강화)

실측상 블록 라벨은 이미 시스템명을 표기(`(그룹웨어)`)하는데도 모델이 ERP로 귀속 → 라벨을
`(소속 시스템: 그룹웨어)`로 강화하고 SYSTEM 규칙 7에 "메뉴·기능의 소속 시스템은 그 근거 블록의
소속 시스템명을 그대로 쓰며, 다른 시스템 소속으로 답하지 않는다(여러 시스템이 근거에 있으면
메뉴가 나온 블록 기준)"를 추가.

## 5. 수용 기준

ⓐ §0의 실측 오답 5건 시나리오 재연 시: #1·#2 경고 부착, #3 표손상 라벨+경고+배지, #4 적용범위
청크 동반+자격 단정 없음, #5 그룹웨어 귀속 정답.
ⓑ 과차단 대조군: 근거에 있는 수치의 정상 인용(경조휴가 일수·자문수당 30/20만 등)과 규칙 10 계산식
답변에 경고가 붙지 않는다.
ⓒ 유닛(모델 미로딩): 수치 정규화·계산식 허용·인용번호 제외·깨진 표 제외 케이스.
ⓓ 골든셋 재실행: 멀티턴 5/5 등 기존 지표 무회귀. 실측 오답 5건을 골든 케이스로 추가(로컬).
ⓔ Playwright/라이브 E2E(`tools/verify_trust_gates.py`) + 적대적 리뷰 워크플로 통과.
