# QualityDrop — 재시험 코호트 정답률 급락

**감지**: 재시험 코호트 정답률이 전일 대비 **10%p 이상** 하락. 🟡 SEV2 — 회귀 의심.
**왜 재시험만 보나**: 전체 정답률은 표본이 매일 85% 바뀌어 하락이 회귀인지 구성인지 구분되지 않는다(docs/58 §6d).

## 1. 먼저 표본을 의심한다
재시험 건수가 적으면(10건 미만) 한두 문항으로 10%p가 움직인다. **분모를 먼저 본다.**
```bash
cd eval && ../tools/.venv/bin/python -c "
import json,sys; d=json.load(open('daily/<날짜>.graded.json'))
print(d['코호트별']); print(d['실패유형별'])"
```

## 2. 실패유형으로 갈라본다
| 늘어난 유형 | 의심 |
|---|---|
| `검색실패` | 재색인·리랭커·플래그 변경. `RAG_RERANK`·컬렉션 이름 확인 |
| `생성환각` | 모델·SYSTEM 프롬프트 변경. LLM 교체나 프롬프트 수정이 있었나 |
| `판정불가` | 채점기 문제일 수 있다 — 서비스가 아니라 평가 파이프라인을 본다 |
| `골든품질` | 회귀가 아니다. 문항이 나쁜 것 |

## 3. 최근 변경을 본다
```bash
git log --oneline --since='2 days ago'
ls -la tools/chroma/          # 재색인 시각
pm2 describe kei-rag-api | grep -E 'restart|uptime'
```

## 4. 확정 전에
**하루치로 회귀를 단정하지 않는다.** 같은 문항이 다음 날도 틀리는지 본다 —
LLM 생성은 결정적이지 않아 한 번의 오답이 회귀를 뜻하지 않는다.
급하면 해당 문항만 `eval/daily_answer.py`로 재실행해 재현성을 확인한다.
