# 런북 — 자동 수술(AutoSurgery)

> 매일 10:00 `eval/auto_surgery.sh`가 무인 Claude Code로 그날 수술을 수행하고,
> 관문을 통과한 변경만 **`autosurgery/<날짜>` 브랜치**에 담는다. ⛔ dev·main 무접촉 — 머지는 사람.

## 알림이 뜨면

### ✅ `ok` — 수술 완료
1. `eval/daily/LATEST-SURGERY.md`(5줄 요약)를 읽는다. 세션에 붙여넣어도 되고 직접 봐도 된다.
2. diff 확인: `git diff dev..autosurgery/<날짜> -- eval/`
3. 납득되면 머지: `git checkout dev && git merge autosurgery/<날짜> && git push origin dev`
   아니면 브랜치를 지운다: `git branch -D autosurgery/<날짜>` (되돌릴 것이 없다)

**무엇을 볼 것인가** — 이 시스템에서 무인 수술이 잘못되는 방식은 정해져 있다:
- **잘 맞히던 문항이 은퇴됐나** — `golden_repair --retire`가 정답 이력 있는 문항을 지웠다면
  자기 채점 조작이다. `--why`에 "정답 0/N" 같은 근거가 있는지 본다.
- **게이트가 무르게 바뀌었나** — 임계값을 낮춰 폐기를 늘리면 점수는 오르고 변별력은 사라진다.
  리프트 수치(미정답률 vs 기저)가 커밋·문서에 적혀 있어야 한다.
- **기각을 기록했나** — 붙이지 않기로 한 가설의 근거가 주석에 남았는지. 남기지 않으면
  다음 회차가 같은 가설을 또 시도한다.

### ⛔ `blocked` — 관문이 막음
되돌리기는 이미 끝났다(작업트리 원복). 사유별 대응:

| 사유 | 뜻 | 할 일 |
|---|---|---|
| 사정거리 밖 변경 | `eval/` 밖(볼트·rag_core·web)을 고치려 했다 | 로그에서 어떤 파일인지 보고, 정말 필요하면 **사람이 세션에서** 처리 |
| 과거회차 변경 | 지난 `*.graded.json`을 재작성하려 했다 | 전방 적용 원칙 위반 — 그대로 두는 게 맞다 |
| 회귀 실패 | eval 스위트가 깨졌다 | 실패한 스위트를 직접 돌려 원인 확인 |
| 디스크 여유 부족 | 루트 10G 미만 | 백업·스냅샷 정리(아래) |

## 설계 근거

- **왜 브랜치인가**: 오토픽스(`maint_executor.py`)가 같은 구조로 7월에 34회 돌았고 그중
  13건이 관문에 걸렸다(SYSTEM 가드레일 변경 6 · 금지구역 7). 무인 에이전트는 실제로 위험한
  수정을 시도한다 — 사람 머지가 마지막 방어선이다.
- **왜 Bash를 주는가**: 수술은 리프트를 재고 회귀를 돌려야 한다(오토픽스는 수정만 하므로
  Bash가 없다). 대신 변경 파일 화이트리스트를 `eval/`로 좁혔다.
- **왜 dev에 커밋하지 않는가**: 관문은 형식(경로·회귀)만 본다. "리프트를 정말 쟀는가",
  "이 은퇴가 타당한가" 같은 판단은 기계가 대신할 수 없다.
