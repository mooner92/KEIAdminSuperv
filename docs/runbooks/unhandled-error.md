# UnhandledError — 미처리 서버 오류(500)

**감지**: `04_rag_api`의 예외 핸들러. 지문(`예외형:라우트`)별 **10분 1건**(`OBS_ERR_THROTTLE_SEC`).
**알림에 담기는 것**: 예외 클래스명 + 라우트 경로뿐. ⛔ 질문·입력값·쿼리스트링은 절대 안 담긴다(docs/56 §5).

## 1. 상위 장애부터 배제
`ServiceDown`이 함께 왔으면 이 알림은 **무시한다** — 원인이 아니라 결과다(자동 뮤트되지만 시차가 있을 수 있다).

## 2. 실제 트레이스를 본다
알림엔 예외형만 있다. 전체 트레이스는 서버 로그에 있다.
```bash
pm2 logs kei-rag-api --lines 200 --nostream | grep -B5 -A20 '<예외형>'
```

## 3. 라우트별 흔한 원인
| 라우트 | 흔한 원인 |
|---|---|
| `/app/chats/*` | SQLite 락·스키마 불일치(마이그레이션 누락) |
| `/v1/*`·`/api/rag/chat` | Ollama 400(컨텍스트 초과 — `RAG_CTX_MAX_CHARS` 확인)·chroma 핸들 |
| `/app/flags`·`/app/stats` | `APP_ADMINS` 미설정(fail-closed라 정상 동작일 수 있다) |

## 4. 재발하면
같은 지문이 반복되면 스로틀 때문에 10분에 1건만 온다 — **빈도를 로그로 확인**하고, 재현되면 회귀 테스트를 먼저 만든다.

## 조치를 못 만들겠으면
그 알림은 삭제 후보다(docs/66 §4). 임계를 올리거나 레지스트리에서 뺀다 — 무시하는 습관이 드는 게 더 나쁘다.
