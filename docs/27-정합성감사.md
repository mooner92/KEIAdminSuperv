# 27. 코퍼스 정합성 감사 (문서 간 이해충돌 탐지)

> 배경(사용자 요청): 다른 문서에서 같은 항목이 언급되는데 제·개정 시차로 값이 다른 경우를
> 전수 확인. ⛔ 이 문서(공개 레포)에는 방법론만 기록 — **감사 결과(실제 값·문서명)는 볼트
> `90_관리/감사/정합성감사-YYYYMMDD.md`에만** 둔다(내부 기준 비공개 원칙).

## 1. 2단계 파이프라인

**① 결정적 스캐너** `tools/01s_conflict_scan.py` — 후보 채굴(판정 아님):
- **주제-수치 교차**: 주제 앵커(수당·한도·기한·휴가일수 등 20종) ±80자 창에서 값을 추출,
  서로 다른 문서가 서로 다른 값을 가지면 후보
- **가이드 낙후도**: 가이드의 기준 시점(개정일/최종검토일/제목 연도) < 인용 규정([[링크]])의 개정일
- **중복 수록**: 같은 제목이 규정원문/가이드 양쪽에 존재 → difflib 유사도로 동일(이중 분류) vs
  상이(버전 충돌) 즉시 구분
- 산출: `tools/index/conflict_candidates.json` (gitignore)

**② 원문 대조 판정**(에이전트 병렬, 후보마다 양쪽 원문 인용 필수):
- 분류: **실충돌**(같은 항목·조건인데 값 다름) / **낙후**(개정 전 값 잔존 — 개정일로 입증) /
  조건차이(정상 병존) / 오탐(추출 창 한계)
- 산출: `tools/index/conflict_audit.json` (gitignore, verdicts+paths)

## 2. 환류

- `review_queue.py --conflicts`: 실충돌·낙후 판정 문서 **+20점** — 낡은 값을 답할 위험 문서가
  검수 큐 상단으로(표손상 +25·👎 피드백과 함께 3중 신호)
- 문서 교정·검수 확정은 사람만(⛔ 자동 수정 없음 — 보고서는 후보 제시용)

## 3. 1차 감사 결과 요약 (2026-07-13, 수치는 볼트 보고서 참조)

- 후보 71건 판정: **실충돌 2 · 낙후 17 · 조건차이 23 · 오탐 29**
- 패턴: ⓐ 가이드가 규정 개정(감사 기준·휴가 일수·가액 한도 등) 이전 값을 유지 ⓑ 같은 기준의
  구판·신판이 모두 코퍼스에 수록(승진·평가 계열) ⓒ ERP 화면 안내문이 현행 규정과 상이(실물 확인 필요)
  ⓓ 삭제된 조문을 타 규정이 계속 인용(dangling reference) ⓔ 내용 동일 이중 수록 9건(색인 정리 대상)
- 오탐 29건의 주 원인 = 추출 창이 무관한 값을 짝지음(범위 표기 분해, 표 인접 행 혼입) —
  스캐너는 재현율 우선, 정밀도는 ②판정 단계가 담당하는 설계

## 4. 재실행
