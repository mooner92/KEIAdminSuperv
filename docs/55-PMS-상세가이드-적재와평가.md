# 55 — 연구관리시스템(PMS) 상세가이드 적재와 정확도 평가

> 2026-07-20. 데이터 추가(코퍼스 확장)와 그 **검증 결과**를 함께 남기는 문서.
> 앞으로 코퍼스에 새 자료를 넣을 때 이 문서를 템플릿으로 삼는다(무엇을 넣었나 → 어떻게 쪼갰나
> → 어떻게 색인했나 → **정말 맞는 답을 하는가**).

## 1. 왜 넣었나 — tier1만 있고 tier2가 없었다

PMS는 전사 시스템 번들에서 온 **tier1(메뉴·기능 목록)** 노트 10개만 있었다. 화면이 무엇이고
어떤 컬럼이 있는지는 알지만, **"어느 필드에 뭘 넣고 어떤 버튼을 누르는지"** 는 답하지 못했다.
ERP에는 있는 **tier2(상세가이드, 사용자지침서 판독)** 가 PMS에는 없었던 것.

| tier | 성격 | ERP | PMS(적재 전) | PMS(적재 후) |
|---|---|---|---|---|
| 1 시스템·모듈 | 메뉴 지도·기능 목록 | ✅ | ✅ 10노트 | ✅ 10노트 |
| 2 상세가이드 | 화면별 필드·버튼·업무흐름 | ✅ 7노트 | ❌ 없음 | ✅ **11노트** |

## 3. 어떻게 쪼갰나 — 탭 기준 병합 + 누락 0 대사

`01v_pms_deep_to_md.py`. 원자료가 5개 파일로 나뉘고 **같은 탭이 여러 파일에 흩어져**(과제관리는
파일 2·3·5) 있어 **탭 기준으로 병합**한다.

- `# <탭>` = 경계 / `## N. <화면>` = 화면. H2 제목의 번호 접두만 제거(병합 시 충돌).
- 문서레벨 섹션(연계도·상태전이·시나리오·검증)은 **제목 패턴**으로 골라 부록 노트로 분리.
- ⛔ 본문 불변(의역 금지). 구조 조정은 헤딩 레벨뿐.
- ✅ **누락 0 이중 대사**: 본문 줄(헤딩·공백 제외) 멀티셋 일치 + 헤딩 제목 집합 일치.
  실측 **본문 5,507줄 · 헤딩 제목 467개 전량 반영**.

산출: 탭 9(과제관리 33화면 · 원내외활동 15 · 성과물관리 13 · 과제선정 5 · 연구윤리·특허 3 ·
연구실적 2 · 전문가 Pool 2 · 행사·대외협력 2 · 과제계약 1) + 개요 + 부록 = **11노트**.

## 4. 청킹 — '기능 단위' 라벨과 화면 맥락 (중요)

첫 적재 땐 화면(`##`)만 청크 라벨을 갖고, **알맹이인 하위 섹션(검색조건·버튼·업무흐름)이 라벨도
화면 표시도 없이** 색인됐다. 검색은 됐지만 근거에 "어느 화면의 버튼인지"가 안 나왔다.

**개편**: 생성기가 화면을 `###`, 하위 섹션을 `####`로 재배치(내용 불변). `chunk_guide` 규칙상
`###`=맥락(cur_sub) / `####`=청크(라벨 + `[cur_sub]` 주입) 이므로, 이제 **모든 상세 청크가
'소제목' 라벨 + '[화면명]' 맥락**을 갖는다. 화면 머리 블록은 `#### 화면 개요`로 승격.

부수 수정: 과대 청크를 문단으로 재분할할 때 맥락 프리픽스를 **이어지는 조각에도 재주입**
(`02_chunk_and_embed.py`) — ERP 상세가이드도 같이 수혜.

회귀 테스트 `tools/test_pms_chunking.py` **9/9**(라벨 569/569 · 맥락 487/487 · 회수 4종 · 화면명 표기).

## 5. 색인 — 재색인 사고와 항구 수정

재색인 중 코퍼스가 **5,607청크**가 되며 Chroma **1회 upsert 상한(5,461)** 을 초과, 컬렉션
reset 직후 upsert가 터져 **인덱스가 빈 채로 남았다**(RAG 다운). 백업 덕에 복구.

→ `02_chunk_and_embed.py`에 **분할 upsert**(`get_max_batch_size` 기반) 추가. 코퍼스가 상한을
넘는 순간 누구에게나 재현되던 결함이다. **재색인 전 chroma 백업은 필수**(manual/05에 명시).

최종 색인: **5,542청크**(PMS 상세가이드 712). 코퍼스 374문서.

## 6. 평가 — 로컬 Qwen 실답변 정확도

`eval/pms_audit.py`. `run_eval.py`가 '검색이 정답 출처를 회수하는가'(Hit@k)를 잰다면, 이 도구는
**로컬 모델이 실제로 내놓는 답이 맞는가**를 잰다(docs/15 §2.1 방법론의 PMS판).

**원자료가 사람이 만든 신뢰 자료**이므로 질문·정답을 원문에서 직접 뽑았다 → '초안 대비'가 아니라
**원문 대비 정답률**이다. 프로덕션과 동일 경로(`retrieve` → `answer`)로 실행.

채점: ⓐ회수(strict=노트+섹션 / relaxed=노트) ⓑ**값 정확도**(must 전부 + any 하나 이상 포함)
ⓒ인용 ⓓ거부(코퍼스 밖 질문은 거부해야 정답) → PASS / PARTIAL / MISS.

### 결과

| 회차 | N | 설정 | 정답률 | 회수 strict | 회수 relaxed | 인용 |
|---|---|---|---|---|---|---|
| 기준선 | 15 | 리랭커 off | 100% (15/15) | 85.7% | 100% | 100% |
| 확장 | 50 | 리랭커 off | 92.0% (46/50) | 62.2% | 97.8% | 100% |
| **확장(프로덕션 동일)** | 50 | **리랭커 on** | **98.0% (49/50)** | 62.2% | **100%** | 97.8% |

문항 구성(50): 경로 22 · 버튼 18 · 화면ID 2 · 업무흐름/필드/상세구분 3 · **거부 5**.
탭 층화: 과제관리 13 · 원내외활동 8 · 성과물관리 7 · 과제선정 4 · 나머지 각 1~2.

> **⚠ 평가는 반드시 프로덕션 설정으로 돌린다.** `rag_core`의 리랭커 기본값은 off(`RAG_RERANK=0`)
> 인데 운영은 on이다(`ecosystem` `RAG_RERANK=1`, `cuda:1`). 기본값으로 돌린 첫 50문항은 92%로
> **실제보다 6%p 낮게** 나왔다. 감사 명령에 `RAG_RERANK=1 RAG_RERANK_DEVICE=cuda:1`을 반드시 포함할 것.

### 남은 1건이 말해주는 것 (회수 약점)

`'연구실적' 화면의 버튼은?` → 모델은 "연도 확정·확정 취소·조회"라 답했다. 실제 라벨은
`[년차확정]`·`[년차확정취소]`다. **환각이 아니다** — 회수된 `화면 개요` 청크에 "③ 연도 확정 및
조회 버튼"이라 적혀 있고 모델은 그걸 충실히 따랐다. 정확한 라벨이 있는 `주요 버튼` 청크가
회수되지 않은 것이 원인.

패턴: **화면명이 흔한 단어일 때**(‘연구실적’은 코퍼스 전반에 등장) 일반적 질의("무슨 버튼 있나")가
`주요 버튼` 대신 `화면 개요`로 붙는다. 반면 고유 토큰이 있는 질의("년차확정")는 정확히 회수된다
(x02 PASS). → 개선 후보: 화면 단위 청크에 버튼 라벨을 개요에도 노출하거나, 질의 확장.

### 채점기·문항 결함도 3건 발견·수정

- **거부 문항 오설계** — "자문료 1회 얼마?"를 코퍼스 밖으로 가정했으나 **실제로 규정에 있었다**
  (수탁연구사업 경비 집행 가이드라인: 1인당 1회 20만원 이내). 모델이 정확히 인용해 답한 것을
  내가 오답 처리 → 진짜 코퍼스 밖 질문으로 교체.
- **채점 과엄격** — "확정하려면 어떤 버튼?"의 정답은 `[확정]` 하나인데 저장·삭제·닫기까지 요구.
- **목록/등록 팝업 혼동** — 자동 생성 문항이 목록 화면과 등록 팝업을 구분하지 않음 → 질문 명확화.

> ⚠ **해석 주의**: 문항은 내가 만들었고 대부분 "어디서/어떤 버튼" 유형이다. 이 수치는
> "PMS 답변이 완벽하다"는 뜻이 아니라 **회귀 감지 기준선**이다. 청킹·인코딩·재색인 변경이
> 품질을 떨어뜨리면 여기서 드러난다.

### 채점기 교훈 (docs/15 재확인)

기준선 첫 실행은 85.7%였으나 **실패 2건 모두 모델이 아니라 채점기 결함**이었다:

1. **거부 오판** — 모델은 코퍼스 밖 질문에 정확히 거부했는데("명시되어 있지 않습니다") 정규식이
   그 표현을 못 잡아 MISS 처리 → 거부 표현 패턴 확장.
2. **문항 오류** — 이의신청 버튼을 물으며 **목록(`etc_0632M`: 엑셀다운·조회)과 상세 팝업
   (`etc_0633P`: 확정·저장·삭제·닫기)** 버튼을 뒤섞음. 모델은 회수된 목록 화면을 정확히 답하고
   "상세 버튼은 근거에 없다"고 정직하게 밝혔다 → 문항을 목록/상세로 분리.

**교훈: 자동 채점기는 표기 변형에 강건해야 하고, 정답은 원문의 화면 단위와 정확히 일치해야 한다.**
