# 35. 이벤트탭 "지금 KEI에서" + 시즌 캘린더 + 사용량 수집 — 확정 스펙 (2026-07-15 사용자 승인)

> 사용자 지시: 시즌 캘린더도 간단히 구현(근 몇 년치 자료는 사용자가 수집 예정 — **윤곽을 먼저**),
> 이벤트탭 나머지 자동 블록 구현, 그리고 "기능을 붙이고 → 실사용 통계로 없애거나/개선"하는
> 운영을 위해 사용량 통계 수집(PostHog류) 도입.

## 0. 사용량 수집 — PostHog 대신 경량 자체 수집(결정 근거)

- PostHog **클라우드**: 사내 사용 데이터의 외부 전송 = ⛔(절대 규칙 5·데이터 분리 원칙).
  **셀프호스트**: ClickHouse·Redis 등 스택이 무겁고 GPU 서버 자원과 경합 — 현 단계 과함.
- 대안 = 자체 수집(수십 줄): 기존 app.db(SQLite)에 `UsageEvent` 테이블 + `POST /app/track` +
  관리자 사용량 뷰. 목적(기능별 사용량으로 존폐·개선 판단)에 충분하고, 나중에 진짜 PostHog가
  필요해지면 이벤트 스키마를 그대로 내보낼 수 있다.

### 설계 (⛔ 프라이버시 — P2.5 연장)
- **이벤트 이름은 서버 allowlist**(자유 문자열 금지) — 질문 텍스트·개인 식별 페이로드가 이벤트로
  들어올 경로 자체를 차단. payload 필드 없음(이름 + 선택적 `page` 경로만, 경로도 allowlist 프리픽스).
- user_id는 저장(DAU 계산용)하되 **관리자 뷰는 집계만**(누가 눌렀는지 미반환).
- 수집 자체를 flag `usage_analytics`로 게이트(off = 프론트가 전송 안 함 + 서버 204 무시).
  도움말 '데이터와 개인정보'에 수집 사실 명시(정직 고지).
- `GET /app/usage?days=`(관리자): 이벤트별 카운트·고유 사용자 수, 일별 활성 사용자(DAU),
  페이지뷰 상위. `POST /app/track`: 로그인 사용자, 초당 과다 호출 무시(간단 스로틀).
- 프론트 `lib/track.ts`: `track(name, page?)` — fire-and-forget(실패 무시·비차단).
  심는 지점(1차): `page_view`(라우트 전환), `chat_send`·`chat_stop`, `forms_search`·`forms_open`,
  `trending_click`, `now_view`(이벤트탭), `changelog_view`, `faq_open`, `journey_view`.
- 관리자 노출: `/admin` 대시보드에 "📈 기능 사용량" 블록(기간 필터 공유).

## 1. 이벤트탭 "지금 KEI에서" (`/now`, flag `events_tab`)

GNB에 탭 추가(플래그 게이트). 블록 구성 — 시즌 캘린더 외 전부 자동:

| 블록 | 데이터 | 갱신 |
|---|---|---|
| 🗓 이번 달 챙길 일(시즌 캘린더) | 볼트 `90_관리/_calendar/seasonal.json`(사람 큐레이션) | 재빌드 |
| 📈 요즘 많이 찾는 키워드 | `GET /app/trending?days=7` + 상대 막대 | 런타임(로그인 시) |
| 📜 최근 개정된 규정 | 문서 프론트매터 `개정일` 상위 5 | 재빌드 |
| 🆕 새로워진 점 | changelog 최근 3건(기존 로더 재사용) | 재빌드 |
| 📖 오늘의 용어 | 용어집에서 날짜 시드 선택(클라이언트 — 정적 export라 '오늘'은 브라우저 계산) | 일 단위 |

- 비로그인: 키워드 블록만 "로그인하면 보여요"로 대체(나머지는 정적).
- 수용: ⓐ flag off = GNB·페이지 미노출(준비 중) ⓑ 각 블록 실렌더 ⓒ 오늘의 용어가 날짜에
  결정적(같은 날 = 같은 용어) ⓓ 다크 실측 ⓔ 캘린더 빈 달 안전("등록된 일정 없음").

## 2. 시즌 캘린더 — 데이터 윤곽(사용자 자료 수집 전 확정)

- 위치: 볼트 `90_관리/_calendar/seasonal.json` (공개 레포 밖 — 내부 일정 데이터).
- 스키마(수집될 "근 몇 년치 자료"를 담을 그릇):
  ```json
  [
    {
      "month": 1,                      // 1~12 (필수)
      "title": "연말정산",              // 필수 — 업무명
      "desc": "전년도 귀속 연말정산 제출·확인",   // 선택 — 한 줄 설명(⛔ 금액·기한 확정값 금지)
      "시기": "1월 중",                  // 선택 — 자유 텍스트("1월 중"·"매년 초"). 확정 일자는 자료 확인 후
      "관련페이지": "/browse/?doc=…",     // 선택 — 사이트 내부 경로만
      "근거": "2023년귀속근로소득연말정산종합안내및FAQ",  // 선택 — 코퍼스 문서 제목(있으면 링크)
      "상태": "예시"                     // "예시"(자료 확정 전) | "확정" — 예시는 UI에 배지 표시
    }
  ]
  ```
- ⛔ 지어내기 금지: 자료 확정 전 항목은 전부 `상태: "예시"` + UI 배지("자료 확정 전").
  초기 시드는 코퍼스에 근거 문서가 실존하는 항목만 소수 등록.
- 검증: `tools/calendar_lint.py` — month 범위·필수 필드·내부 경로·확정값(금액·`N일 이내`) 금지·
  근거 문서 실존(볼트 대조). 자료 반입 절차: 자료 → json 작성 → lint → 재빌드.
- UI: 이번 달 크게 + 다음 달 미리보기, 월 선택 칩(1~12).

## 3. 마감

구현 → 유닛(track allowlist·usage 집계·calendar lint) → 적대 리뷰 워크플로 → 재빌드 →
E2E(`verify-now.mjs`: 블록·게이트·다크·track 발화·admin 사용량) → changelog 노트
(이벤트탭 신규 + 사용량 수집 고지) → help 개인정보 문구 갱신 → 커밋.
