# 29. 아이디어 정리 — 인기 키워드·이벤트탭·가입 정책·사용자 목록 (⛔ 초안, 미승인)

> 사용자 발제(2026-07-13): ⓐ 이벤트탭 등 데이터를 재밌게/고도로 쓰는 창의 기능
> ⓑ 오늘/주간/월간 인기 검색 키워드 집계("휴가 신청", "도서 신청" 등)
> ⓒ 가입은 @kei.re.kr 메일만 + 이메일 인증 + ID=메일 고정 ⓓ 관리자가 사용자 목록 열람.
> 이 문서는 **정리·설계 초안** — 구현은 사용자가 항목을 고르면 착수.

## 1. 인기 검색 키워드 집계 (오늘/주간/월간) — 저비용·고효용

- **데이터는 이미 있다**: app.db의 사용자 질문(Message) + P2.5 대시보드의 k-익명 집계 인프라.
  새로 필요한 것은 ① 기간 창(일/주/월) ② **질문이 아닌 '키워드' 단위** 집계뿐.
- **키워드 추출은 무LLM·결정적**: 여정 트리거 키워드 + 30_용어집 용어 + 규정명 사전 매칭
  (후속질문 `suggest_followups`의 최장 일치 방식 재사용). "휴가 신청"·"도서 신청"류 명사구만 남는다.
- **노출 2면**:
  - 사용자: 채팅 첫 화면(빈 상태)에 "요즘 많이 찾는 키워드 TOP N" 칩 → 클릭 시 질문 프리필(기존 `/?q=` 재사용).
  - 관리자: `/admin` 대시보드 인기질문에 기간 필터(일/주/월) 추가.
- **🔒 프라이버시 불변**: 기존 k-익명 규칙 그대로 — 서로 다른 사용자 `STATS_MIN_USERS`(3)명 이상이
  쓴 키워드만 노출, 질문 본문은 사용자 화면에 절대 비노출. 관리자도 본문 미반환 원칙 유지.
- 플래그: `trending_keywords` (release·off 기본).

## 2. 이벤트탭 "지금 KEI에서" — 기존 데이터의 조합 확장

한 탭에 시기성 정보를 모은다. 전부 **이미 가진 데이터의 재조합**이라 환각 위험 없음:

| 블록 | 데이터원 | 예시 |
|---|---|---|
| 요즘 많이 찾는 키워드 | §1 집계 | "이번 주: 연말정산·출장 정산" |
| 최근 개정된 규정 | 프론트매터 `개정일` | "이번 달 개정 3건 — 복무규정 …" |
| 새로 추가된 가이드/여정 | 볼트 diff·`_journeys` | "신규: 국외출장 여정" |
| 시즌 캘린더 | **운영자 큐레이션**(신규 JSON) | "1월: 연말정산 / 3월: 재산등록" |
| 오늘의 용어 | 30_용어집 랜덤 1건 | "오늘의 용어: 전결" |
| 검색 트렌드 스파크라인 | §1 주간 추이 | 키워드별 미니 그래프 |

- 정적 export 제약 → 기존 flags/stats 패턴대로 **정적 셸 + 런타임 `/app/*` fetch**.
- ⚠ 시즌 캘린더만 사람이 관리하는 신규 데이터(운영 부담) — 나머지는 자동. 캘린더는 2차로 미뤄도 됨.
- 플래그: `events_tab`.

## 3. 가입 정책 — @kei.re.kr 한정 + 이메일 인증 + ID=이메일

- **가입 폼**: ID 입력 제거, 이메일 1칸. 서버측 도메인 검증(`@kei.re.kr`만, fail-closed —
  allowlist 방식이라 오타 도메인·외부 메일 전부 거부). `username = email` 고정(표시명은 로컬파트).
- **이메일 인증**: 가입 시 6자리 코드 발송 → 입력해야 계정 활성(미인증 로그인 불가).
  코드는 app.db `VerifyCode`(TTL 10분·재발송 쿨다운·시도 5회 제한). 인증 완료 전 비밀번호만 미리 설정.
- **⚠ 선결 확인(막히는 지점)**: 온프레미스·사내망이므로 **KEI 내부 SMTP 릴레이** 접근 정보
  (호스트/포트/발신 계정)가 필요하다. 이것이 없으면 인증 메일을 보낼 수 없다.
  - 대안(비권장): 발송 불가 시 도메인 형식 검증만 — 타인 메일 도용 가입이 가능해져 인증보다 약함.
- **기존 계정 마이그레이션**: v1 출시 전 dev 계정뿐 → 리셋이 가장 깔끔. `APP_ADMINS`도 이메일 기준으로
  전환(fail-closed 유지). 테스트 계정(admintest)은 dev 전용으로만 존치, prod 병합 시 제거(기존 방침).

## 4. 관리자 사용자 목록

- `GET /app/users`(current_admin): 이메일(=ID)·가입일·마지막 활동·채팅 수·인증 여부·관리자 여부.
  `/admin`에 "사용자" 탭 추가.
- **🔒 프라이버시 경계 불변**: "누구인지"까지만 — **타인 채팅 본문을 읽는 엔드포인트는 계속 없음**
  (P2.5 설계 원칙 ⓐ 유지). 목록·활동 메타만 반환.

## 5. 우선순위·의존성 제안

1. **§3+§4 묶음**(가입 정책+사용자 목록): v1 출시 전 사실상 필수(보안·운영 기반). 단 SMTP 확인이 선결.
2. **§1 인기 키워드**: 인프라가 이미 있어 저비용, 사용자 가치 즉시. 독립 착수 가능.
3. **§2 이벤트탭**: §1을 포함하는 확장 — §1 반응을 보고 확대가 안전. 시즌 캘린더는 마지막.

## 확인 필요(사람)

- 사내 SMTP 릴레이 호스트/포트/발신 계정 — §3의 선결 조건.
- 이벤트탭 시즌 캘린더를 관리할 담당(운영 데이터).
