# 20. 관리자 코퍼스 관리(운영 난이도↓) — 설계안 (v1.1 후보)

> 목표(사용자 제안): /admin에서 근거 md 목록 보기 · 제외 · 새 문서(hwp/hwpx/pdf/md) 추가 →
> 자동 청킹·재임베딩 · 잘못 추가 시 롤백. 현재는 전부 SSH+CLI — 이걸 웹으로.
> 판정: **방향 옳음.** 단, 아래 4가지 설계 원칙을 지켜 단계적으로.

## 핵심 설계 결정

1. **제외 = 삭제가 아니라 토글(soft-exclude)**
   `tools/index/exclude.json`(slug 목록) — `02_chunk_and_embed`가 skip. 파일은 그대로 →
   실수해도 토글 해제로 즉시 복구(데이터 무손실). "제외 후 재색인"이 곧 사용자가 말한 "해당 문서 빼고 다시 만들기".

2. **롤백 = 재임베딩이 아니라 스냅샷 스왑**
   재색인 전 `tools/chroma` → `chroma.bak-<ts>` 자동 백업(현행 수동 규칙의 자동화).
   롤백 버튼 = 디렉터리 스왑 + 인덱스 리로드 → **수 초**(재임베딩 불필요). 보존 2세대면 충분.

3. **업로드는 2단계 승인(변환 미리보기 → 편입)**
   hwp/hwpx/pdf 변환은 표 깨짐이 흔함(실측). 업로드 즉시 편입 금지 —
   ⓐ staging(repo 밖 `~/kei-uploads/`)에 저장 → 01/01c로 변환 → **미리보기(md)** 제시
   ⓑ 관리자가 "편입 승인" → 볼트에 이동(검수상태: 미검수) → 재색인 큐.
   md 직접 업로드는 미리보기=원문이라 사실상 1.5단계. ⛔ 절대규칙(원문 보존·검수는 사람) 유지.

4. **재색인은 큐+락, 적용은 무재시작 리로드**
   - 서브프로세스로 02 실행(동시 1개 락, 진행 로그 스트림), GPU 점유 몇 분 감안 "진행중" 배지.
   - 완료 후 `rag_core.reload()`(backend/인덱스 캐시 리셋) 신설 → **PM2 재시작 없이 적용**.
   - 웹은 재빌드 필요(docdata) — Phase 2에선 "웹 반영은 다음 배포에" 고지로 시작.

## 단계별 (각 단계가 독립 가치)

| Phase | 내용 | 규모 |
|---|---|---|
| **P1 목록·제외** | /admin 코퍼스 탭: 문서 목록(제목·구분·청크수·검수상태·제외여부) + 제외 토글 + "재색인 필요 N건" 배지. 재색인은 아직 CLI | S~M |
| **P2 재색인 버튼** ✅완료 | 백업→02 실행(락·로그)→reload() 무재시작 적용 + 롤백(스냅샷 스왑) 버튼 | M |
| **P3 업로드** | md 즉시 / hwp·hwpx·pdf → 변환 미리보기 → 승인 편입(확장자·크기 검증, 관리자 전용, staging repo 밖) | L |

## 경계 조건
- 전부 `current_admin` 뒤 + 감사 로그(FlagAudit식 CorpusAudit: 누가·언제·무엇을 제외/편입/재색인).
- 볼트 파일 변경은 서버 로컬 git 커밋(공개 push 아님)으로 이력 보존 — 롤백 2중 안전망.
- prod 동결 원칙 유지: 이 기능 자체도 dev에서 만들고 flag(`corpus_admin`)로 배포.

## P1 상세 스펙 (2026-07-09 확정 — ✅ 구현 완료, E2E 8/8)

### 데이터
- `tools/index/exclude.json` = `{"excluded": ["<slug>", ...]}` — slug는 볼트 파일 stem(문서 슬러그와 동일).
  gitignore 경로(tools/index/) 안 — 규정 파생 아님이지만 운영 상태라 레포 밖 취급 동일.
- `CorpusAudit` 테이블(신설): id·slug·action(exclude|include)·actor·at — 감사 추적(검수상태와 무관).

### API (전부 관리자 `current_admin`)
- `GET /app/corpus` → `{docs:[{slug,title,section,검수상태,chunks,excluded,needs_reindex}], summary:{total,excluded,indexed_chunks,needs_reindex}}`
  - `chunks` = 현재 chroma에 색인된 청크 수(path 기준 집계, 60s 캐시)
  - `needs_reindex` = (excluded && chunks>0) || (!excluded && chunks==0) — "상태와 색인의 불일치"
- `POST /app/corpus/exclude` body `{slug, excluded}` → exclude.json 갱신 + CorpusAudit 기록
- 재색인 실행은 P1에선 CLI 유지: `02_chunk_and_embed.py`가 exclude.json을 읽어 skip(신규 연동)

### UI (/admin, flag `corpus_admin`)
- "코퍼스 관리" 섹션: 요약(전체/제외/재색인 필요 N) + 검색 + 문서 행(제목·구분·검수·청크수·제외 토글)
- 재색인 필요 문서는 ⟳ 배지. 안내문: "재색인은 서버에서 `python tools/02_… ` 실행(P2에서 버튼화)"

### 수용 기준
ⓐ 제외 토글 → exclude.json 반영·audit 기록·목록 즉시 갱신(needs_reindex 표시)
ⓑ 02 실행 시 제외 문서의 청크 0(iter_chunks 단위 검증 — full 임베딩은 불요)
ⓒ 비관리자 403 ⓓ Playwright: 관리자 로그인 → 목록·검색·토글·배지 실렌더

## P2 구현 기록 (2026-07-09 ✅, E2E 풀 사이클)
- `POST/GET /app/corpus/reindex`: 스냅샷 백업(2세대 로테이션)→02 서브프로세스(락·로그 스트림, tqdm 제외)→
  `rag_core.reload()` 무재시작 적용. `POST /app/corpus/rollback`: 디렉터리 스왑(+pre-rollback 보존)→reload — **1.7초**.
- `rag_core.reload()`: 모델(임베딩·리랭커·LLM) 유지, 컬렉션·파생 인덱스만 재생성. ⚠ **chromadb 경로별 전역
  캐시(SharedSystemClient)를 비워야** 스왑된 디렉터리가 열림(미비우면 옛 핸들 재사용 — 실측으로 발견·수정).
- /admin: 재색인 버튼(진행 로그 폴링 3s)+롤백 버튼(최근 2개 스냅샷, confirm).
- corpus 목록에서 type 프론트매터 없는 파일(폴더 README) 제외 — 02와 판정 일치(기저 needs_reindex 0).
- E2E: 복무규정 제외→재색인(4803→4725, 서버 라이브 반영 확인)→복귀+롤백(1.7s, 4803·78청크 원상복구·기저 0).
