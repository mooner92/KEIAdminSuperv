# 17. 서비스 확장 로드맵 & 시스템 계층 코퍼스 확장

> 다관점 발굴(34개 아이디어) + 시스템 커버리지 분석에서 도출한 **계획안 + 기반 설계**.
> 핵심 원칙: **답변 품질 = 모델 × 검색 × 콘텐츠**, 병목은 콘텐츠(→ [16-reasoning-effort-AB.md](16-reasoning-effort-AB.md)에서 재확인).
> 모든 신규 기능은 **feature flag 게이트**(off 배포) + **절대 규칙**(값은 근거에만·출처+면책·의역 금지·미공개) 준수.

---

## 0. 왜 "시스템 계층"이 최우선인가

현재 코퍼스는 **ERP(내부 행정시스템)만** 메뉴·기능 단위로 문서화(40_시스템/ 12노트·99기능)돼 있고,
**전자결재·기안·대외업무·웹디스크**는 규정·용어에 *언급*만 될 뿐 "어떻게 조작하는지"가 없다.

| 시스템 | 코퍼스 상태 |
|---|---|
| ERP | ✅ 12 시스템 노트 (메뉴·기능) |
| 전자결재 / 기안 | ❌ 전용 노트 없음 (결재 83·기안 28 노트에 언급만) |
| 대외업무 / 웹디스크 | ❌ 전용 노트 없음 (5·3 노트에 언급만) |

그 결과 "출장 정산 **어떻게 상신?**"류(기안→전자결재→첨부)에 **끝까지 답하지 못한다.**
서식 도우미·플레이북·업무팩 등 다운스트림 기능도 이 계층이 채워져야 end-to-end가 된다.
→ **Phase 0(시스템 계층 확장)이 최우선.** 새 UI보다 콘텐츠 투자가 ROI가 크다(입증된 교훈).

## 1. Phase 0 — 시스템 계층 코퍼스 확장 (기반 구축 완료)

ERP와 **동일 파이프라인**을 다중 시스템으로 일반화. 원자료만 주면 편입되도록 기반을 마련했다.

### 파이프라인
```
시스템 원자료(.md, ERP와 동일 형식: ## N.모듈 > ### 서브 > #### 기능)
  → 01d_system_to_md.py --system <key>   → 40_시스템/ '<시스템> · 모듈' 노트(type:system)
  → 01e_system_crosslink.py --system <key> → 규정 교차링크(## 관련 규정, 그래프 엣지)
  → 01b_autolink.py                        → 나머지 상호참조(멱등)
  → 02_chunk_and_embed.py                  → #### 기능 단위 청킹·임베딩
```

### 새 시스템 추가법 (3단계)
1. `tools/01d_system_to_md.py`의 **`SYSTEMS` 레지스트리에 한 줄 등록**(name/prefix/분류/태그) — 전자결재·대외업무·웹디스크는 **사전 등록됨**.
2. `tools/01e_system_crosslink.py`의 **`SYSTEM_KEYWORDS`에 도메인 키워드**(시스템 공통 `_default`, 데이터 확인 후 모듈별 정밀화).
3. 원자료를 주고 실행:
   ```
   python 01d_system_to_md.py --system eas --src <파일.md> --vault KEI-행정가이드
   python 01e_system_crosslink.py --vault KEI-행정가이드 --system eas
   python 01b_autolink.py --vault KEI-행정가이드
   python 02_chunk_and_embed.py --vault KEI-행정가이드 --db tools/chroma   # 클린 리빌드
   ```

### 적재 현황 (2026-07-06 전사 번들 적재 완료 — dev)
전사 문서(`KEI 전사 시스템 전체 기능 정리`)를 `--bundle` 모드로 적재. **21개 신규 노트**(허브 1 + 시스템 6개):

| 분류(=둘러보기 필터) | 노트 | 비고 |
|---|---|---|
| 행정관리(ERP) | 12 (기존, 분류 리네임) | `ERP시스템`→`행정관리(ERP)` |
| 연구관리(PMS) | 개요+9모듈 | 굵은 기능명→#### 승격(70기능, ERP식 기능 청킹) |
| 그룹웨어 | 개요+5모듈 | **전자결재·문서수발·기록물·PIMS(자원예약)·게시판** |
| 통합포털(EIP)·웹메일·웹디스크·전자도서관 | 각 1 | 단일 노트 |
| 사내시스템(전사) | 허브 1 | 전 시스템 [[링크]] → 그래프 허브 |

- 교차링크 127개(시스템↔규정, 분류·모듈별 키워드) — `01e_system_crosslink.py --system all`로 일원화(ERP 포함).
- 커버리지 검증: 원문 438줄 → 노트 448줄(손실 0), 고유 문자열 스팟체크 12/12.
- 웹 섹션 라벨 `ERP 시스템` → **`사내 시스템`**(vault.ts·Explorer·DocDrawer·GraphDocPanel·d/[slug]·graph 범례). 분류가 둘러보기 체크박스 필터로 자동 노출.
- 당초 예상(전자결재=별도 시스템, 대외업무=별도)과 달리 실제로는 **전자결재=그룹웨어 모듈, 대외활동=PMS 모듈**로 확인 — 단일 파일용 `--system` 레지스트리(eas 등)는 심화 문서용으로 보존.

### 적재 2차 (2026-07-08 — ERP 상세가이드 + 행위 그래프)
G-ProOne 사용자지침서 PDF 판독본(화면 50개 **신청 방법** 상세: ✔필수입력·🔍팝업·[버튼]·연동)을 `--deep-guide` 모드로 적재:
- **7개 노트**: `ERP 상세가이드 개요`(화면 매핑표 50행) + 회계(ACT)·자산(ASS)·예산(BDG)·일반·총무(GEN)·인사(HRM) 모듈 + 공통 패턴(출장 업무 흐름). `###`→`####` 승격으로 상세 팝업도 라벨 청크. 커버리지 스팟 10/10·손실 0. 크로스링크 +21(총 152).
- **행위(Action) 흐름 typed 엣지** — 온톨로지의 '행위' 개념을 refs 방식으로 부분 도입: `rag_core.ACTION_FLOWS`에 (신청→정산·결과보고) 페어 10건을 등록하되 **문서 근거가 있는 것만**(ERP 상세가이드 부록 '출장 업무 흐름'의 화면ID 체인, PMS 화면쌍). 검색이 신청 화면을 회수하면 의무적 후속 단계 화면을 근거에 자동 첨부(`후속 단계: 정산(자동첨부)`) + SYSTEM 규칙 7이 답변 끝에 후속 안내. 조건부 후속(취소·변경)은 오도 위험이라 제외. flag `graph_expand_actions`(기본 off·/admin 토글·env 오버라이드), 별표 refs·reg_refs에 이은 typed 엣지 3호.

### RAG/UI 일반화 (하드코딩 제거 — 완료)
- `rag_core`: 근거 블록 라벨이 하드코딩 `(ERP 시스템)` → **규정명 접두에서 시스템명 동적 추출**(`(전자결재 시스템)` 등). SYSTEM 프롬프트 규칙 7도 "'(… 시스템)' 항목" 일반화.
- `web/ChatApp`: 근거 칩 `🖥 ERP` → **`🖥 <시스템명>` 동적**.
- `02`(청킹)은 type:system을 이미 #### 단위로 처리 → 무변경.

### ⚠️ 데이터 의존성 (절대 규칙)
시스템 메뉴·경로는 **원자료가 있어야** 정리한다(ERP도 `KEI_ERP_entire_features.md`에서 왔음).
**없는 메뉴를 지어내지 않는다**(절대규칙1). 수집물은 검수상태 미검수로 적재 → 사람 검수.

## 2. 다운스트림 기능 로드맵 (Phase 0 이후)

34개 아이디어를 가치×실현×자산재사용으로 평가한 결과(위반 0건). **4개 기반 자산**(별표 refs 역인덱스·근거 JSON 영속화·검수상태 배지·프론트매터)이 다수를 푼다.

### 🟢 Tier 1 — Quick Wins (S~M·저위험)
- **서식 도우미/허브** — "무슨 서식·어디에·주의점"(별표/별지 1급 청크 + refs 역인덱스 + ERP/전자결재 경로 칩)
- **근거 스냅샷 + 감사추적** — 답변 근거를 규정집 기준일·검수상태로 봉인(정산·감사 대응)
- **연결 레일** — "이 규정에 딸린 서식·시스템·용어" 원클릭(docdata backlinks + byeol_idx)
- **최근 본 문서·이어보기**, **인라인 용어 툴팁**

### 🟡 Tier 2 — 실행 조립 & 신뢰 (M)
- **업무 플레이북**(가이드→단계 체크리스트+근거링크+시스템 경로), **실수방지 경고 카드**(단서·기한·예외), **온보딩 여정**, **검수 커버리지 게이지+신뢰 게이트**, **답변 근거 자동검증**

### 🔵 Tier 3 — Bigger Bets (L 또는 선행 필요)
- **별표 기반 계산 도우미**(별표 검수·정합 선행), **상황별 마법사**, **규정 상충/개정 diff**, **업무 바로가기 팩**(Tier 1·2를 조립하는 상위 허브)

> ⚠️ 다운스트림 선행조건: 서식/플레이북/업무팩은 **Phase 0(특히 전자결재)** 이 채워져야 "규정→서식→기안→결재" end-to-end가 성립.

## 3. 공통 원칙
- **feature flag**(관리자 /admin 토글·off 배포·감사로그) · **검수상태 자동변경 금지**(제안만·확정은 사람) · **k-익명**(개인정보) · **온프레미스**.
- 데이터 선행: 프론트매터 `관련서식[]`는 비어있으나 **refs 역인덱스가 조문↔서식을 이미 커버**. 검수는 신뢰 기능의 변별력 전제(현 코퍼스 거의 미검수).

## 4. 데이터 기반 확장 (2026-07-06 인벤토리 → 발굴)

실보유 데이터 자산을 인벤토리한 뒤, "이 데이터라서 가능한" 기능 17개를 추가 발굴(자산별 워크플로).

### 4.4 추천 트랙
1. **서식 트랙**(최고 ROI): 양식함 41건 CSV 수집(반나절) → 브리지+대장+배지+감사 4기능.
2. **첫 화면 트랙**: 스타터 칩 + FAQ 시드(수작업 ~1.5h) — 신규 사용자 진입장벽 제거.
3. **안전 트랙**(admin): 고위험 답변 레이더 + 수요×품질 매트릭스 — 수작업 0, 검수 우선순위 자동화.

## 5. 부록 — 34개 아이디어 카탈로그
전체 발굴·평가 원자료(가치/실현/자산/리스크 점수)는 다관점 워크플로 산출물에 보관(로컬). 상위 16개 상세는 이 로드맵에 반영. §4의 17개 데이터 기반 아이디어 원자료도 동일 보관.
