## 1. 🔴 Blockers — v1 출시 전 필수 (6건, 합산 2~3일)

### B1. app.db/.app_secret 자동 백업 부재 `[S]` `ops`
- **현상**: crontab 비어있음, deploy/에 백업 스크립트 없음(실측). 전 계정·채팅·피드백·플래그가 SQLite 파일 1개.
- **수정**: `deploy/backup-appdb.sh` — `sqlite3 ".backup"`(온라인 백업, WAL 안전) + `.app_secret` 사본 + 보존기간 로테이션.
  prod(`/KEIAdminSuperv/tools/`)·dev(worktree) 모두 대상(읽기 전용 — prod 동결 원칙 위배 아님). crontab 일 1회 설치.
- **수용 기준**: ⓐ 스크립트 1회 실행 → 백업 파일 생성 + `PRAGMA integrity_check` = ok ⓑ crontab 등록 확인
  ⓒ 백업 저장소는 **repo 밖**(`~/kei-backups/`) — 사용자 데이터 커밋 금지.

### B2. 개정일 원시 JS Date 문자열 렌더 `[S]` `web`
- **현상**: `web/lib/vault.ts:78` `String(r.data["개정일"])` — gray-matter가 YAML 날짜를 Date 객체로 파싱 →
  `Tue Aug 17 2021 09:00:00 GMT+0900…` 노출. 둘러보기 행·문서 드로어·/d 페이지·근거 배지 4개 화면, docdata 131/303건 오염.
- **수정**: `fmtDate(v: unknown)` — Date instance → `YYYY-MM-DD`, 문자열은 그대로. `revised`·`최종검토일` 등 날짜 필드 일괄 적용 후 재빌드.
- **수용 기준**: ⓐ docdata JSON에 GMT 문자열 0건 ⓑ Playwright: 둘러보기 행·드로어 헤더가 `YYYY-MM-DD` 렌더.

### B3. 한글 IME 조합 중 Enter 전송 `[S]` `web`
- **현상**: `ChatApp.tsx` 채팅 입력(onKeyDown Enter)과 👎사유 입력에 `isComposing` 가드 없음 →
  조합 중 Enter가 이중전송·마지막 글자 유실 유발(한국어 전용 서비스의 상시 버그).
- **수정**: 두 핸들러에 `if (e.nativeEvent.isComposing || e.keyCode === 229) return;`.
- **수용 기준**: Playwright — 조합 상태(keyCode 229/isComposing) Enter는 전송 안 됨, 일반 Enter는 전송됨.

### B4. 스트림 오류 시 부분 응답이 '완성된 답'으로 저장 `[M]` `backend+web`
- **현상**: `app_api.py` 스트림 gen()에서 예외 시 누적분(acc)이 있으면 **절단 표시 없이 그대로 영구 저장**,
  오류 표시는 빈 응답일 때만. 클라이언트 `m.content || "⚠️…"` 패턴이 부분 응답 존재 시 에러를 은폐.
  규정 답변 도메인에서 "반 잘린 답 = 완성 답" 저장은 절대 규칙 1(정확성)에 직결.
- **수정**: ⓐ 백엔드 — 예외 시 저장 텍스트 끝에 `⚠️ (응답이 중간에 끊겼습니다 — 다시 시도해 주세요)` 마커 부착
  + SSE `error` 이벤트 송신 ⓑ 클라이언트 — error 이벤트 수신 시 절단 안내 + **다시 시도** 버튼(같은 질문 재전송).
- **수용 기준**: ⓐ 유닛 — 마커 부착 로직(부분/빈/정상 3분기) ⓑ 클라이언트 — error 이벤트 파싱·재시도 핸들러 존재(코드 검증)
  ⓒ 정상 스트림 회귀 통과.

### B5. 비밀번호 재설정 경로 전무 `[S]` `ops+web`
- **현상**: signup/login만 존재, reset 라우트·관리 CLI 없음. 분실 = 계정 영구 잠금.
- **수정**: `tools/user_admin.py` CLI(`list` / `reset-pw <user>` / `deactivate <user>`, bcrypt 재해시, APP_DB env 지원)
  + 로그인 화면에 "비밀번호를 잊으셨나요? 관리자에게 문의하세요" 1줄. 셀프서비스 리셋은 v2.
- **수용 기준**: dev app.db에서 테스트 계정 reset-pw → 새 비밀번호로 API 로그인 성공. 로그인 화면 문구 렌더.

### B6. ≤1080px에서 근거 패널 완전 소실 `[M]` `web`
- **현상**: `ChatApp.module.css` `@media(max-width:1080px){.sources{display:none}}` — 대체 접근 없음.
  노트북 절반 화면에서 제품 핵심(출처 조문)이 사라지고 "근거 조문은 우측에 표시됩니다" 안내가 거짓이 됨.
- **수정**: ≤1080px에서 답변 하단/헤더에 **"근거 N개" 버튼** → 오버레이(기존 sources 패널 마크업 재사용)로 표시.
  안내 문구는 뷰포트 무관 표현으로 수정. (버그 수정 성격 — 플래그 없이 적용)
- **수용 기준**: Playwright 1000px — 근거 버튼 노출·클릭 시 근거 카드 오버레이 표시·닫기 동작. 1440px 회귀(기존 패널 유지).

## 5. 테스트 전략
- 버그 수정(B2·B3·B6): **Playwright 실렌더**(프로젝트 규칙 — 번들 검사 아닌 실화면).
- 백엔드 로직(B4): 유닛(마커 3분기) + 정상 스트림 회귀. 인위적 스트림 절단 E2E는 불가 → 코드 경로 검증으로 갈음(스펙에 명시).
- 운영(B1·B5): 실제 실행 검증(백업 파일 integrity_check, CLI로 비번 변경 후 로그인).
