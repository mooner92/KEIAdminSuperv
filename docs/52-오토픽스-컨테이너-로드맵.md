## 0. 결론 요약 (TL;DR)
1. **가능하고, 공식 지원 경로가 있다** — Claude Code headless(`claude -p`, `--allowedTools`,
   `--output-format json`(cost_usd 포함), dontAsk 퍼미션 모드)와 Claude Agent SDK(Python)가
   2026년 현재 무인 파이프라인 표준이다. 제안 구조는 트렌드에 부합한다.
2. **단, 설계 수정 2가지를 강하게 권고한다**:
   - ⓐ **Qwen에게 CLI를 쥐어주지 않는다** — Claude Code 호출은 **결정적 오케스트레이터
     (Python 스크립트)**가 한다. Qwen의 역할은 지금처럼 보고서(Gate 0)까지. (§2 근거)
   - ⓑ **"완전 자동"의 마지막 관문 = 사람 머지** — 자동은 "코드 수정→검증→PR 생성"까지,
     머지 버튼이 곧 승인이자 **롤백 지점**이다. 무인 머지는 Phase C에서 실적 보고 결정. (§3)
3. **자동 수정은 절대 라이브에 바로 반영하지 않는다**(§3.5, 사용자 지적) — 불변 이미지 +
   **블루-그린 승격 관문**(골든셋 50문항 행동 회귀가 필수 게이트)으로 "검증 통과 전엔 트래픽 0".
   핵심 기능 붕괴·모델 공격에 의한 가드레일 변질 모두 승격 차단으로 막고, 롤백은 라우터 1초 전환.
4. **K8s는 지금 아니다** — 단일 노드·공유 GPU·SQLite에 K8s는 순비용. **Docker Compose
   블루-그린**(web+api만 컨테이너, Ollama·임베더는 호스트 유지)가 안전·롤백·이전(manual/) 이득을
   챙기는 적정선. k3s 재평가 조건 명시. (§5)
4. 트렌디 업그레이드는 선별 채택(§6): Claude Code GitHub Action(공개 레포 PR 리뷰), 경량 CI,
   Renovate, chroma 스냅샷 백업, 비용 예산 가드. 과한 것(K8s·OpenTelemetry 풀스택·semantic-release)은
   근거와 함께 기각.

## 2. 오토픽스 아키텍처 — "누가 Claude Code를 부르나"
```
제보(사용자) ─→ [Gate0 분석: 로컬 Qwen] ─→ 보고서(G2 + claude_프롬프트)
                                              │
                              [승인 트리거: Phase A=관리자 버튼 / B=자동]
                                              │
        [오케스트레이터 maint_executor.py — 결정적 Python, LLM 아님]
              │ 1. 새 worktree 생성(autofix/<id>, feat/krds 기준)
              │ 2. claude -p "<audit.soul 헌장> + <보고서 프롬프트>"
              │      --allowedTools "Read,Edit,Write,Bash(테스트 한정)"
              │      --output-format json --max-turns N   (예산·시간 캡)
              │ 3. 검증 게이트: 관련 test_*.py + verify-*.mjs 실행
              │ 4-성공. 브랜치 push + PR 생성(gh) + 🔔 알림(+비용 기록)
              │ 4-실패. 로그 첨부 보고 + worktree 폐기(코드 흔적 0)
              ▼
        [사람: PR 리뷰 → 머지] ─→ 배포 스크립트 ─→ 패치노트·제보 답글(기존 5단계)
```
**ⓐ Qwen이 CLI를 잡으면 안 되는 이유** (제안에서 유일하게 바꾸는 부분):
- **주입 에스컬레이션 차단**: 제보(신뢰 불가)→Qwen 보고서→"실행"으로 이어지는 사슬에서,
  실행 단계가 LLM 재량이면 docs/51 §9에서 세운 "권한으로 막는다" 원칙이 무너진다.
  오케스트레이터가 결정적이면 **무엇이 실행되는지 코드로 감사 가능**하다.
- 9B 모델의 CLI 조작 신뢰도 문제 + 디버깅 불가. 그리고 **이득이 없다** — 보고서에 이미
  완성 프롬프트가 있으므로 "전달"은 코드가 하면 된다. Qwen은 분석가, Claude는 시공자,
  오케스트레이터는 결정적 감독관 — 역할 분리가 곧 안전이다.

**audit.soul (헌장 파일, `tools/audit.soul`)** — 모든 무인 실행에 선두 주입:
- 임무: 첨부된 유지보수 보고서의 해당 G2 항목만 수정한다(스코프 밖 변경 금지).
- ⛔ 금지구역: `KEI-행정가이드/`·`rule_files/`·`*.hwp`·`.app_secret`·`app.db`·`manual/`·
  RAG 가드레일(SYSTEM 프롬프트)·기능 플래그 기본값. 절대 규칙(CLAUDE.md ⛔) 전부 승계.
- 의무: 수정 후 관련 테스트 실행·통과 확인, 커밋 메시지 규약, 변경 요약을 JSON으로 출력.
- 계약: 확신 없으면 수정하지 말고 "사람 확인 필요"로 종료(빈손 종료가 잘못된 수정보다 낫다).

**API key 관리** (지시: 마이그레이션 시 교체 가능하게):
- `tools/.anthropic_key`(0600, gitignore — `.app_secret` 관례와 동일) → 오케스트레이터가
  `ANTHROPIC_API_KEY`로 주입. `manual/` 03(반입)·05(기동)에 키 항목 추가(구현 시).
- 참고: 2026-06-15부터 구독 플랜의 `claude -p`/Agent SDK는 별도 월간 크레딧 — **API key
  종량제로 갈지, 구독 크레딧으로 갈지**는 §8 결정 사항(비용 §4).

**Phase A 이후 고도화(선택)**: `claude -p` 서브프로세스 대신 **Claude Agent SDK(Python)** —
오케스트레이터가 이미 Python이므로 구조화 출력·세션 제어·서브에이전트가 필요해지면 자연 승격.

## 3. 롤백 설계 (지시: "이전 버전으로 롤백하기 좋게")
| 시점 | 롤백 수단 | 비고 |
|---|---|---|
| PR 머지 전 | **브랜치 폐기**(원클릭) | 본선에 흔적 0 — 이것이 기본 방어선 |
| 머지 후 배포 전 | `git revert` | PR 단위라 깔끔 |
| 배포 후 | 릴리스 태그로 재배포(§5 컨테이너면 이미지 태그 교체) | `deploy.sh vX.Y` |
| 데이터 | app.db 자동백업(기존)·chroma 백업(재색인 관례)+스냅샷 cron(§6) | 코드와 독립 |
- 원칙: **오토픽스는 절대 본선에 직접 커밋하지 않는다**(항상 브랜치+PR). 릴리스는 태그로만.

## 3.5. ⭐ 배포 안전 — 불변 이미지 + 블루-그린 승격 관문 (2026-07-19 추가, 사용자 지적)
**전제 수정**: "자동 수정 → 바로 라이브 반영"은 **금지**한다. 핵심 기능이 깨지거나(회귀),
모델 공격으로 가드레일이 약화되면 라이브 장애가 된다. 방어는 **"새 버전은 검증 관문을
통과하기 전엔 단 한 명의 사용자도 못 만난다"** — 사용자 지적을 반영한 블루-그린.

```
[green 컨테이너: 라이브 트래픽]  ← 계속 안전 (blue가 깨져도 무관)
        │  오토픽스 머지 → 새 이미지 빌드
[blue 컨테이너: 트래픽 0]
        │  ┌ 승격 관문(blue에서만 실행, 트래픽 격리) ─────────┐
        │  │ 1. verify-*.mjs 72종 + test_*.py 20종          │
        │  │ 2. ★골든셋 50문항 행동 회귀(eval/golden.jsonl) │
        │  │    — 면책 누락·근거 밖 답변·거부 회귀 감지      │
        │  │ 3. /health 정상 + 스모크(로그인→질문→근거→PDF) │
        │  └────────────────────────────────────────────────┘
        ▼  전부 통과해야만
[라우터 전환 green→blue]  ── 문제 시 즉시 되돌림(1초, 이미지 태그 교체)
```

### 위협별 방어 (사용자 우려 2종)
**① 파일 삭제·손상**
- 서비스 컨테이너 파일시스템 **read-only 마운트** — 런타임에 코드·설정 삭제 불가.
- 볼트·`.app_secret`·`app.db`는 **서비스가 못 쓰는 별도 볼륨**(RAG는 chroma만 읽음).
  git이 코드 진실원천 → 언제든 복원. 오케스트레이터=결정적 코드(§2 ⓐ)라 실행 감사 가능.

**② "이상 답변하도록 내부 수정"(가드레일 무력화 — 가장 위험)**
- 가드레일(`rag_core.SYSTEM`·면책·"근거 없으면 확인 안 됨")은 **audit.soul 금지구역**
  (절대 규칙 4 승계) — 오토픽스가 못 건드림.
- **골든셋 50문항이 승격 관문의 필수 게이트**: 답변 행동이 변질되면(면책 누락·근거 밖 답변·
  거부해야 할 질문에 답변) 회귀가 **실패 → 승격 차단**. 변질된 이미지는 애초에 트래픽 못 받음.
- 커밋 diff는 **사람이 PR 머지** — 가드레일 변경이 diff에 보이면 즉시 거부.
- (선택) 이미지 다이제스트 고정·서명으로 "승인된 이미지만 라우팅".

### 구현 형태 (K8s 없이)
- Docker Compose 두 스택(`kei-*-green`/`kei-*-blue`) + **서버/nginx 라우터가 활성 색을 가리킴**
  (`ACTIVE_COLOR` 파일/env 1줄 교체 = 전환·롤백). 승격 관문 = `promote.sh`(관문 통과 시에만
  라우터 전환). 데이터 볼륨(볼트·chroma·app.db)은 **두 색이 공유**(코드만 교체, 데이터 불변).
- ⚠ 데이터 마이그레이션이 필요한 변경(스키마)은 블루-그린으로 못 덮음 — 그런 PR은
  `needs-migration` 라벨로 사람 전용 배포(자동 승격 제외).

## 4. 비용·예산 가드

## 5. 컨테이너화 판단 — Docker는 단계적 YES, K8s는 NO(지금은)
**정직한 평가**: K8s의 가치(다중 노드 스케줄링·셀프힐링·선언적 스케일)는 우리 지형(단일 노드·
공유 GPU·SQLite·정적 파일·사내 전용)에서 살 게 없다. 운영 복잡도·학습 비용만 순증.
PM2+worktree가 이미 프로세스 관리·이중 슬롯(3100/3101)을 제공 중.

**그래도 Docker Compose를 단계 도입할 가치**(트렌디해서가 아니라 실익):
1. **롤백**: 이미지 태그 고정 → "지난 버전으로" = 태그 교체 1줄 (§3 표와 결합)
2. **이전(manual/) 단순화**: 런북 01~05단계 상당 부분이 `docker compose up`으로 대체
3. **재현성**: node22/LibreOffice/폰트 의존성이 이미지에 고정 — "빌드는 반드시 nvm 22" 류 함정 소멸

**하이브리드 구성(권장)**: 컨테이너 = `kei-web`(server.js+out) · `kei-api`(uvicorn+venv).
호스트 유지 = Ollama(공유 GPU·Vulkan 드라이버 535 의존 — 컨테이너화 리스크 큼), 임베더/리랭커
(GPU 직접 접근), 볼트·chroma·app.db(볼륨 마운트). PM2 → compose 서비스로 점진 이관.
**k3s 재평가 트리거**: ⓐ노드 2대 이상 ⓑGPU 전용 서버 분리 ⓒ동시 사용자 급증으로 복제 필요 —
셋 중 하나 전이면 그때 k3s(경량 K8s)부터.

## 7. 단계별 실행 계획 (⚠ 순서 수정 2026-07-19 — 컨테이너 격리가 오토픽스보다 먼저)
사용자 지적 반영: 자동 수정이 라이브를 건드리기 전에 **격리·승격 관문이 선행**돼야 안전.
따라서 "반자동 오토픽스(PR까지)"는 컨테이너 없이 시작 가능하지만, **자동 배포는 §3.5
블루-그린이 있어야만** 켠다.

- **Phase A — 반자동 오토픽스, 배포는 사람** (구현 ~1일, 컨테이너 불요):
  `audit.soul` + `maint_executor.py`(결정적 오케스트레이터) + 의견함 G2 항목 "🤖 자동 수정 시도"
  버튼 → worktree→`claude -p`→verify/test→**PR 생성**→🔔. 머지·배포는 **사람**(현 pull형 CD).
  수용 기준: G2 제보 1건이 "PR 생성+검증 통과"까지 무인 도달, 실패 시 흔적 0,
  주입 제보에서 audit.soul 거부 종료, 골든셋 회귀 통과.
- **Phase B — 컨테이너 격리 + 블루-그린 승격 관문** (§3.5 구현): Compose green/blue 두 스택 +
  `promote.sh`(verify+test+**골든셋 50문항**+health 통과 시에만 라우터 전환) + 즉시 롤백.
  read-only 파일시스템·데이터 볼륨 분리·가드레일 금지구역. **이게 있어야 자동 배포를 논한다.**
  경량 CI(GitHub, 코드-only)·Renovate·chroma 백업 cron 병행.
- **Phase C — 무인 배포(제한적)** (B 안정화·실적 기반): 승격 관문을 통과한 **저위험 클래스**
  (문구 수정·단일 파일·`needs-migration` 아님)만 자동 승격 허용. 그 외는 계속 사람 머지.
  실패율·롤백 빈도 데이터로 허용 클래스를 점진 확대. self-hosted runner는 여기서 검토.

## 8. 결정 대기 (사용자)
1. **Phase A 착수 승인** — 및 자금원: API key(종량) vs 구독 Agent SDK 크레딧.
2. GitHub PR 흐름 사용 여부(공개 레포 — 코드만 올라가는 현 가드레일 하에서 PR도 코드만).
3. Phase C 컨테이너 이관 시점(마이그레이션과 겹치면 그때 함께가 효율적).
