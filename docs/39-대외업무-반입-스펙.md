### 1-3. 개인정보 경계 (P2.5 원칙의 연장)

- **개인명(담당자·의원명)은 RAG 코퍼스에 넣지 않는다.** 근거: ⓐ 인사이동으로 스테일
  ⓑ 챗봇이 "OO 담당자는 윤OO"라고 단정 답변하는 것 자체가 개인정보 노출+오정보 위험
  ⓒ 정리본 스스로 "매칭은 부서 단위 권장" 명시.
- 반입본 편집 규칙: §7-3(핵심 담당자 연속성) 단락 전체 삭제 → "담당자는 부서 단위로 확인하고,
  현재 창구는 대외업무관리시스템에서 조회" 1줄로 대체. 본문 잔여 개인명(§3-2 (나) 등)도 제거.
- 검증: 반입 후 볼트 문서에서 원본 §7-3 개인명 목록 grep 0건(자동 테스트).
- 의원실명(요구처)은 반입본(분류체계)에 애초 집계 수준만 존재("개별 의원실") — 그대로 허용.

## 2. 용어집 재정리 (③ 30_용어집 신규 ~10노트)

정의 문구는 **분류체계 문서의 설명 문구만** 사용(창작 금지), 각 노트 `관련규정: []`(해당 없음),
태그 `[대외업무]`. 목록(안):

1. 대외요구자료 — 정의 + 4대 사이클 요약
2. 국정감사 공통요구자료(총괄표) — 대량 동시배포 방식 포함
3. 결산검토기초자료 — 1~2월 취합, 작성1/작성2 양식
4. 경제·인문사회연구회(연구회/경사연) — 최대 요구처, 소관기관 관계
5. 통합공시·수정공시 — 2~4월 정기·11월 점검
6. 출연금 교부신청·집행률 — 월례 보고
7. 법인카드 모니터링 — 월례, 감사실
8. 정무위원회(정무위) — 소관 상임위, 회기 연동
9. 국정감사 후속조치 — 감사 후 11~1월, 증가 추세
10. NKIS(국가정책연구포털) — 연구성과 등록 월례

- 기존 용어 노트와 제목 충돌 검사 후 반입(슬러그 충돌 시 접미어). 01g(용어 교차링크)는
  관련규정이 없어 효과 없음 — 실행하되 무해.

## 3. 대외업무관리시스템 활용 노트 (② 40_시스템)

**원자료에서 관측된 사실만** 기술(⛔ 화면 캡처 없이 UI 절차를 상상하지 않는다):

- 시스템 정체: 대외 요구자료의 접수·배정·제출을 관리하는 사내 시스템.
- 확인된 메뉴: `대외요구자료 > 상세조회`(연도별 파일 서문에 명시).
- 레코드 구조: 요구일자 / 제출기한 / 질의명(요구사항) / 요구처 / 담당부서 / 담당자 / 처리상태
  (관측 상태값: "완료(제출)").
- 조회 특성(관측): 1회 조회 상한이 있어 기간 구간을 나눠 조회(원자료 수집 방식에서 확인).
- 활용 시나리오: ⓐ 이번 달 예상 대외업무 대비(분류체계 §2 참조) ⓑ 과거 유사 요구 선례 검색
  ⓒ 담당 창구 확인(개인명은 시스템에서 직접 — RAG는 부서까지만 안내).
- 「TODO: 원문 확인」: 메뉴 전체 구조·권한 체계는 실물 화면 확인 후 보강.

## 4. /now 월별 대외업무 캘린더 (④)

### 4-1. 데이터 — `seasonal.json` 확장

- 분류체계 **§2(월별 흐름)·§9(종합 결론)**에서 "3개년 공통 반복 확정" 항목만 반입.
- 항목 설계: 월별 1~3건 + **월례(매월) 5건**. 스키마 확장:
  - `month: 0` = **매월(상시)** 항목(신설) — 인력현황, 출연금 교부·집행률, 법인카드 모니터링,
    각종 수요조사, 개별 의원실 질의 대응.
  - `구분: "대외업무"`(옵션 필드 신설) — UI에서 작은 칩으로 표시, 기존 항목(연말정산 등)과 구별.
- `상태`: 3개년 모두 관찰된 항목 = **"확정"**(근거 있음 — 예시 배지 제거됨).
  연도별 유동 항목(국정감사 총괄표 배포월 5~8월 유동)은 해당 월들에 넣되 desc에 "연도별 유동" 명시.
- `근거`: "대외요구자료 반복업무 분류체계 (3개년 통합)"(반입 문서 제목) — calendar_lint 실존 검사 통과.
- ⛔ 중단 업무(주간계획·업무추진비·리서치트렌드)는 캘린더 배치 금지(§3-5). 금액·"N일 이내" 문구 금지.
