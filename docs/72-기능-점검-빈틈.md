## 2. 우선순위 (효과 ÷ 비용)

### P1. 여비 계산기 ⭐ — 질문 1위 × 불만 1위가 겹치는 자리
직급 × 구간 × 교통수단을 넣으면 **별표 그대로** 금액을 보여주는 화면. `/approval`(금액→전결권자)과
같은 계열이고 부품도 동형: 결정적 조회 + 근거 원문행 + "부서 확인" 면책.
⚠ 선행 조건 — 여비규정 별표가 **깨진 표**로 판정돼 있다(👎·제보 2건의 실체). `01p_table_restore`
스테이징 → 사람 검수 → `01q_table_store`로 값 확정이 먼저다. 검수 없이 계산기를 만들면 절대규칙 1 위반.

### P2. 미종결 제보 3건 종결 — 사용자가 직접 낸 목소리
"별표 표 깨짐"(2건, P1과 같은 뿌리) · "답변 복사 버튼 무반응"(1건). '분석됨'에서 멈춰 있다.
복사 버튼은 소규모 수리 — 즉시 처리 가능.

### P3. prod 승격 대기 기능 — 이미 만들었는데 사용자에게 도달 안 함
`journey_freshness`(여정 신선도 배지) · `corpus_amend`(개정 반영) · `lab_hub`가 dev만 on.
개발 비용 0, 승격만 하면 됨. **다음 승격 열차에 반드시 포함.**

### P4. 기안 도우미 — /approval의 '누가' 다음 질문 ✅ 구현(2026-08-19, flag `gian_helper`)
문서종류별 첨부 서류·기록물철·협조/결재 구분. 결재선 질문 24건의 실제 절반이 여기다.

- 매핑 인덱스 `tools/01r_gian_map.py` → `tools/index/gian_map.json`(결정적·LLM 0회, 재색인 파생에 등록).
  볼트 5종(업무별 적용·기록물철 코드표·결재상신 공통·문서관리규정·기록물관리규정) + `approval.json` 조인.
- 화면 `/gian`(`web/pages/gian.tsx` + `web/components/gian/`) — 업무군 5종 선택 → ⓐ문서종류 ⓑ첨부(**권장**)
  ⓒ기록물철 후보(코드·보존기간·근거 문장) ⓓ결재선 역할 7종(문서관리규정 제26·27·29·30조 조인)
  ⓔ전결권자(위임전결 별표). 근거 없는 자리는 비우고 "원문 확인"(참조·후열은 조문 근거 없음을 명시).
- 회귀 `web/verify-gian-helper.mjs`(28항목). ⚠ `verify-gian.mjs`는 기존 '기안 노트 적재' 검증이라 별도 파일.

### P5. 여정 확장(specs/13 미완 8건 중 사용자 노출분)
연구비 계열 여정 신설(자문수당·예산 전용·위촉연구원) · 신입 온보딩 1장 · T03 **서식 연결 0/67**
(여정 단계에서 별지 미리보기 바로 열기) · T04 단계 체크·진행률.

### 하지 않을 것
- **복지·시설 화면**(명상실·주차장 등) — 코퍼스에 근거가 없다. 화면을 만들면 없는 규정을 있는
  것처럼 보이게 한다(절대규칙 1). 필요하면 **원문 확보가 먼저**.
- 영어 언어팩(specs/08) — 07-28 보류 결정 유지.

## 3. 병목 하나 — 사람 검수

`value_store.json` 0행 = 볼트에 `검수완료` 문서가 **0개**다. P1(여비 계산기)·specs/06(금액 룰
엔진)이 전부 여기서 막힌다. 기능 로드맵의 최대 제약은 코드가 아니라 **검수 대기**다.
검수 큐(`/admin`)는 자주 틀린 규정 순으로 정렬돼 있으니, **여비규정 별표부터** 착수하면
P1과 직결된다.
