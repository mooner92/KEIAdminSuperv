## 1. 이번 주에 고친 것 — 측정 자체의 결함 3건

품질 분석을 하다 **측정기가 틀렸다는 사실**을 먼저 발견했다. 개선 방향을 잘못 가리키고
있었으므로 우선 고쳤다. 셋 다 "조용히 잘못되는" 유형이었다.

| # | 결함 | 규모 | 조치 |
|---|---|---|---|
| ① | 축 채점기 5곳이 **근거 확인 없이** 거부→검색실패로 단정 | 검색실패 56건 중 **9건(16%) 오분류**, 1건은 **7회차 연속** | `refusal_cause()` 단일 정본 신설, 5곳 통일. 신설 원인 `근거부적합` |
| ② | 채점기에 `q`만 넘겨 **x_sources 접근 불가** | ①을 고쳐도 항상 검색실패로 샜을 구조 | `item`(질문+답변) 전달로 수정 |
| ③ | `defterms`가 **별첨 인용 법령 정의를 본문 조에 귀속** | 400 바인딩 중 4건, 원인이 7일간 은폐 | `01j`에서 별첨 이후 스캔 제외 → 재감사 **오귀속 0** |

⚠ 그리고 **①의 수정이 새 구멍을 만들었다**: 신설 원인 `근거부적합`을 `classify_failure`
화이트리스트에 넣지 않아 08-07에 2건이 `미분류`로 떨어져 **수술대기에서 통째로 누락**됐다
(리포트 9건 / 실제 11건). 08-08부터 정상 집계된다.

**교훈(설계 원칙으로 승격):** 분류 축을 새로 만들 때는 *생성 → 집계 → 표시* **경로 전체**를
같은 커밋에서 검증한다. 중간 한 곳만 모르면 그 항목은 사라지고, **사라진 것은 통계에서
'정상'처럼 보인다.** → 원인 목록과 리포트 버킷을 소스에서 파싱해 대조하는 회귀를 넣었다.

## 2. 남은 서비스 결함

### A. 생성환각 — 신뢰 게이트의 사각지대

전 회차 생성환각 **63건 전수 분석**: 증거 문장에 숫자가 없는 건이 **52건(83%)**.
현행 게이트(`numeric_guard`·`table_guard`)는 금액·%·기간·날짜·표만 감시한다.
**대부분의 환각은 숫자를 안 틀리고 다른 것을 지어낸다.**

| 유형 | 실측 사례 |
|---|---|
| **출처 조문 날조** | "개인정보 보호법 제25조제1항" ← 원문은 "개인정보보호지침 제3조" |
| **기산일 바꿔치기** | "안 날" ← 원문은 "마친 날" |
| **적용범위 혼동** | 국내 여비 질문에 **국외** 기준으로 답변 |
| **금지→허용 뒤집기** | 원문은 일반 공개 **금지**인데 "심의 절차로 가능"이라 답변(08-08) |
| **없는 UI 상태 발명** | "신청요청/참석확정 체크박스" ← 원문에 그런 구분 없음 |
| **다른 절차로 대체** | 근로시간 집계 질문에 전자결재 기안 절차 설명(**3회 반복**) |

## 3. 통합 개선안

원칙: **측정을 먼저 믿을 수 있게 만들고**(T2·T4), **가장 위험한 환각**을 막고(T1),
마지막에 **시험지를 정리**한다(T3). 전부 결정적(LLM 0회) 구현 가능한 것부터 배치.

### T1. 출처 조문 날조 가드 ⭐

**무엇** — 답변이 인용한 `[규정명 제N조]`가 **실제 근거(x_sources)에 있는 조문인지**
결정적으로 대조. 없으면 ⚠ 경고 부착(기존 `numeric_guard_note`와 동일 방식).

**왜 최우선인가**
- ⛔절대규칙 3(모든 답변에 정확한 출처)을 **직접** 위반한다.
- **LLM 0회·완전 결정적** — 답변에서 `[…제N조]`를 뽑아 x_sources와 집합 비교하면 끝.
- 문자열 대조라 판단이 개입하지 않아 **오탐 위험이 낮다**.
- 사용자가 출처를 믿고 원문을 찾아갔는데 그 조문이 없으면 **신뢰가 즉시 무너진다.**

**하지 않을 것** — 답변 차단. 기존 게이트와 같이 **경고 부착까지만**.

### T2. 환각 유형 분리 집계

**무엇** — 한 덩어리인 `생성환각`을 최소 셋으로: `출처날조` / `근거곡해`(적용범위·기산일·
금지허용) / `코퍼스밖-거부실패`(거부형 시드).

**왜** — 63건이 한 라벨에 섞여 **어느 가드가 몇 건을 잡을지 예측할 수 없다.** T1의 효과
측정도 분리 없이는 불가능하다.

### T3. 반복 실패 가시화 + 출제 위생

- 수술대기 항목에 **"N회째" 배지**(hash 기준 연속 실패 횟수).
- 노이즈 12~17% 고착 대응: `golden_repair.py`가 이미 후보를 뽑는다 — **소비 루틴이 없다.**
  주간 1회 사람 검토 루프를 붙인다.
- 「길라잡이」 등 **비규정 문서의 골든 출처 가중치** 재검토.

### T4. 지표 신뢰성 정비

- **어휘갭**: 이동평균 + 층별 최소 표본 미만이면 "표본 부족" 표기. 하루치 갭으로 우선순위를
  바꾸지 않는다(08-06의 10.0%p 오판 재발 방지).
- **재시험 코호트**: 폐기·판정불가를 뺀 **순수 오답률**을 별도 병기. 지금 값은 시험지 결함에
  오염돼 추이 해석이 불가능하다.

### T5. 어휘 갭 별칭 사전 — **보류**

T4로 갭이 **지속적**임이 확인되면 착수. 지금은 근거가 흔들린다.

## 4. 권고 순서

```
T2(환각 분리) → T1(출처 날조 가드) → T4(지표 신뢰성) → T3(출제 위생) → T5(보류)
```

T2를 앞에 두면 T1의 **목표와 효과를 수치로 말할 수 있다.**
다만 T1은 단독 가치가 크고 구현이 짧아 **T1 먼저도 타당**하다(운영자 선택).
