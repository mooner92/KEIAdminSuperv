# docs/44 — 보안 명세 (secure check): 위협 모델 · 조치 현황 · 잔여 리스크

> 2026-07-16 작성·확장. 배경: 소개(랜딩) 페이지(`/`, `/about`)가 **외부 공개될 수 있고**,
> 현행 dev(3101)가 **포트 변경 없이 정착지가 될 수 있다**(사용자 확정). 따라서 3101 자체를
> 공개 가능 수준으로 명세·조치한다. (prod 3100은 이 문서 범위 밖 — 신경 쓰지 않음.)
>
> 검증 스위트: `web/verify-secure.mjs` (**37/37**, 아래 각 조치의 회귀 테스트).

## 0. 아키텍처와 신뢰 경계
```
[브라우저] ── HTTP(S) ──> web/server.js :3101 (정적 out/ + 프록시, 의존성 0)
                              ├─ 정적: out/ (규정 원문 docdata·검색인덱스·문서 페이지 = 민감)
                              ├─ /api/app/* ──> FastAPI app_api.py :9001 (127.0.0.1 전용)
                              └─ /api/rag/*  ──> 동일 :9001 /v1/* (OpenAI 호환, 업스트림 무인증)
```
- **신뢰 경계 1**: 브라우저 ↔ server.js — 여기서 로그인 게이트·보안 헤더·본문 상한.
- **신뢰 경계 2**: server.js ↔ FastAPI — 127.0.0.1 바인딩. XFF는 server.js가 소켓 주소로
  **덮어쓰므로**(위조 차단) FastAPI가 신뢰 가능.
- 바깥 방벽(현행): Cloudflare Zero Trust(사내 전용). 외부 공개 시나리오에선 이 방벽이
  랜딩에 한해 열리므로, **아래 조치들이 실질 방어선**이 된다.

## 1. 위협 모델과 조치 매트릭스

### T1. 비로그인 콘텐츠 노출 (외부 공개 시 치명)

> ⚠ **2026-07-29 — 이 게이트는 한 번 우회됐다.** 허용목록 자체는 맞았는데,
> **인가를 원본 경로로 판정하고 서빙은 정규화 경로로** 해서
> `/_next/static/../../d/<문서>.html` 이 통과했다(비로그인 200, 실측 5종).
> 허용목록에 무엇을 넣느냐만큼 **어느 경로로 판정하느냐**가 중요하다 —
> 순서는 반드시 **정규화 → 인가 → 서빙**. 상세·회귀 = docs/63 §2.
| 공격 표면 | 위험 | 조치 | 상태 |
|---|---|---|---|
| `/browse/`·`/d/<slug>/`·`/journey/` 등 페이지 HTML | 규정 원문·여정 데이터가 HTML에 인라인 | 서버 게이트: 비로그인 302→랜딩 | ✅ 이번 조치 |
| `/docdata/*.json`(332건)·`/search-index.json`(전 규정 본문 4MB)·`changelog/approval.json` | 원문 일괄 다운로드 | 〃 (허용 목록 외 전부 차단) | ✅ |
| `/_next/data/<id>/*.json` (페이지 데이터) | 문서 본문 포함 | 랜딩 2건(index/about)만 허용 | ✅ |
| `/api/rag/chat` → 업스트림 `/v1`(무인증) | **익명 RAG 질의로 규정 내용 추출** | server.js에서 비로그인 401 | ✅ |
| `/api/app/*` | 채팅·피드백·관리 | FastAPI 자체 JWT 인증(기존) — 이중 게이트 불필요 | ✅ 기존 |
| 랜딩 소개 카드 | 서비스 진입점 노출 | 카드 3종 프레젠테이션 전용(링크 제거) | ✅ |
| 검색엔진 색인 | 공개 시 URL 확산 | `/robots.txt` Disallow: / (서버 내장) + 페이지 noindex meta | ✅ |

**게이트 구현**(web/server.js, 의존성 0 유지): app_api와 동일 JWT(HS256·쿠키 `kei_session`·
`tools/.app_secret`, env `APP_SECRET_FILE`)를 Node `crypto`(HMAC + `timingSafeEqual`)로 검증, exp 확인.
**fail-closed** — 세션키 없으면 전부 차단, 해제는 `REQUIRE_LOGIN=0`(비상용)뿐.
비로그인 허용 목록(이외 전부 302→`/`): `/`·`/about(/)`·`/_next/static/*`(해시 코드만)·
`/_next/data/<id>/{index,about}.json`·`/fonts/*`·`/favicon.*`·`/robots.txt`·
`/api/app/auth/*`·`/api/app/flags`·`/api/rag/health`.
⛔ **허용 목록에 규정 콘텐츠 경로를 추가하지 말 것.**

### T2. 인증·계정 공격
| 위험 | 조치 | 상태 |
|---|---|---|
| 로그인 무차별 대입 | 실패 8회/5분(사용자+IP) → 429. **프록시 뒤 IP 붕괴 교정**: server.js가 XFF를 소켓 주소로 덮어쓰고 `_client_ip()`가 이를 사용(위조 불가 — API는 127.0.0.1 전용) | ✅ 기존+이번 교정 |
| 인증 코드(6자리) 대입 | 코드는 HMAC 해시만 저장, 10분 TTL, **5회 시도 후 폐기**, 재발송 60초 쿨다운+비밀번호 확인 | ✅ 기존 |
| 대량 가입·코드 발송 남용 | IP당 가입 10회/시간 → 429 (env `APP_REG_RL_MAX`, dev만 100) | ✅ 이번 조치 |
| 약한 비밀번호 | 최소 4자 → **8자**로 상향(신규 가입) | ✅ 이번 조치 |
| 외부인 가입 | `@kei.re.kr` 도메인 allowlist(fail-closed, env 미설정에도 잠김) + **관리자 승인제**(signup_approval ON — 승인 전 로그인 403) | ✅ 기존 |
| 세션 토큰 탈취 | 쿠키 `httponly`+`samesite=lax`(기존). HTTPS 배포용 `COOKIE_SECURE=1` 토글 신설 | ✅ 기존+이번 |
| 계정 열거 | 로그인 실패 메시지 단일화(아이디/비번 구분 없음) | ✅ 기존 (register 409는 잔여 — §3) |
| 관리자 권한 | `APP_ADMINS` fail-closed(미설정 시 아무도 관리자 아님), 부트스트랩 없음 | ✅ 기존 |

### T3. 웹 애플리케이션 공격
| 위험 | 조치 | 상태 |
|---|---|---|
| XSS 시 데이터 유출 | **CSP 신설**: `default-src 'self'` + script/style만 unsafe-inline(Next 정적 export 제약), img `self data:`, connect/font `self`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri/form-action 'self'` — 외부 오리진 유출 경로 차단 | ✅ 이번 조치 |
| 클릭재킹 | `X-Frame-Options: DENY` + CSP frame-ancestors | ✅ |
| MIME 스니핑/격리 | `X-Content-Type-Options` + **COOP/CORP `same-origin` 신설** | ✅ |
| 디렉터리 탈출 | 경로 정규화 + ROOT 프리픽스 검사 | ✅ 기존 |
| 초대형 본문 DoS | 프록시 본문 상한 2MB(413) — Content-Length + 청크 카운터 양쪽 | ✅ 이번 조치 |
| 슬로우로리스 | `headersTimeout 30s`/`requestTimeout 120s` 명시(SSE 응답엔 무영향) | ✅ 이번 조치 |
| XFF 위조 | server.js가 항상 소켓 주소로 **덮어씀**(신뢰 경계 §0) | ✅ 이번 조치 |

### T4. 데이터 최소화·프라이버시 (기존 구현, 재확인)
- 관리자에게 타인 채팅 열람 엔드포인트 없음 · `/stats`·`/feedback` 본문 미반환 · k-익명(K≥3) 집계.
- `/track`: 로그인 필수, 라우트 프리픽스만 저장, 시간 절사, 보존 180일 자동 삭제.
- LLM·임베딩·볼트 전부 온프레미스 — 외부 API 반출 없음(CSP connect-src 'self'가 이중 방어).

## 3. 잔여 리스크 (수용 또는 후속)
| 항목 | 내용 | 방침 |
|---|---|---|
| JWT 폐기 불가 | 무상태 토큰 — 로그아웃해도 탈취 토큰은 만료까지 유효(TOKEN_DAYS) | 수용(만료 有). 필요 시 jti 블랙리스트 후속 |
| register 계정 열거 | "이미 가입된 이메일"(409) — 가입 여부 노출 | 낮음(도메인 제한+승인제) — 공개 확정 시 메시지 단일화 |
| CSP unsafe-inline | Next 정적 export 인라인 부트스트랩 제약 | 수용 — nonce 도입은 서버 렌더 필요(구조 변경) |
| 레이트리밋 인메모리 | 프로세스 재시작 시 초기화, PM2 단일 프로세스 전제 | 수용(단일 프로세스 운영 규약) |
| 오토픽스 관문 미격리 | `gate_python`이 도는 테스트가 worktree의 `tools/*.py`를 import — 에이전트가 쓴 코드가 관문에서 실행된다. 관문이 실행하는 파일(`test_*.py`·`package.json`)의 변경은 차단했으나 구조는 남음(docs/63 §3) | **후속 — 컨테이너 관문 전까지 `AUTOFIX_ENABLED=0` 권장** |
| 접속 로그 일부 부재 | 로그인 이벤트는 기록됨(§2-11 완료). server.js 정적 게이트의 302 차단은 미기록(비로그인 내비게이션마다 발생해 소음 — 공개 후 필요성 재평가) | 부분 완료 · 잔여는 후속 |

## 4. ⛔ 외부 공개(랜딩 오픈) 전 필수 체크리스트
1. **HTTPS 종단** 확보(CF 프록시/터널) + `COOKIE_SECURE=1` 설정.
2. **dev 편의 제거**: 테스트 픽스처 계정(`b6test`·`fb_test`·`badgetest` 등 7종) 삭제
   — ⛔`admintest`는 **실재하지 않는 계정**이다(2026-07-29 확인, docs/63 §4).
   `APP_DEV_ECHO_CODE` 제거(2026-07-29부터 루프백 전용이지만 원칙상 제거), `APP_REG_RL_MAX` 제거(기본 10 복귀),
   `tools/.test_credentials` 제거.
3. `signup_approval` **ON 유지** 확인(현재 ON) — SMTP 개방 전까지 승인제가 유일한 가입 통제.
4. server.js로 서빙 유지 — **nginx로 바꾸면 게이트 소멸**(auth_request로 재현 전에는 금지).
5. `REQUIRE_LOGIN` env가 어디에도 "0"으로 남아있지 않은지 확인(fail-closed 확인).
6. `verify-secure.mjs` 37/37 재실행 + 외부망에서 실제 익명 접근 스팟체크.
7. ~~실패 로그인 로깅~~ → **완료**(§2-11, 2026-07-16). 공개 후 `grep SECURITY ~/.pm2/logs/kei-rag-api-dev-error-*.log`로 공격 시도 모니터링.
