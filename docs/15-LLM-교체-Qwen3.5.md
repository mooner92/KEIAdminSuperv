## 1. 배경 — 왜 교체를 검토했나

- 기존 Qwen2.5-14B-Instruct(Q4)는 한국어 RAG에 무난했지만, 후속 세대(Qwen3, Qwen3.5)가
  지시이행·추론에서 크게 개선되었고, 특히 **금액·기한 등 수치 응답의 정확성**이 서비스 신뢰의
  핵심 과제였다(⛔ 절대 규칙 1: 규정 수치를 지어내면 안 됨).
- 2026-07-03 Qwen3-14B로 1차 교체 후, 같은 날 Qwen3.5 세대 존재를 확인(HF 실측)하고
  후보 평가를 진행, 07-04 Qwen3.5-9B로 2차 교체.

## 2. 평가 방법론 (재현 가능)

측정 스크립트·데이터는 `eval/reports/qwen3-audit-0703/`(gitignore — 규정 파생 텍스트라 커밋 금지).

### 2.1 대규모 정확도 감사 (기준선, N=487)
- **질문 생성**: 색인된 실제 청크(Chroma 메타데이터 = 근거 정답)에서 LLM이 규정명·조 번호를
  숨긴 자연 질문을 역생성 → 각 질문의 정답 출처가 확정됨.
- **층화 표본**: 놓치기 쉬운 층 가중 — 별표 16% · 규정(수치포함) 30% · 규정(일반) 20% ·
  가이드 18% · ERP 8% · 용어 6%. 보일러플레이트(변환 경고·TODO placeholder) 청크는 제외.
- **채점**: ⓐ 검색 회수(strict=규정명+조 / relaxed=규정명, top-5) ⓑ **값 정확도**(정답 청크의
  핵심 수치가 답변에 실제 등장하는지) ⓒ 출처 인용·면책·거부 → PASS/PARTIAL/MISS/REFUSED 판정.
- 실행: `audit.py --n 500 --port 9000` (프로덕션 리랭커 경로 그대로).

### 2.2 동일근거 A/B (N=25, 값 문항 중심)
- 같은 질문에 **검색(retrieve)을 1회만 수행**해 두 모델에 동일한 [근거]를 주입 → 순수 생성모델 차이만 비교.
- A = Qwen3-14B(CUDA, 공유 Ollama) / B = Qwen3.5-9B(Vulkan, 격리 Ollama). 지연은 서빙 경로가
  달라 비교 무의미 — **품질(값 정확도)만** 본다.

## 3. 결과

### 3.1 Qwen3-14B 기준선 (N=487)
| 지표 | 값 |
|---|---|
| 종합 PASS | 78.0% |
| 검색 Hit@5 (strict) | 95.3% (@1 79.5%) |
| 면책 문구 | 100% (결정적 보장) · think 유출 0건 |
| 출처 표기 | 95.7% |
| **값 정확도(수치 문항 225개)** | **평균 55.8%** · 전량누락 69건 ⚠ |

- 버킷별 약점이 뚜렷: 별표 PASS 72.5%, 규정_수치 71.1%, 가이드 66.3% (용어 100%, 규정_일반 92.9%).
- 값 전량누락 표본 정밀검토 → 절반은 측정 노이즈(연도 표기 등), 절반은 **실제 누락**
  (별표 금액을 "기준에 따라 지급"으로 뭉뚱그리고 실제 수치 생략).

### 3.2 A/B: Qwen3-14B vs Qwen3.5-9B (동일근거 25문항)
| 채점 | A(Qwen3-14B) | B(Qwen3.5-9B) |
|---|---:|---:|
| 1차(공백 민감 정확일치) | 승 7 | 승 2 |
| **공정 재채점(공백 무시)** | 승 1 | **승 6** (무승부 18) |
| **평균 값 일치율** | 40.8% | **57.3%** |

**채점 함정(중요 교훈)**: 1차 채점에선 A가 우세해 보였으나, B의 오답 다수가 실은
**정답인데 토큰 공백**(`제 11 조`, `2 년`) 때문에 정확일치가 실패한 것. 공백 무시로
재채점하자 결과가 역전됐다. → 자동 채점기는 표기 변형에 강건해야 한다.

### 3.3 교체 결정 근거 (정리)
1. **값 정확도 우위**: 57.3% vs 40.8% — 이 서비스의 1순위 리스크(수치 오답)에서 더 나음.
2. **경량**: Q4 기준 ~5.7GB(vs 14B ~9GB) + 컨텍스트 8K 제한 시 총 ~6.4GB → GPU 1장에 여유,
   공유 GPU(동료 모델과 자리 경쟁) 환경에서 상주 안정성↑.
3. **세대 이점**: 네이티브 262K 컨텍스트(RAG 확장 여지), apache-2.0.
4. **공통 한계 확인**: 무승부 18건 대부분이 **양쪽 다 실패** — 값 정확도의 잔여 병목은
   모델이 아니라 **콘텐츠·검색**(별표 미회수)이다. → 후속 과제는 별표 레시피 노트(§8).

## 9. Qwythos-9B A/B 기각 (2026-07-24 — 사용자 요청 실측)

커뮤니티 화제 모델 `empero-ai/Qwythos-9B-Claude-Mythos-5-1M`(Qwen3.5-9B 기반·uncensored·
Claude 트레이스 증류·1M ctx·추론 CoT)을 현행 Qwen3.5-9B와 A/B — **같은 검색·프롬프트·리랭커**,
프로세스 env `LLM_MODEL`만 스왑(`eval/ab_model_test.py`, 골든 100문+거부형 12문, 채점자 LLM 양쪽 동일).
두 모델 GPU 동시 상주(Q4 각 ~6GB, 스왑 오버헤드 없음).

| 지표 | Qwen3.5-9B(현행) | Qwythos-9B | 판정 |
|---|---|---|---|
| 골든 100문 정답(1심 strict) | **25** | 22 | 현행 승 |
| 오답 | **27** | 33 | 현행 승 |
| 골든 토큰 보존 | **79%** | 50% | 현행 승 |
| 과잉거부 | **8** | 10 | 현행 승 |
| 거부형 12문 거부 | **12/12** | 11/12 ⛔ | 현행 승 |
| 지연 중앙값 / p90 | **13.2s / 15.2s** | 26.7s / 53.6s | 현행 승(2~3.5×) |

**기각 근거**: 전 지표 열세 + ⛔절대규칙4 리스크 실증 — 코퍼스 밖 질문("사내 주차장 배정")에
공용차량 지침을 억지 결합하고 **존재하지 않는 ERP 절차("총무관리 메뉴에서 차량 배정 신청")를 생성**.
uncensored 후학습이 거부 게이트를 약화시킨다는 사전 우려가 1건이지만 정확히 재현됨.
홍보 벤치(+34 MMLU)는 영어 범용 지표로 우리 한국어 규정 RAG에 전이되지 않음도 확인.
교훈: **벤치 화제성 ≠ 도메인 성능 — 교체 검토는 반드시 이 A/B 하네스로**(재사용:
`LLM_MODEL=<후보> python eval/ab_model_test.py --tag <이름>` → `--grade`).
