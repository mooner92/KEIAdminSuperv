> 발단: 사용자가 x.ai Grok 4.5 발표 페이지(https://x.ai/news/grok-4-5)의 디자인을 보고
> ① 섹션별 명확한 구분 ② 우측 스크롤 레일(스크롤 위치에 따라 각 섹션 제목이 나타나는 내비게이션)을

> 예쁜 소개 페이지가 있으면 좋겠다."

> 이 문서는 초안을 4관점(신입 UX·보안/데이터·기술 실현성·브랜딩) 적대 비평 워크플로에 돌려
> 확정된 major 결함 전건을 반영한 **개정판**이다.

## 0. 아이디어 평가 (정직하게)

### 강점 — 이건 '예쁘게'가 아니라 온보딩 문제를 푼다
- **타깃과 정확히 맞는다.** 이 서비스의 사용자는 행정이 낯선 신입·전입자다. 그들이 처음 만나는
  화면이 로그인 폼 하나라면 "이게 뭘 해주는 거지?"를 아무도 답해주지 않는다. 스크롤 내러티브
  소개 페이지는 첫 3분의 온보딩(무엇을 묻고, 근거가 어떻게 달리고, 어디를 둘러보는지)을 대신한다.
- **보고·확산 자산이 된다.** 운영진 보고, 타 부서 소개 때 소개 페이지 하나가 PDF 열 장보다 낫다.
- **개명 비용이 낮다.** 브랜드명이 `web/lib/site.ts`의 `SITE_NAME` 단일 출처(14개 파일 참조).
  단, 하드코딩 소탕 목록은 §4 P1에 grep 전수 기준으로 명시(Login.tsx의 "KEI 행정 LLM",
  Layout.tsx footer, server.js·ecosystem 로그 문자열 포함).

### 리스크 — 그리고 각각의 대응 (비평 확정 사항 반영)
| 리스크 | 대응 |
|---|---|

| 데모 영상·스크린샷에 **실제 규정 내용**이 찍힘 | ⛔ 커밋 금지 + **3단 폴백**(§5) — 최종단은 규정 텍스트 0인 커밋 가능한 목업. `git add -f` 금지 |

| 애플식 스크롤 스크럽은 무겁고 유지보수 비쌈 | 뷰포트 진입 시 자동재생으로 체감 90%를 10% 비용에. 스크럽은 P4 스트레치 |
| 로그인 UX 변경 | 기능 플래그 `landing_page`(off=기존 Login 폼) + FLAG_REGISTRY·FLAG_DEFAULTS 동기 |
| 비로그인 노출 확대 | 사이트는 CF ZT 뒤지만 **prod·dev 모두 0.0.0.0 바인딩(실측)** — LAN 직결은 ZT를 우회하고, 정적 자산은 플래그·로그인과 무관하게 서빙된다. 인그레스 검증(§6④) 전에는 실규정 영상을 `web/public/`에 배치하지 않는다 |

### 개선(원안 대비 확정한 변경)
1. **영상은 '스크롤하면 재생'이 아니라 '보이면 재생' + 접근성 필수 요건.** IntersectionObserver
   자동재생(음소거·루프)이되, ⓐ `prefers-reduced-motion: reduce`면 자동재생 금지(포스터+▶버튼)
   ⓑ 항상 보이는 일시정지/재생 토글(WCAG 2.2.2) ⓒ 내용 설명 figcaption. 스크럽은 P4.
2. **랜딩의 1차 주소는 SSG 정적 페이지 `/about`.** 비로그인 `/` 게이트에 랜딩을 끼우면
   me()+flags() 왕복 뒤에야 CSR로 떠서 첫 페인트가 스피너다(실측 구조). `/about`은 즉시
   페인트되는 진짜 "애플 느낌"이 가능하고 보고·시연·전파 URL로도 적합. 비로그인 `/`는 같은
   컴포넌트를 재사용해 랜딩을 보여주되(flag on일 때), **flags settle 대기**로 Login 플래시를
   막는다(§4 P2). `/about`도 flag off면 "준비 중" 렌더(정적 export라 파일은 항상 존재).
3. **스크롤 레일은 재사용 컴포넌트 `ScrollRail`.** 위치는 offsetTop이 아니라
   `getBoundingClientRect().top + scrollY`(offsetParent 함정 회피) + body ResizeObserver 재계산
   (배너·웹폰트·미디어 로드로 문서 높이가 변함 — 실측된 변동 요인). 라벨은 `<button>`
   (키보드 Enter 동작), 활성 섹션 `aria-current`, 라벨 간 최소 간격 클램프, `nav` 랜드마크.
   각 섹션 `scroll-margin-top: var(--header-h)`(sticky 헤더 가림 방지). ≤880px 숨김.
   scrollRoot 주입 prop을 처음부터 설계(P4에서 fill 레이아웃 화면 재사용 대비).
4. **다크 고정이 아니라 토큰 분기.** 히어로만 다크 계열 그라디언트(양 테마 공용), 본문은
   시맨틱 토큰. 기존 `[data-theme]` 규약 위반 없음.
5. **기존 사용자 보호.** 세션 만료자가 `/`에서 랜딩을 만나도: ① 랜딩 상단 고정 헤더에 상시
   '로그인' 버튼 ② 로그인 성공 이력(localStorage 마커) 있으면 컴팩트 변형(로그인 카드 우선)
   ③ 히어로 CTA는 로그인 폼으로 스크롤+**포커스 이동** ④ 최상단 skip-to-login 링크.

원칙(비평으로 ⓪ 추가): **⓪ 기능 전달 — 태그라인 없이 1초 내 용도 추측 가능**
① 타깃(행정이 낯선 신입·전입자)에게 말 걸기 ② 공공기관 사내 서비스 톤 ③ 짧고 GNB에 어울림

## 3. 정보 구조 — 소개 페이지 섹션 구성(안)

`/about`(SSG, 1차 주소) = 비로그인 `/`(flag `landing_page` on) 공용 컴포넌트:

1. **히어로** — 로고 + "규정을 근거로 답하는 KEI 행정 가이드" + [시작하기] CTA(로그인 폼으로
   스크롤+포커스 이동). 다크 그라디언트. 상단 고정 헤더에 상시 '로그인' 버튼.
2. **"이렇게 물어보세요"** — 배속 데모 영상(§5) + **예시 질문 칩 3~5개**(읽을 수 있는 텍스트,
   예: "출장비 정산 어떻게 하나요?" — 클릭 시 로그인 후 첫 질문 프리필로 이어지면 가점).
3. **"모든 답에 근거가 달립니다"** — 근거 패널·문서 드로어 데모 + 규정집 기준일 고지 +
   **"규정에 없으면 '확인되지 않는다'고 답합니다"** — 거부 답변 실동작 시연을 1급 요소로
   (가드레일이 이 프로젝트의 가장 강한 신뢰 자산이다).
4. **"둘러보고, 연결해서 보세요"** — 둘러보기·관계 그래프·서식 찾기 3열 카드.
5. **"믿을 수 있게 운영합니다"** — **사용자 언어 수치만**: 규정 원문 N건·업무 가이드 N건·
   규정집 기준일·검수완료 N건(양수 프레임). 전부 **빌드타임에 볼트에서 계산**. ⛔ Hit@1·청크 수
   등 개발자 지표 금지(신입에게 외계어 + "17%는 틀림"으로 역해석됨), ⛔ 측정 소스 없는 지표
   (예: '출처 표기율' — 측정 파이프라인이 생기기 전엔 카드 금지). 면책·내부 전용 고지.
6. **시작하기** — Login 컴포넌트 재사용(`embedded` prop: autoFocus 제거 — 없으면 로드 즉시
   최하단으로 점프해 내러티브 무력화, onAuthed 배선) + **가입 3단계 스텝퍼**(① KEI 이메일 가입
   → ② 메일 6자리 코드 입력 → ③ 바로 질문. "메일이 안 오면 관리자 문의" 한 줄).

우측 `ScrollRail`(6개 라벨). 로그인 상태에선 footer '소개'로 `/about` 재방문.
