# 32. 업데이트 노트("새로워진 점") + 최신 업데이트 배너 — 구현 완료(2026-07-14)

> 사용자 발제(2026-07-13): 데모 배너 자리에 **가장 최신 업데이트를 한 줄로**, 업데이트마다
> 제목·설명·사용법을 md로 쌓아 사이트에 '패치노트'류 페이지로 노출. v1 배포 후
> **"계속 개발되고 있다"는 신호**가 목적. 민감 내용은 공개 GitHub에 올라가지 않게.
> 이 문서는 순화된 설계 스펙(공개 레포용) — 노트 '본문'은 비공개 볼트에만 둔다.

## 1. 왜 / 무엇

- v1 이후 개선이 사용자 눈에 보이지 않으면 도구는 "멈춘 것"으로 인식된다. 각 기능 출시를
  **사용자 언어의 짧은 노트**로 남기고, 첫 화면 상단 배너가 최신 1건을 알린다.
- 이름 후보: **"새로워진 점"(추천)** / "업데이트 소식" / "패치노트". 행정 도구 톤에는
  개발 용어(패치)보다 "새로워진 점"이 맞다고 판단 — 최종 선택은 사용자.

## 2. 콘텐츠 모델 — 노트는 볼트에(공개 레포 밖)

- 위치: 볼트 `90_관리/_changelog/YYYY-MM-DD-슬러그.md` (RAG 코퍼스 아님 — 색인 제외 처리).
  볼트는 git 밖(Syncthing/사설 아카이브)이므로 **공개 GitHub에 절대 올라가지 않는다**.
- 프론트매터:
  ```yaml
  type: changelog
  제목: 업무 한 장(스윔레인) 공개
  날짜: 2026-07-12
  분류: 신규   # 신규 | 개선 | 수정 | 데이터
  요약: 국내출장·연차 등 절차 전체를 한 장의 지도로 — 상단 메뉴 '업무 한 장'   # 배너용 한 줄
  관련플래그: journey_map   # 선택
  관련페이지: /journey/     # 선택 — 배너/카드 클릭 이동
  ```
- 본문(2~6줄): **무엇이 바뀌었나 → 어떻게 쓰나 → 참고**. 스크린샷 없이 글로.
- ⛔ 작성 규약: 규정 값(금액·기한)·내부 인프라 정보(서버·포트·경로) 금지 — 사용자용 문구만.
  린트가 기계 검사(§5).

## 3. 노출 3면

1. **상단 배너**(신규 flag `changelog`): 최신 노트 1건의 `요약`을 한 줄로 —
   `🆕 새로워진 점: {요약} · 자세히 →` 클릭 시 노트 페이지. **X 닫기** 시 해당 노트 id를
   localStorage에 저장 → 같은 노트는 재노출 안 함, **새 노트가 나오면 다시 노출**.
   기존 `demo_banner`(예시용)는 이 배너로 대체하고 레지스트리에서 제거(flag debt 정리).
2. **/changelog 페이지**: 최신순 카드 목록(제목·날짜·분류 칩·본문), 분류 필터.
   기존 도움말 허브 톤과 동일한 스타일.
3. **푸터 링크 1개** + 도움말 허브 목차에서 링크.

## 4. 파이프라인·운영 플로우

- `web/lib/vault.ts`에 `loadChangelog()` — 빌드타임 정적 수집(볼트 변경=재빌드는 기존 운영과 동일).
  최신 1건은 Layout 배너로, 전체는 /changelog로.
- 02 청커·01o/01s/01t 스캐너는 `type: changelog` 스킵(코퍼스·감사 오염 방지).
- **기능 출시 절차에 1단계 추가**: 구현 → 검증 → 플래그 on → **노트 작성** → 재빌드.
  보조 도구 `tools/changelog_new.py`(프론트매터 템플릿 생성) 선택 구현.
- 초기 백필: v1 이후 개발분을 사용자 언어로 6~8건(결재선 판정기·업무 한 장·후속 질문·
  표 복원·최신값 단일화·도움말 개편 등) 등록하고 시작.

## 5. 검증(수용 기준)

ⓐ 노트 린트 — 필수 프론트매터·규정 값 패턴(원 단위 금액·N일 이내)·인프라 문자열 0건
ⓑ 배너: 최신 노트 노출 → X 닫기 → 재방문 시 미노출 → **새 노트 추가 시 재노출**(실렌더)
ⓒ /changelog 목록·필터·다크모드 실측 ⓓ flag off 시 배너·페이지·푸터 링크 전부 미노출
ⓔ RAG 검색에 changelog 텍스트 미유입(인덱스 스캔).
