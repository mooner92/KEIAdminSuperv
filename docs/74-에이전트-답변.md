# docs/74 — 에이전트 답변 경로 (oh-my-pi 하네스 + 로컬 Qwen)

> 2026-10-06 운영자 지시: "품질게시판 퀄리티 보강좀 하자. qwen 답변을 qwen을 그냥 호출하지 말고,
> oh my pi를 설치해서 여기에 qwen을 연결하고 이거로 답변 받아서 돌려줘봐. 지금 에이전트 없이 그냥
> qwen 쓰니까 RAG를 참조해도 퀄리티가 너무 낮아."

## 0. 한 줄 요약
단발 RAG(검색 1회 → 생성 1회) 대신, **oh-my-pi(omp) 에이전트 하네스** 위에서 같은 Qwen3.5-9B가
**읽기 전용 규정 도구 3종**(검색·조문 열람·목차)으로 근거를 보충한 뒤 답하는 경로를 dev에 추가했다.
요청 `model="kei-agent"`일 때만 동작하고, 기본 채팅·prod는 불변이다.

## 1. 구성

```
[질문] ─▶ 04_rag_api /v1/chat/completions (model=kei-agent)
            │ ① 1차 근거 시드 = rag_core.retrieve(condense_query(q))   ← 서비스와 동일(기준선 이상 보장)
            │ ② 인용 힌트 = 시드 규정 블록이 인용했지만 빠진 조·별표(결정적)
            ▼
        agent_core.run_agent ──spawn──▶ bun tools/agent/kei_agent.ts (omp SDK, in-memory 세션)
                                          │ 모델: kei-qwen35-agent (같은 GGUF, num_ctx 32K)
                                          │       @ 전용 Ollama 127.0.0.1:11438 (GPU1)
                                          │ 턴1 [점검] 항목별 근거 유무 → 빈 곳만 도구 호출
                                          │ 턴2 [최종 답변] 서비스 SYSTEM 규칙 그대로
                                          ▼  도구 = POST /v1/agent/{search,article,toc} (토큰 인증)
            ◀── {answer, evidence[], toolCalls[], checkNote}
            │ ③ 후처리 = 서비스와 동일(_postprocess·집계 단서·면책·수치/귀속/주제 게이트)
            │    + 근거 밖 URL 제거 — 판정 근거는 **에이전트가 실제로 읽은 것**
            ▼
        응답(x_sources·x_gates·x_agent) — 실패면 단발 경로로 강등(x_agent.fallback)
```

| 파일 | 역할 |
|---|---|
| `tools/agent/kei_agent.ts` | omp `createAgentSession` 러너. 기본 도구·MCP·LSP·스킬·확장 전부 off, 커스텀 도구 3종만 |
| `tools/agent_core.py` | 도구 백엔드·시드·힌트·프롬프트·후처리·강등 |
| `tools/04_rag_api.py` | `model=kei-agent` 분기 + `/v1/agent/*` 도구 엔드포인트(프로세스 토큰 인증) |
| `deploy/ecosystem.agent-ollama.config.js` | 에이전트 전용 Ollama(11438) |
| `eval/agent_ab.py` | 같은 문항·같은 채점기로 단발 vs 에이전트 A/B(게시판·질문은행 무접촉) |
| `tools/test_agent_core.py` · `tools/agent/verify_egress.sh` | 회귀(가드레일·근거0 거부·힌트·링크) · 외부망 0 |

## 2. 불변식 (⛔)
1. **가드레일 불변**(절대 규칙 4) — 에이전트 system = 도구 절차(추가) + `rag_core.SYSTEM`(그대로).
2. **근거 0건 답변 거부**(절대 규칙 1) — 시드·도구 근거가 하나도 없으면 답을 버리고 단발로 강등.
3. **외부망 0**(절대 규칙 5) — omp 카탈로그 갱신 `refresh("offline")` + 하위 프로세스 프록시를 죽은
   주소로(루프백만 예외). `verify_egress.sh`가 strace로 루프백 외 connect 0을 확인.
4. **서비스 러너 무접촉** — 에이전트 모델은 별도 Ollama 인스턴스. 같은 인스턴스에 올리면 서비스
   8K 러너가 축출된다(§3-③).
5. **기본 경로 불변** — `kei-admin-rag` 요청·채팅 UI·prod는 그대로. `RAG_AGENT=1`(dev)일 때만 분기.

## 7. 채팅 진행 표시 (flag `agent_chat`, 2026-10-07)
> 운영자: "좀 느려도 좋으니 정확도가 높은게 중요해" · "답변 나오는게, claude처럼, 생각중, ~~하는중 이러면서
> 변화를 좀 보여줘서 심리적으로 불편하지 않게"

- **러너 → 진행 이벤트**: `kei_agent.ts`가 단계마다 stdout에 NDJSON 한 줄(`{type:"progress", stage, tool?, args?, n?}`)을
  즉시 쓴다 — seed(1차 검색 N건) · check(근거 점검) · tool(검색어/열람 조문/목차) · answer(작성) · verify(검증).
  `agent_core._spawn`이 줄 단위로 읽어 `on_progress`로 넘기고, `progress_label()`이 한국어 한 줄로 바꾼다
  (예: "‘국내출장 숙박비’(으)로 규정을 더 찾는 중…", "여비규정 별표 2 원문을 읽는 중…"). 검색어·규정명은 길이 절단.
- **SSE**: `POST /app/chats/{id}/messages?stream=1` — 플래그 on + `RAG_AGENT=1`일 때만 `progress` 이벤트를
  meta 앞에 흘리고, 끝나면 **기존 프로토콜 그대로** meta → delta → done(완성 답을 조각 전송 — 기존 타자 UI 재사용).
  15초마다 SSE 주석(keep-alive)으로 유휴 절단 방지. 에이전트 실패면 "기본 방식으로 답변하는 중…" 후 같은 스트림에서 단발 경로.
- **저장 보장**: 진행 중 중단·이탈(제너레이터 종료)에도 작업 스레드가 끝까지 답을 만들어 **정확히 한 번** 저장
  (스트림/작업 중 늦은 쪽이 저장, 락) — 기존 Stop 안내("대화를 다시 열면 확인")와 같은 약속.
- **화면**: 답변 자리에 단계 목록 — 지난 단계 ✓(성공색) · 지금 단계 점멸(또는 사고 구슬). 첫 글자가 오면 답으로 교체.
  `aria-live="polite"`, `prefers-reduced-motion`이면 점멸 정지, 색은 시맨틱 토큰(다크모드 자동).
- **플래그**: `agent_chat`(기본 off, /admin 토글). prod는 `RAG_AGENT` env가 없어 켜도 무동작.
- 회귀: `tools/test_agent_chat.py` 5종(순서·강등·이탈 저장 1회·플래그 off 불변·라벨).
