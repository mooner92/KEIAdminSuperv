# 25. 업무 한 장 (스윔레인 여정 뷰) — korea100 벤치마킹

> 실측 근거: 신입 페르소나가 "출장 처리" 지시 하나에 6턴 소요(전체 여정이 안 보여 되물음 루프),
> 서무의 반복 응대("다음 뭐예요/누구 결재예요"). 채팅(지금 단계)과 상보적인 **전체 여정 한 장**.
> korea100의 업무구조도(레인×단계 노드 모델)를 우리 데이터 자산(전결·기한·ERP·조문)으로 구현.

## 1. 데이터 (⛔ 절대 규칙 — 근거 없는 노드 금지)

- 위치: **볼트** `90_관리/_journeys/*.json` (규정 파생 콘텐츠 → 공개 레포 커밋 금지, Syncthing 동기화.
  빌드 타임에 web이 read-only 소비 — 기존 볼트 소비 패턴과 동일)
- 스키마: `{id, title, emoji, 요약, 검수상태, lanes[], stages[], nodes[], edges[][]}`
  - node = `{id, name, lane, stage, action, erp?{화면, 코드, 경로}, 기한?{text, 근거}, 전결?{사다리, 근거}, 근거[]{규정명, 조}}`
  - 모든 수치·기한·전결·메뉴코드는 **볼트 원문에서 대조한 것만** 기입(작성 시 대조 완료), `검수상태: 미검수`
    로 시작해 사람 검수. 자동 생성 없음(수작업 큐레이션 — 환각 위험 차단).
- 초기 3종: 국내출장(6노드) · 연차휴가(4노드) · 초과근무(4노드).

## 2. UI/UX 구조 (반응형 이중 레이아웃)

- 페이지 `/journey` + GNB '업무 한 장'(flag `journey_map`, release·off 배포).
- 상단: 업무 선택 칩(🧳 국내출장 …) + 요약(단계·기한·근거 수) + 미검수 배지 + 기준일.
- **데스크톱(≥900px) = 스윔레인**: 행=레인(신청자/결재권자/ERP 시스템), 열=단계(준비→신청→결재→…).
  노드 카드에 이름 + 칩(🖥 ERP코드 · ⏱ 기한 · ✍ 전결). 노드 간 흐름은 **SVG 오버레이 화살표**
  (노드 위치 실측 → edges 연결, 리사이즈 대응) — korea100과 동일 접근(mermaid/d3 미사용).
- **좁은 화면(<900px) = 세로 스텝퍼**: 단계별 그룹, 카드에 레인 배지 — 같은 데이터의 모바일 뷰.
- 노드 클릭 → **상세 패널**: action·기한 원문·전결 사다리·근거 조문 리스트(클릭 시 기존 DocDrawer로
  원문 열람 — titleToSlug 재사용). 하단 면책: "공식 전결·기한은 원문과 담당 부서 확인".
- 다크모드: 시맨틱 토큰(`--color-*`)만 사용(표 복원 탭 하드코딩 사고 재발 방지).

## 3. 수용 기준

ⓐ 3개 여정 데이터의 모든 근거가 볼트 원문과 일치(작성 시 grep 대조 기록) ⓑ 데스크톱 스윔레인
노드·화살표 렌더 + 노드 클릭 → 근거 → DocDrawer ⓒ 모바일 뷰포트에서 스텝퍼 전환 ⓓ 다크모드 대비
ⓔ 플래그 off 시 GNB·페이지 비노출 ⓕ Playwright 실렌더.

## 신선도 감시 (2026-08-03 신설, specs/13 T01)

여정은 **사람이 손으로** 만들기 때문에 규정이 개정·삭제되면 조용히 낡는다. 그 사실을 알
방법이 아예 없다는 것이 이 화면의 최대 약점이었다(틀린 안내는 없는 안내보다 나쁘다 —
⛔절대규칙 1의 확장: 지어낸 적 없는 말이 사실이 아니게 된 것도 잡아야 한다).

- 도구 `tools/01k2_journey_freshness.py`(결정적·LLM 0회, 01k 다음 실행) —
  노드 `근거`(규정명·조)를 `article_status.json`과 대조 → `tools/index/journey_freshness.json`
  · `삭제`(없는 조문을 안내 중) · `개정`(내용이 달라졌을 수 있음) · `미확인`(표기 오류 의심)
- 화면 `components/journey/FreshnessNote` — **지도 위**에 표시(낡았을 수 있다는 사실을 먼저
  보고 내용을 읽어야 한다). 플래그 `journey_freshness`(기본 off).
  톤은 심각도 비례: '개정'은 "달라졌을 수 있다"(단정 금지), 삭제·미확인만 재검토 요청.
- ⛔ 리포트·표시만 — 여정 수정은 사람이 원문을 보고 한다.
