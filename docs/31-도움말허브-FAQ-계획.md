# 31. 도움말 허브·FAQ 계획 (⛔ 초안, 미승인) + 도움말 UX 수정 기록

> 사용자 발제(2026-07-13): 사내 다른 서비스(Minesweeper — 채용 이해충돌 검토 도구)의
> 사용 안내·FAQ·사이트 소개·푸터를 참고하되 **"우리는 저렇게까지 자세히 안 해도 된다"**,
> **"스크롤이 갑자기 생기지 않게"**(FAQ 아코디언은 예외 인정). 이 문서는 그 적용 계획.

## 0. 이미 수정한 것 (계획 아님 — 2026-07-13 완료)

- **다크 가독성**: 도움말 등 무클래스 텍스트가 다크에서 안 보이던 버그 — 근본 원인은 TDS가
  런타임에 body 글자색을 라이트 값(rgb 33,37,41)으로 덮어쓰는 것(배경에서 이미 겪은 것과 동일).
  `globals.css`의 `html body` 오버라이드에 `color: var(--color-text)` 추가로 **전 페이지** 해결.
- **닫기 동선**: 도움말 상단 `‹ 뒤로` + 푸터 링크가 /help에서는 `✕ 도움말 닫기`로 바뀌어
  재클릭 시 이전 화면 복귀(토글). `verify-help.mjs` 8/8(다크/라이트 색 실측·토글·뒤로).

## 1. 벤치마킹 대상 분해 (Minesweeper) → 우리 번역

| Minesweeper | 그대로 가져올 것 | 우리 식으로 줄일 것 |
|---|---|---|
| 사용 안내(단계별 매뉴얼 + 원칙 배너) | 원칙 배너("자동 추출은 초안, 판단은 사람" ↔ 우리 "근거 없으면 답 안 함") | 단계 매뉴얼은 짧은 "잘 묻는 법" 섹션으로 축소 |
| FAQ(아코디언, 마지막 수정일) | 아코디언(기본 접힘 — 스크롤 통제), 하단 "해결 안 되면 문의" | 문항 수 8±2로 제한 |
| 사이트 소개(별도 페이지) | — | **안 만듦** — 현행 도움말 첫 섹션이 이미 수행 |
| 푸터(브랜드·문의·링크 3종·GitHub) | — | **현행 유지** + `FAQ` 링크 1개만 추가(과밀 방지) |

## 2. 구조 — 별도 페이지가 아니라 "도움말 허브" 한 페이지

```
/help  (한 페이지, 상단 앵커 목차)
 ├─ 이 도구는 무엇인가요?      ← 현행 유지(소개 = 사이트 소개 대체)
 ├─ 잘 묻는 법                ← 신규(간결 5~6줄: 규정 용어로, 한 번에 한 주제,
 │                              후속질문 칩·선택 질문·업무 한 장 활용)
 ├─ 한계 / 데이터와 개인정보    ← 현행 유지
 └─ 자주 묻는 질문(FAQ)        ← 신규 아코디언(기본 접힘)
```

- **스크롤 원칙(사용자 요구)**: 초기 로드에서 접힌 상태 기준으로 목차+섹션 제목이 한 화면에
  들어오게 유지. 아코디언 펼침 외에는 갑작스런 스크롤 생성 없음. 펼침 시 `scroll-margin`으로
  헤더에 가리지 않게. 별도 페이지 전환(사용안내/FAQ/소개 3분할)을 **안 하는 이유**도 이것 —
  이동·복귀 동선이 늘고 각 페이지가 짧아 낭비.
- 푸터: `도움말` 옆 `FAQ` 링크 1개 추가 → `/help#faq` 앵커로 바로 이동(같은 토글·닫기 동선 공유).

## 3. FAQ 문항 초안 (규정 값 없음 — 사용법·신뢰 원칙만, ⛔ 금액·기한 등 규정 내용 금지)

1. "규정에서 확인되지 않습니다"가 자꾸 떠요 → 근거 없으면 답 안 하는 설계. 규정 용어로 재질문 요령.
2. 답이 옛 규정 같아요 → 규정집 기준일(footer) 개념 + 취소선(~~옛값~~)의 의미 + 담당 부서 확인.
3. 답변의 금액을 그대로 써도 되나요 → "원문에서 수치 확인" 안내가 뜨는 이유, 근거 패널·문서 드로어 사용법.
4. 근거로 나온 표가 이상해요 → ⚠표 확인 배지의 의미, 원문 보기 경로.
5. 관리자가 제 대화를 볼 수 있나요 → 볼 수 없음 + k-익명 집계만(도움말 개인정보 섹션 링크).
6. 인증 메일이 안 와요 → (SMTP 개통 후) 재발송 60초·스팸함·관리자 문의. 개통 전엔 문항 숨김.
7. 비밀번호를 잊었어요 → 관리자 재설정 요청.
8. 답이 틀렸어요 → 👎 피드백이 검수 우선순위로 이어지는 흐름(자기개선 루프) 소개.

- 콘텐츠는 코드 내 정적 배열(빌드 포함). **데이터 기반 확장(2차)**: 운영 대시보드의 거부율
  상위·👎 상위 질문 유형을 보고 관리자가 문항을 추가 — FAQ가 실사용 문제를 따라가게.

## 4. 구현 계획·수용 기준

- 플래그 `help_hub`(release·off) — FAQ·잘 묻는 법·푸터 FAQ 링크를 게이트(도움말 자체는 상시).
- 수용: ⓐ 접힘 기본·초기 뷰포트 내 목차 ⓑ 아코디언 펼침/접힘·앵커 점프 실렌더 ⓒ 다크/라이트
  색 실측 ⓓ 푸터 FAQ→#faq 앵커 ⓔ 규정 값 0(스캔) ⓕ 기존 닫기 토글과 충돌 없음.
- 예상 규모: 프론트 전용(help.tsx + css), 백엔드 변경 없음.
