## 2. 구조 — 별도 페이지가 아니라 "도움말 허브" 한 페이지

```
/help  (한 페이지, 상단 앵커 목차)
 ├─ 이 도구는 무엇인가요?      ← 현행 유지(소개 = 사이트 소개 대체)
 ├─ 잘 묻는 법                ← 신규(간결 5~6줄: 규정 용어로, 한 번에 한 주제,
 │                              후속질문 칩·선택 질문·업무 한 장 활용)
 ├─ 한계 / 데이터와 개인정보    ← 현행 유지
 └─ 자주 묻는 질문(FAQ)        ← 신규 아코디언(기본 접힘)
```

- **스크롤 원칙(사용자 요구)**: 초기 로드에서 접힌 상태 기준으로 목차+섹션 제목이 한 화면에
  들어오게 유지. 아코디언 펼침 외에는 갑작스런 스크롤 생성 없음. 펼침 시 `scroll-margin`으로
  헤더에 가리지 않게. 별도 페이지 전환(사용안내/FAQ/소개 3분할)을 **안 하는 이유**도 이것 —
  이동·복귀 동선이 늘고 각 페이지가 짧아 낭비.
- 푸터: `도움말` 옆 `FAQ` 링크 1개 추가 → `/help#faq` 앵커로 바로 이동(같은 토글·닫기 동선 공유).

## 3. FAQ 문항 초안 (규정 값 없음 — 사용법·신뢰 원칙만, ⛔ 금액·기한 등 규정 내용 금지)

1. "규정에서 확인되지 않습니다"가 자꾸 떠요 → 근거 없으면 답 안 하는 설계. 규정 용어로 재질문 요령.
2. 답이 옛 규정 같아요 → 규정집 기준일(footer) 개념 + 취소선(~~옛값~~)의 의미 + 담당 부서 확인.
3. 답변의 금액을 그대로 써도 되나요 → "원문에서 수치 확인" 안내가 뜨는 이유, 근거 패널·문서 드로어 사용법.
4. 근거로 나온 표가 이상해요 → ⚠표 확인 배지의 의미, 원문 보기 경로.
5. 관리자가 제 대화를 볼 수 있나요 → 볼 수 없음 + k-익명 집계만(도움말 개인정보 섹션 링크).
6. 인증 메일이 안 와요 → (SMTP 개통 후) 재발송 60초·스팸함·관리자 문의. 개통 전엔 문항 숨김.
7. 비밀번호를 잊었어요 → 관리자 재설정 요청.
8. 답이 틀렸어요 → 👎 피드백이 검수 우선순위로 이어지는 흐름(자기개선 루프) 소개.

- 콘텐츠는 코드 내 정적 배열(빌드 포함). **데이터 기반 확장(2차)**: 운영 대시보드의 거부율
  상위·👎 상위 질문 유형을 보고 관리자가 문항을 추가 — FAQ가 실사용 문제를 따라가게.

## 4. 확정 스펙 (구현 기준)

### 4.1 페이지 구조 (`/help` — flag `help_hub` on 기준)
```
‹ 뒤로
h1 도움말
[앵커 목차 칩]  소개 · 잘 묻는 법 · 한계 · 개인정보 · FAQ    ← flag on일 때만
#intro   이 도구는 무엇인가요?        (현행 유지 — 사이트 소개 겸함)
#howto   잘 묻는 법                  (신규, 불릿 5~6개)
#limits  한계 — 꼭 알아두세요         (현행 유지)
#privacy 데이터와 개인정보            (현행 유지)
#faq     자주 묻는 질문              (신규, 네이티브 <details> 아코디언·기본 접힘)
#contact 문의                       (현행 유지)
```
- flag off = 현행 도움말 그대로(목차·잘 묻는 법·FAQ 미노출) — 안전 기본값.
- 섹션에 `scroll-margin-top`(고정 헤더 가림 방지). 아코디언은 네이티브 `<details>/<summary>`
  (접근성·무JS 동작). 초기 로드에 전부 접힘 → **갑작스런 스크롤 없음**(사용자 요구).
- 스타일은 `web/styles/Help.module.css` 신설 — 시맨틱 토큰(`--color-*`)만 사용(다크 호환).

### 4.2 FAQ 콘텐츠 (코드 내 정적 배열 — ⛔ 금액·기한 등 규정 값 금지, 사용법·원칙만)
§3의 8문항. `hidden` 속성 지원 — "인증 메일이 안 와요"는 SMTP 개통 전까지 `hidden: true`
(개통 시 속성만 제거). 각 문항은 질문(요), 답 2~4문장, 필요 시 내부 링크.

### 4.3 푸터
- flag on일 때 `도움말` 옆에 `FAQ` 링크 1개 추가 → `/help/#faq`. 기존 도움말 닫기 토글과
  독립(FAQ 링크는 항상 이동만). 그 외 푸터 불변.

### 4.4 수용 기준(전부 실렌더 판정)
ⓐ flag off: 현행과 동일(목차·FAQ 미노출) ⓑ flag on: 목차 앵커 점프 + 초기 접힘
ⓒ 아코디언 펼침/접힘 동작 ⓓ 다크/라이트 글자·배경 색 실측 ⓔ 푸터 FAQ → #faq 도달
ⓕ 페이지 텍스트에 규정 값 패턴(원 단위 금액·N일 이내) 0건 스캔 ⓖ 도움말 닫기 토글과 충돌 없음.

- 규모: 프론트 전용(help.tsx·Help.module.css·Layout 푸터) + FLAG_REGISTRY 1건. 재색인 불필요.
