## 1. 인프라 (이번에 구축)

  대용량 HTTP를 차단해 openjdk deb은 HTTPS 미러(kakao)로 수동 설치, JRE는 Adoptium tar.

- **`tools/01p_byeolji_pdf.py`**: 볼트 `원본파일` 프론트매터 ↔ rule_files HWP 정확 매핑 →
  HWP→PDF(캐시) → 별지 라벨 페이지 탐지 → ①별지별 분리 PDF(`web/public/forms-pdf/<규정>/…`,

  - **원문 서식명 = 페이지 최대 폰트 스팬**(제목) — 서식찾기 서식명의 정답 소스.

- 산출물 전부 git-external(.gitignore: forms-pdf/·byeolji_png/·.byeolji_cache/ — 내부 콘텐츠 커밋 금지).
- 다운로드 서빙: 정적 out/forms-pdf(빌드 시 public/ 복사) — **로그인 게이트 뒤**(docs/44 허용목록 밖).

## 6. 운영 연동 (같은 날 구현 — 사용자 지적 반영)
1. **재색인 연동**: `/app/corpus/reindex`가 02 전에 **01p를 증분 실행**(HWP mtime 캐시 +
   per-규정 manifest 재사용 — 무변경 시 ~8초). 규정 업데이트 → 재색인만 해도 별지 PDF·

2. **직결 서빙**: server.js가 `/forms-pdf/*`를 `web/public`에서 우선 서빙 — **웹 재빌드 없이**
   01p 산출물이 즉시 반영(out/은 빌드 시점 사본). 게이트 통과 후에만.
3. **⛔ 복원본 보호**: 01_hwp_to_md 재실행이 비전 복원 별지를 깨진 변환본으로 되돌리는 사고 방지 —
   `byeolji-restored` 마커가 있는 md는 건너뜀(강제는 `--overwrite-restored`).
4. **누락 별지 감지**: 01q가 manifest↔md 라벨 diff(`missing_in_md`) 리포트.

## 7. HWP 다운로드 (2026-07-16 — 사용자 요구 ①)
- 서식찾기에 **HWP↓ 컬럼** 추가: 별지를 실제 편집·작성할 수 있게 한글파일 제공.
- **별지만 HWP로 분리하는 것은 포맷상 불가**(HWP는 페이지 단위 추출 도구가 없고,
  변환 왕복 시 서식 깨짐) → **규정 원문 전체 HWP 사본**을 제공한다(01p가
  `forms-pdf/<규정>/`에 원본명 그대로 복사, manifest `hwp` 필드). 서식만 필요한
  사용자는 분리 PDF(인쇄·수기작성용), 편집이 필요한 사용자는 원문 HWP에서 해당
  별지 페이지를 열어 작성 — 관공서 실무 관행과 동일.
- 원본이 PDF뿐인 규정(비HWP 소스)은 HWP 컬럼 없음(manifest에 hwp 없음 → UI 미표시).

## 8. PDF 변환 페이지 팽창 보정 (2026-07-16 — 사용자 요구 ②)
문제: HWP→PDF 변환 시 페이지가 늘어나 **별지 라벨(제목) 페이지와 서식 본문이 분리**
(예: 개인정보보호지침 별지 제8호 — 1p 제목만, 2p 표).

원인(실측으로 확정):
1. HWP가 요청하는 서체(한양신명조·신명 신신명조·한컴바탕·KoPub바탕체 등)가 서버에
   없어 LO가 **Noto Sans CJK SC**(행높이 **1.44em**)로 폴백 → 38→44p 악화.
2. LO의 비율 줄간격 = 배율×**폰트 메트릭**(ascent+descent), HWP = 배율×**글자크기**.
   메트릭 1.15~1.44em이 그대로 곱해져 줄마다 15~44% 팽창 → 셀 줄바꿈이 설계
   행높이를 넘어 표가 다음 페이지로 통째로 밀림.
3. ⚠ fontconfig 매핑(binding="strong")은 **LO가 무시**(fc-match는 UnBatang인데
   변환은 Noto SC — 실측). 시도 흔적 남기지 말 것.

해결(01p `convert_pdf` — `BYEOLJI_FONT_FIX=1` 기본):
- **HWP→ODT→PDF 2단 변환**으로 바꾸고 ODT의 content/styles.xml을 직접 치환:
  ① 한글 서체명 전부 → 대체 서체(고딕 키워드 휴리스틱으로 명조/고딕 분기, 라틴 보존).
     대체 서체는 자동 선택(`_resolve_font_targets`): **함초롬(HCR Batang/Dotum) 설치 시
     1순위**(HWP 표준 서체 — 글꼴 모양까지 원문 동일, 2026-07-16 사용자 제공 TTF
     `~/.fonts` 설치) → 미설치면 나눔(1.15em) 폴백. env 강제 `BYEOLJI_FONT_SERIF/GOTHIC`.
  ② 비율 줄간격 ×(1/대체서체 단일행 메트릭) — LO 줄높이(배율×폰트메트릭)를 HWP
     산식(배율×글자크기)으로 환산. 함초롬 1.30em→**0.769** · 나눔 1.15em→0.87
     (`BYEOLJI_LH_FACTOR`로 강제 가능). A/B 실측(6540·3100 인사규정): 함초롬 vs 나눔
     페이지 수·라벨-단독 페이지 **동률** — 채택 근거는 레이아웃이 아니라 서체 충실도.
     ⚠ HY중고딕(1.0em)은 진품이나 메트릭이 달라 전역 계수와 충돌 — 치환 타깃으로
     미사용(설치만 유지). 향후 **한양신명조**(HY계열 세리프, 1.0em 추정) TTF를 구하면
     계수 1.0으로 원문 메트릭 완전 재현 가능(한컴 설치 PC의 Windows/Fonts에서 확보).
- 실측(6540 개인정보보호지침): **44p(Noto)→35p**, 별지 제1·2·3·4·6호가 라벨+표
  **1페이지 서식으로 병합**. 제5·7·8·9호는 본문만으로 페이지가 꽉 차는(표 7.8in+
  안내문) **원문 설계상의 경계 케이스**로 분리 유지 — 콘텐츠는 완전(라벨 페이지 포함).

### 8b. 근본 수정 3종 (2026-07-21 — 원본 HWP 확보 후 재실측)
사용자가 원본 규정집 HWP를 제공("원본은 별지당 정확히 1쪽")하여 위 '경계 케이스' 판단이
**틀렸음이 확정** — 남은 분리는 원문 설계가 아니라 변환 결함이었다. 실측으로 3개 원인 추가 확정:

1. **HWP '쪽 나눔' 미보존(핵심)** — ODT에 `fo:break-before="page"`가 **0개**(실측). 별지마다
   새 쪽에서 시작해야 하는데 흐름 레이아웃이 되어, 렌더 높이가 원본과 조금만 달라도 별지
   제목이 앞 쪽 꼬리에 붙고 표만 다음 쪽으로 밀렸다('제목만 페이지'의 진짜 원인).
   → `_rewrite_odt ③`: 단독 라벨 문단(`[별지 제N호…`, ≤40자)의 자동 스타일을 복제(BRKn)해
   break-before 주입 — 본문 속 인용은 오폭 안 함.
2. **US Letter 오변환** — H2Orestart ODT가 8.5×11in(Letter)로 떨어져 세로 가용높이가
   A4보다 **0.69in 짧았다**. 별지 5호 표(12행 합 7.86in)가 정확히 이만큼 못 들어감.
   → `_rewrite_odt ④`: Letter일 때만 A4(8.2677×11.6929in)로 치환.
3. **빈 꼬리 쪽** — 규정집이 본문에 박아둔 쪽번호 텍스트('6560-24' 등)가 쪽나눔 주입 후
   다음 쪽에 한 줄 잔여로 남아 1쪽 서식이 2쪽 범위로 잡힘.
   → 추출 범위 끝쪽부터 '텍스트 ≤40자·이미지 없음' 쪽 트림(표는 셀 텍스트가 있어 안전,
   머리글 밑줄 같은 장식 드로잉은 판정 제외).

결과(6540): 별지 10건 중 **9건이 원본과 동일한 1쪽**(제5호 유출신고서 = 라벨+제목+표+쪽번호
한 쪽 — 원본 한글 화면과 동일). 제8호만 2쪽 = 진짜 내용(작성 안내문 264자)으로 원본도 2쪽.
원본 HWP 소스 = `~/erps/규정집/`(scp 반입, git-external) — 재생성 시
`01p --src ~/erps/규정집,~/kei-uploads/originals --force`.
- 라벨 탐지 v2(보정 후 전수 검증에서 실측 보완 — md 실서식 라벨 손실 **0건** 달성):
  ① **줄 단위 우선**: 줄 시작 괄호+라벨 + '라벨·개정이력(〈신설/개정 …〉·[신설 …]·삭제)
     제거 후 잔여 ≤8자'만 인정 — 이력 꼬리 65자짜리 실라벨은 잡고, '…서식]에 따라'
     본문 인용은 거름. 폴백=상단 짧은 줄(≤28자) 연속 결합(여러 줄로 쪼개진 라벨).
  ② **한 페이지 다중 라벨**: 삭제 스텁 목록+실서식 동거 페이지 — 전부 수집하되
     **삭제 스텁 26건은 범위 경계로만** 쓰고 다운로드 항목 미생성(폐지 서식 미제공).
  ③ **심층 패스**: 별지가 새 페이지로 시작하지 않는 규정(라벨이 페이지 중·하단 —
     내부감사·연구윤리·직인관리 등 9건)을 전체 줄에서 수색, 라벨별 마지막 출현 채택
     (인용=조문(앞) vs 서식=문서 끝). 하단 라벨이면 서식명은 다음 페이지에서.
  ④ **별표 = 경계 전용**: 마지막 별지 범위가 뒤따르는 별표를 삼키는 버그 수정
