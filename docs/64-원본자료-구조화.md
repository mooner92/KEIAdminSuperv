# 64 — 원본 자료 구조화 (2026-07-29)

> ERP에서 내려받은 원본 자료(규정집·양식·가이드)를 **정본 분류 체계**로 재배치하고,
> 버전(개정 이력)을 manifest로 추적해 코퍼스 관리를 쉽게 한다.
> 도구=`tools/organize_sources.py`, 구조화 저장소=`~/kei-sources/`(⛔ repo 밖·내부자료).

---

## 1. 왜

기존에는 원본을 `rule_files/`에 **한 폴더에 몰아넣고** 있었다. 새 개정본이 오면
어느 규정의 어떤 버전인지, 구버전을 어떻게 보관할지 규칙이 없었다.

ERP `규정집구조.xlsx`가 **정본 분류 체계**를 담고 있다 — 8편(編) · 규정 104개,
각 규정에 규정번호·개정일·변경내역·담당자. 이걸 기준으로 원본을 재배치하면:

- 새 버전이 오면 **해당 규정 폴더에 넣고 구버전은 `구버전/`으로** — 갈아끼우기가 명확
- 정본 목록과 대조해 **누락·중복을 자동 발견**
- 코퍼스(볼트) 재생성 시 **어느 원본이 진실원천인지** 분명

## 2. 구조

```
~/kei-sources/
├── 규정집/
│   ├── 제3편_인사·복무/
│   │   └── 3110_직원신규채용규칙/
│   │       ├── 3110직원신규채용규칙240422.hwpx   ← 현행(본칙)
│   │       ├── 구버전/                          ← 이전 개정본
│   │       └── 하위기준/                         ← <채용> 운영요령 3종
│   └── ...제1~8편
├── 회계양식/ 연구양식/ 연구행정가이드/ 편철목록/ ...  ← 카테고리 보존
├── sources_manifest.json                         ← 버전·누락·미분류 기계 판독
└── 규정집_관리대장.md                             ← 사람 판독(자동 생성)
```

**정본 체계의 핵심**: `<태그>` 하위기준(예 `<채용> 연구원급 신규채용 운영 요령`)은
xlsx에서 **직전 규정번호에 소속**된다. 도구가 이 순서를 읽어 부모 규정 폴더의
`하위기준/`으로 배치한다.

## 3. 무결성 규약

⛔ **원본 `~/erps`는 절대 수정하지 않는다** — 복사만 한다(되돌리기 안전).
기본은 dry-run, `--apply`로만 실제 복사.

**파일 보존 검증**: 원본 파일 수 = 배치 파일 수. 2026-07-29 실측 규정집 112개 → 112개
(유실 0). 이 검증 중 **파일 유실 버그**를 잡았다 — `<위탁비>` 하위기준이 부모 규정
`7160`(제정안만 있어 누락)과 함께 배치에서 빠졌다. → 부모가 없어도 하위기준을
`NNNN_부모규정_파일없음/하위기준/`에 보존하고 manifest에 `고아_하위기준`으로 기록.

## 4. 실행

```bash
cd tools
.venv/bin/python organize_sources.py --src ~/erps --dest ~/kei-sources          # dry-run
.venv/bin/python organize_sources.py --src ~/erps --dest ~/kei-sources --apply  # 실제
```

매칭 3단: ① 규정번호(파일명 앞 4자리) ② 정본 핵심어 substring ③ 토큰 겹침.
관리대장·목차·`(안)` 초안은 규정 본칙에서 제외(사람 확인용 미분류로).

## 6. 관리대장 자동 생성

`~/kei-sources/규정집_관리대장.md` — 편별 규정 목록 + 버전 수 + 하위기준 수 + 누락/미분류.
`organize_sources.py` 재실행 시 갱신된다. 새 개정본을 넣고 도구를 돌리면 대장이 따라온다.

## 8. 양식·가이드 구조화 (2026-07-29)

규정집은 xlsx가 정본이지만, **양식·가이드는 ERP 화면 자체가 정본**이다.
`파일구조도/*.png`(화면 스크린샷)를 판독해 `tools/index/form_taxonomy.json`에 옮기고,
`tools/organize_forms.py`가 파일을 섹션에 배정한다.

| 대상 | 화면 | 정본 | 파일 | 배정 | 미분류 |
|---|---|---|---:|---:|---:|
| 회계양식 | 회계관리>회계관련양식조회 | 42건 | 68 | **68** | 0 |
| 연구양식 | 과제관리>연구관리양식 | 59건 | 73 | 69 | 4 |
| 연구행정가이드 | 전직원 연구행정 가이드 | 72건 | 65 | 63 | 2 |

**파일이 정본보다 많은 게 정상이다** — 한 항목에 국문/영문, 기본/일반×착수/중간/최종처럼
여러 실물이 붙는다(사용자가 지적한 "한 항목에 여러 문서"가 이것). 섹션 폴더가 그 묶음이 된다.

### 표기 별칭이 필요했다

파일명과 화면 항목명의 어휘가 어긋난다. 유사도만으로는 못 잡는 사례:

- `통합이지바로` ↔ `통합Ezbaro` (문자 겹침 0)
- `면접비지급정보` ↔ `면접비 지급을 위한 개인 지급 정보`
- `영수증양식` ↔ `영수증(현금수령 확인증)`

→ `ALIASES`에 실측 사례로 등록. 회계양식은 이 보정으로 미배정 13개 → **0개**가 됐다.

### 미분류 6개 — 부속파일

편집서체 zip 3개·별첨 zip·인디자인 작업파일·`(안)` 초안. 양식 실물이 아니라 부속물이라
`99_미분류/`에 둔다. 파일 보존은 검증했다(206개 → 206개, 유실 0).

## 9. 다음 — 코퍼스 반영 (미착수)

구조화는 **원본 저장소**를 정리한 것이다. 이걸 볼트(코퍼스)에 반영하는 것은 별도 단계이며,
**무엇을 넣을지 문서별 판단이 필요**하다:

- 볼트 `20_규정원문`에는 이미 규정 원문 112개가 kordoc 변환·별지 검수된 상태다.
  전체 재변환은 그 작업을 유실시키므로 **신규·개정분만** 반영한다.
- 회계양식·연구양식(빈 양식)은 **서식 찾기**(별지 PDF 파이프라인), 안내문은
  **가이드**(`10_업무가이드`)로 — 성격이 다르다(docs/50·34).
- ⚠ XLSX·DOCX는 현재 변환 파이프라인에 처리기가 없다(HWP/HWPX/PDF/PPTX만).
- ⛔ 실물 문서(통장사본·사업자등록증·결산보고서)는 계좌·재무 데이터가 있어
  RAG 색인 제외 대상이다.
