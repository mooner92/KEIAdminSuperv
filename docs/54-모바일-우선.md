# 54 — 모바일 전용 셸 (v2, flag `mobile_shell`)

> v1(반응형 강화만)에서 확장 — 사용자 지시(07-20): "모바일 전용으로 UI/UX 전체 설계.
> 하단바 간단하게. 유저는 LLM 사용이 ~90%, 나머지는 스키밍하고 한번 보는 정도.
> 부가기능은 전부 기타메뉴로. Expo 앱 대비 구조를 미리 잡는 과정."

## 구조 (한 코드베이스 · CSS 발동 · 데스크톱 무영향)
- **flag `mobile_shell`** (release 관례: off 배포 → dev 검증 → on). Layout이 로그인+플래그일 때
  루트에 `data-mshell`을 부여 — 모든 셸 규칙은 `≤640px ∧ [data-mshell]`에서만 발동.
- **하단 탭바** `components/mobile/MobileTabBar.tsx` — 💬질문(`/`) · 📚규정(`/browse`,`/d/`) ·
  ☰더보기(`/now` + 모든 부가 화면 prefix가 활성 매칭). 탭 정의는 데이터(`MOBILE_TABS`)로 분리
  → **Expo(React Navigation) 탭으로 1:1 매핑 가능**. safe-area(`env(safe-area-inset-bottom)`) 대응.
- **미니멀 헤더**: 로고 + 🔔(관리자) + 테마 토글만. 상단 GNB 내비 숨김(탭바 전담).
- **푸터 숨김** — 도움말·소개·관리자 링크는 ☰더보기 허브에 카드로 이전(데스크톱 허브에도 추가).
- **--m-tab-h** CSS 변수(58px+safe-area)로 본문·채팅이 탭바를 비켜남.

## 화면별
- **채팅(홈, ~90% 사용)**: 셸에서 `100dvh` 기반 뷰포트 꽉 참 — 스레드 flex 확장, 컴포저 항상
  탭바 위, 근거 FAB는 컴포저 위로. 면책 문구 유지(절대 규칙 3).
- **☰더보기(/now)**: 카드 그리드 → **콤팩트 목록 행**(아이콘·제목 좌 / 설명 우 2줄 클램프).
  스키밍→탭 결정에 최적화. 항목: 캘린더·서식·새로워진 점·그래프·결재선·업무 한 장·의견 보내기·
  도움말·소개(flag)·관리자(admin).
- **관리자(/admin)**: 모바일 진입 기본 탭=의견함(AI 자동 수정) — v1 유지.
- **나머지 부가 화면**: 기존 반응형 그대로(한번 보는 정도) — 탭바만 얹힘, 더보기 탭 활성 유지.
- **관계 그래프(무거운 페이지 간소화)**: 모바일 셸에선 캔버스(`react-force-graph`, 물리
  시뮬레이션 — 무겁고 터치 조작 난해) 대신 **리스트 간소 뷰**(`MobileGraphList`). 같은 graph
  데이터로 "문서 검색 → 연결(관련 규정) 펼침 → 이동". `useMobileShell()`로 분기해 **캔버스
  번들을 아예 로드하지 않음**(검증: force-graph 요청 0건). ⚠ 캔버스가 공유 pageProps의
  link.source/target를 노드 객체로 변형할 수 있어 id 정규화(sid)로 방어.

## Expo 이관 시나리오
1단계: 이 반응형 URL을 WebView 래핑(즉시 앱화 — 탭바·safe-area 이미 대응).
2단계: `MOBILE_TABS` 데이터 → React Navigation 탭, 화면별 컴포넌트 이식(공용 로직은 lib/).
