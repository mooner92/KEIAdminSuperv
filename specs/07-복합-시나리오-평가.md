# Spec 07 — 복합 시나리오 평가 + 신규 데이터 축 편입 + 이력 상세 보기

> 2026-07-26 · 사용자 지적 3건:
> ① "매일 비슷한 질문이 나오고 변화가 없다 — 한 문서가 아닌 **복합적·구체적** 질문을 하게 하자"
>   (예: "연구위원인데 세종→런던 3박5일 세미나 — 항공사 제한? 항공비 상한? 숙소비? 귀국시간? 정산?")
> ② "**새 기능(특히 데이터)이 추가되면 그걸 질문에 활용하는 과정**이 필요하다"
> ③ "전체 자가평가 이력에서 **날짜별 테스트 내역**을 볼 수 있게 — 새 탭? 더 편한 방법?"
> 선행: docs/58(자가평가) · specs/05·06(신규 데이터 축)

## 0. 현 상태 실측 (2026-07-26, 은행 200문항)

| 지표 | 실측 | 함의 |
|---|---|---|
| 출처 문서 수 | **전부 단일 청크** | 구조적 단일문서 편향 |
| 페르소나·상황 문항 | **0건** | 실제 사용자의 물음 형태와 괴리 |
| 질문 길이 중앙값 | 41자 | 짧은 단문 위주 |
| 말미 패턴 | "…무엇인가?/해야 하는가?" 반복 | 정형성 → 체감상 "매일 비슷" |
| 멀티턴 문항 | 0건(전부 단발) | 멀티턴 회귀가 평가에 없음 |

**원인은 프롬프트가 아니라 구조**다: `daily_gen.gen_one()`이 **청크 1개**를 주고 "그 원문만으로 답할 수
있는 질문"을 요구한다(docs/58 §1.1). 채점 근거를 단일 청크로 고정하려는 설계였고, 그 대가로
복합 질문이 원천 차단됐다.

## 1. A트랙 — 복합 시나리오 문항

### 1-1. 골격 = 이미 있는 자산
- **여정 13종**(`90_관리/_journeys/*.json`) — 노드·근거가 이미 구조화됨.
  실측: 해외출장 7노드·11근거 / 물품구매 6노드·13근거 / 휴직·복직 6노드·13근거 …
  ⟹ 사용자 예시("세종→런던 세미나")가 **해외출장 여정 그대로**다.
- 보조 축: `deadlines`(정산 기한) · `approval`/`amount_rules`(결재·금액) · 별표(등급·상한) ·
  `ACTION_FLOWS`(신청→정산 후속).

### 1-2. 생성 절차 (`eval/daily_gen.py` 확장 — `gen_scenario()`)
```
① 여정 1개 선택(라운드로빈: 최근 출제 적은 여정 우선)
② 그 여정의 근거 조문 2~4개를 청크로 회수(= 다중 골든의 원천)
③ 페르소나·상황 변수 샘플 — ⛔ **근거에 실존하는 값 집합에서만**
   · 직급: approval의 대상 축(부원장/부서장/실·팀장/연구직…)
   · 지역·등급: 여비규정 별표의 지역 구분에 있는 값만
   · 기간·금액: 근거 원문에 나오는 범위 안에서만
④ LLM에 [근거 N개 + 페르소나 + 상황]을 주고 요구:
   {"질문": "<상황이 담긴 실무 질문 1문장>", "골든": ["<근거1 원문 문장>", "<근거2 원문 문장>", …]}
⑤ 게이트(기존 + 추가): 골든 문장이 **각 근거 원문에 실존**해야 채택 ·
   상황 변수가 근거에 없는 값이면 폐기(창작 차단) · 골든 2개 미만이면 단일 문항으로 강등
```

### 1-3. 멀티턴 체인(같은 시나리오의 후속 질문)
`턴[]` 배열로 2~3턴 저장: `["항공 운임 상한은?", "그럼 정산은 언제까지?", "숙박비는 어디까지?"]`.
채점은 턴별 골든 대조 + **맥락 유지**(2턴에서 주제가 바뀌면 실패 — `condense_query` 회귀를 평가에 편입).

### 1-4. 은행 스키마 확장(하위호환)
```jsonc
{ "형식": "복합",                       // 없으면 "단일"(기존 문항 그대로 동작)
  "시나리오": {"여정": "해외출장", "페르소나": {"직급": "연구위원"}, "변수": {"지역": "…", "기간": "3박5일"}},
  "출처": [ {규정명, 조, 청크id}, … ],   // 복수(단일 문항은 기존 dict 유지 — 로더가 양쪽 수용)
  "골든": ["…", "…"],                   // 복수
  "턴": ["…", "…"] }                     // 멀티턴일 때만
```
채점(`daily_grade`): 복합은 **골든별 개별 판정 → 전부 충족=정답 · 일부=부분 · 핵심 누락=오답**.
`refusal_detect`·수치 대조 등 기존 3단 판정은 그대로 재사용.

### 1-5. 쿼터
신규 40문항 = **복합 10(25%)** + 단일 30. 단일을 유지하는 이유는 **청크 커버리지 순환**(코퍼스
전체를 도는 원래 목적)이 복합만으로는 달성되지 않기 때문. 복합은 여정 13종 라운드로빈.

## 2. B트랙 — 신규 데이터 축 자동 편입 (사용자 지적 ②)

**문제**: specs/05·06으로 개정영향·금액판정 데이터가 생겼는데 **평가 문항은 옛 축만** 본다.
기능이 늘 때마다 사람이 문항을 손으로 추가하는 건 지속 불가능.

**설계 — 평가 축 레지스트리(`eval/axes.py`)**: 축마다 `(인덱스 파일, 샘플러, 정답 산출, 최소 쿼터)`.
| 축 | 소스 | 문항 예 | 정답 산출 | 특징 |
|---|---|---|---|---|
| `amount` | `amount_rules.json` | "○○ 업무 △△원이면 전결권자?" | **룰 조회**(결정적) | ⭐ LLM 채점 불필요 |
| `impact` | `graph_analytics.impact_by_article` | "제N조 개정 시 영향 조문은?" | **그래프**(결정적) | ⭐ 〃 |
| `defterm` | `defterms.json` | "X란 무엇인가?" | 정의 원문 | 〃 |
| `deadline` | `deadlines.json` | "○○ 후 며칠 이내?" | 오프셋 값 | 〃 |
| (기존) | 청크 | 현행 값·절차·조건형 | LLM 원문대조 | — |

**이 축들의 결정적 정답**은 채점 신뢰도를 구조적으로 끌어올린다(T7·T9 계열 채점기 오판이 원천 차단).
쿼터: 축별 최소 2문항/일(총 40 중 8) — 데이터가 없으면 자동 생략.

**규약(재발 방지)**: 새 파생 인덱스를 만들 때 **평가 축 등록**을 마감 조건에 넣는다
(docs/53 문서관리 매트릭스에 한 줄 추가 — "새 인덱스 → axes.py 등록 여부").

## 3. C트랙 — 이력에서 날짜별 상세 보기 (사용자 질문 ③)

### 3-1. 선택지 비교
| 안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| ⓐ 새 탭 | 원본 유지 | 탭 난립·맥락 단절, **우리 사이트에 새 탭 패턴 없음** | ❌ |
| ⓑ 같은 탭 `/quality?date=` | 기존 게시판 화면 **그대로 재사용**(문항 표·필터 완비) | 이력↔상세 왕복 시 목록 위치 상실 | 🟡 |
| ⓒ **사이드 패널**(공용 `SideDrawer`) | 목록 유지한 채 **날짜를 옮겨가며 비교**, 우리 패턴(문서 드로어·서식 미리보기)과 일치 | 60문항 전체를 담기엔 좁음 | 🟢 |

### 3-2. 채택 — **ⓒ + ⓑ 하이브리드**
> 이력을 훑는 목적은 "**그날 뭐가 틀렸나**"이지 60문항 전체가 아니다.

- 행 클릭 → **사이드 패널**: 그날 요약(정답률·판정 분포·유형별) + **오답·검토필요 문항만** 목록
  (각 문항 = 질문·판정·증거·근거 조문 링크 → 기존 문서 드로어로 진입)
- 패널 하단 **"이 날짜 전체 문항 보기 →"** → `/quality?date=YYYY-MM-DD`(기존 게시판을 날짜 파라미터로
  재사용 — 필터·펼침 그대로)
- 데이터: `web/public/quality/daily/YYYY-MM-DD.json` **이미 서빙 중**(문항 60건에 판정·증거·출처 포함) —
  신규 API 불필요, 패널에서 fetch.
- 접근성·일관성: `SideDrawer`가 Esc·배경 클릭·포커스 이동을 이미 담당.

## 4. 검증 관문
1. **생성 품질**: 복합 문항 20건 표본 — 골든 실존율 100%(게이트), 상황 변수 창작 0건(수동 대조).
2. **다양성 지표**: 은행 말미 패턴 상위 빈도·평균 질문 길이·출처 문서 수 분포를 리포트에 추가
   (다양성이 **측정되지 않으면** 또 정형화된다).
3. **결정적 축 정확도**: amount·impact 축 문항은 룰/그래프와 100% 일치해야(불일치=버그).
4. **회귀**: 기존 단일 문항 채점 불변(하위호환) · `regress_refusal` 통과 · 크론 총 소요 90분 이내.
5. **UI**: verify-quality-history.mjs — 행 클릭→패널·오답 목록·전체 보기 이동·Esc.

**B 실측 메모**
- 축 문항 8건 E2E: 생성(LLM 0회) → 실서비스 답변 → 결정적 채점 = **8/8 정답, 91초**.
- 첫 표본이 출제 결함 4종(조사·잘린 anchor·역산 조항·미완결 정의)을 드러냄 → 전부 게이트화.
  **템플릿 출제라고 안전한 게 아니라, 인덱스가 지저분한 만큼 게이트가 필요하다**는 게 교훈.
- 전결권자 대조는 라벨이 아니라 **직급 원자**로(별표에 `부서장`·`부서장/센터장` 병존).
- 다양성 기준선(A 전): 평균 41.9자 · 말미집중도 16.7% · 출처문서 39 · 축비중 0% → A 이후 재측정.

**A 실측 메모**
- 여정 13종 중 조문 근거 2건 이상 = 출제 가능. 복합 3건 실생성 → 채점까지 통과.
- 스키마는 **파괴하지 않았다**: 대표 `출처`(dict)를 그대로 두고 `출처들[]`·`골든들[]`을 추가 —
  publish slug 심기·검수 신호·원인 분류 등 기존 소비자가 무변경으로 동작한다.
  (spec §1-4의 "출처를 배열로" 초안 대신 채택 — 하위호환 비용이 이득보다 컸다)
- 채점 대조는 2그램+**어간**. 어형 그대로면 '금지한다'≠'금지됩니다'로 정상 의역이 오답이 된다.
  대신 과대 인정 위험이 생기므로 임계 0.45와 부분/검토필요 경계를 회귀로 고정.
- 여정 근거의 40%가 '조 없는 가이드'였다 → 문서 단위 2그램 매칭 추가로 출제 가능 여정 9→12/13.
  (남은 1건 육아시간사용은 근거 문서가 1종뿐 — 복합의 정의상 출제 불가, 데이터 보강 대상)
- 값 토큰 금지 게이트는 사용자 예시("3박5일")형 상황 수치도 함께 막는다. 게이트②(숫자는 근거에
  실존)와 양립 불가라 값 없는 상황 서술로 복합성을 만드는 쪽을 택했다 — 근거 밖 창작 0이 우선.
