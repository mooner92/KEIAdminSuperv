# Spec 01 — "규정에 없다" 과잉거부 개선: 측정기 정밀화 + 결정적 검색 라벨

> 2026-07-24 · Qwythos A/B(eval/ab) 부산물로 발견된 과잉거부를 원인 분해해 설계.
> 관련: docs/58(자가평가) · docs/62 T7(채점기 오류 선례) · docs/12(품질 트랙)

## 0. 배경 — 실측이 뒤집은 가설들

A/B 100문항에서 "과잉거부 8건(Qwen3.5)"이 집계됐다. 통념적 원인 후보를 실측으로 검증한 결과:

| 가설 | 실측 | 판정 |
|---|---|---|
| 임베딩 차원 부족/벡터 오설정 | 과잉거부 8건 중 6건은 정답 규정이 top-5에 **정상 회수**됨 | ❌ 기각 |
| 청킹이 너무 큼 | 걸린 청크 전부 ~240자(중앙값 166자), 골든이 컨텍스트에 100% 포함 | ❌ 기각 |
| 규칙17(무관 유추 금지)이 과함 | 결론부 기준 재분류 시 진짜 거부는 검색실패 1건뿐(옳은 거부) | ❌ 기각 |
| **거부 판정 정규식의 문맥 무시** | "규정에서 **확인된**"(긍정)·정답 후 꼬리 부가문구("서식 내용은 명시되지 않아 원문 확인")를 거부로 오집계 | ✅ **주원인** |
| **임베딩 텍스트에 규정명 부재**(어휘 불일치) | "중복게재?"·"명패 여분?" 2건 — 정답 문서가 top-5 미회수. 조문 청크는 조 헤더만 있고 **어느 규정인지는 벡터에 없음** | ✅ 부원인 |

⚠ 이는 docs/62 **T7과 같은 클래스의 재발**(측정기가 문맥을 안 봄): T7은 정상 거부→오답 오판,
이번(T9)은 정상 답변→거부 오판. **측정기가 틀리면 개선 방향 전체가 오도**되므로 Phase 0이 최우선.

## 2. Phase 0 — 거부 판정기 정밀화 (측정기부터 고친다)

### 2.1 결함 (실측 확정)
1. `규정에서\s*확인` 이 "규정에서 확인**된**"(긍정) 매칭 → 부정형(`확인되지 않`)으로 한정 필요
2. 전체 텍스트 스캔이라 **정답 결론 + 꼬리 부가 안내**("~는 근거에 명시되지 않아 원문 확인 바랍니다")를 거부로 집계 → 두괄식 규약(SYSTEM: 첫 줄 굵은 결론)에 맞춰 **결론부 스코프** 판정 필요

### 2.2 설계
- 신설 `tools/refusal_detect.py` — **단일 정본**(현재 REFUSAL_RE가 4곳에 복제되어 드리프트 중):
  ```python
  def is_refusal(text, head_chars=200) -> bool
  # ① 패턴 정밀화: '규정에서\s*확인되지\s*않' 등 부정형만
  # ② 스코프: 결론부(첫 head_chars, 두괄식 첫 문단)에서만 거부 판정
  # ③ 부가문구 무해화: 결론부 밖의 '명시되지 않' 등은 판정에 불포함
  ```
- 소비처 교체(4곳): `eval/daily_grade.py` · `eval/regress_refusal.py` · `eval/ab_model_test.py` ·
  `tools/app_api.py`(관리자 거부율 통계 — 동일 결함 존재)
- ⛔ **RAG 답변 경로는 불변** — 이것은 측정기 수리이며 SYSTEM·가드레일은 손대지 않는다.

### 2.3 검증 관문
- 표적 회귀: 이번 오탐 실물(초과사례금 "2일 이내"+꼬리문구 / ERP "확인된 4,399건" / 금품등)이
  **비거부**로, 진짜 거부 실물(명패 결론거부 / Qwythos "규정에서 확인되지 않습니다" 결론)이
  **거부**로 판정되는 유닛테스트 (`tools/test_refusal_detect.py`)
- A/B 재채점(`ab_model_test --grade` 재실행) → 실제 과잉거부율 재보고
- `regress_refusal.py` MUST_REFUSE 5/5 유지 확인(거부 감지가 느슨해지면 안 됨)

## 3. Phase 1 — 결정적 검색 라벨 (Contextual Embedding, 안전 4겹)

### 3.1 문제
조문 청크 임베딩 텍스트 = "제7조(…) ①…" — **소속 규정명이 벡터에 없다**.
"중복게재란?"의 정답이 `연구부정행위` 노트에 있어도 본문에 그 단어가 없으면 밀집 검색이 놓친다.

### 3.2 설계 — 안전 4겹(사용자 합의)
| 겹 | 내용 |
|---|---|
| ① 검색 전용 | 라벨은 **임베딩 입력에만** 사용. Chroma `documents`(모델이 읽는 근거)·메타(출처 표기)는 **원문 그대로** — 라벨 오류가 답변·출처에 침투할 경로가 구조적으로 없음 |
| ② 결정적 조립 | 라벨 = 이미 검수된 필드의 **복사**만: `[{규정명}] {분류}` (+ term 노트는 `용어` 필드). LLM 미사용 = 환각 0 |
| ③ (Phase 2 예약) | LLM 요약 라벨은 Phase 1 부족 시에만 — 원문 어휘 제약 + 결정적 검증(근거 밖 규정명·숫자 포함 시 폐기→②로 폴백) |
| ④ 골든 관문 | 별도 컬렉션(`kei_regs_v2`)에 색인 → A/B → **엄격 개선 시만 승격**, 퇴행 시 폐기 |

구현: `02_chunk_and_embed.py`에 `EMBED_CTX_LABEL=1`(기본 off) —
`embs = encode([label(c) + c.text])`, `documents=[c.text]`(원문). 라벨 예:
`[한국환경연구원 연구윤리규정 · 5800_연구] 제7조…` / term: `[용어: 중복게재 · 연구윤리] …`

### 3.3 검증 관문 (승격 조건 전부 충족 시만)
1. **회수 A/B**: 골든 100문 — 정답 규정 top-5 회수율(Hit@5)·Hit@1, 구 vs 신 컬렉션. **신 ≥ 구** 필수
2. **표적 2건**: "중복게재란?"·"명패 여분?" — 신 컬렉션에서 정답 문서 회수 여부
3. **거부형 12문**: 무관 질문에 대한 회수 거리 변화 관찰(라벨이 무관 문서를 끌어올리지 않는지)
4. **E2E**: `verify_trust_gates.py` 6/6 + `regress_refusal.py` 통과(신 컬렉션 지정)
5. 승격 = `RAG_COLLECTION` 스왑(재기동 1회). 실패 = 신 컬렉션 삭제, 코드 플래그는 잔류(무해)

### 3.4 리스크와 대응
- 라벨이 순위를 흔들어 기존 정답이 밀림 → ④관문 Hit@1·Hit@5 하한으로 차단
- 규정명이 모든 청크에 반복되어 "규정명 언급 질문"이 특정 문서로 쏠림 → 거부형 12문 + 골든 전수로 검출
- 재색인 비용 — 5,700청크 1회(~수 분, GPU), Chroma 백업 선행(CLAUDE.md 규약)

## 8. Phase 3 — 정의형 질문 결정적 라우팅 (2026-07-25, 문헌 조사 후 채택)

**문헌 검토**(사용자 지시 — "논문 찾아보고 가장 효과적으로"): 어휘 불일치의 표준 해법 4종 비교 —
ⓐ Contextual Retrieval(색인 시 LLM 맥락, Anthropic 2024 — 결정적 코어는 P1로 기채택, LLM 풀버전은
5,700회 생성+환각검증 부담) ⓑ HyDE(질의 시 가상답변 임베딩 — 쿼리당 LLM 지연 + **9B 가상답변
환각을 검색이 추종하는 위험**, 규정 도메인 부적합 판정) ⓒ doc2query--(청크별 합성질문 색인 —
오프라인 안전하나 대공사·노이즈 필터 필요) ⓓ 구조화 지식 라우팅.

**채택 = ⓓ**: 잔여 실측 실패("중복게재란?")는 **정의형 질문** 클래스이고, 우리는 이미
`defterms.json`(01j — 규정 원문 정의 바인딩 282용어, '중복게재'→학술지발간규정 제17조 정의 포함)
이라는 결정적 인덱스를 보유. LLM 0·환각 0·지연 0으로 문헌 확률 기법보다 이 클래스에 정확.
ⓒ(doc2query)는 이후 **실측 잔여 갭이 확인될 때만** 재개(YAGNI).

**설계**: rag_core `_defterm_route(query)` — ①정의형 패턴("X란?", "X이란/란 무엇", "X(의) 정의/뜻")
감지 시에만 발동(오폭 방지 게이트) ②defterms 용어 최장일치(2자+) ③해당 정의 조문 청크를 Chroma
실조회(규정명+조)해 근거에 **자동첨부**(기존 별표 refs·scope_anchor와 동형, 🔗 배지 흐름) —
충돌용어(11개)는 정의 전부(≤2) 첨부해 정직하게 병기. 토글 `RAG_DEFTERM_ROUTE`.
검증 관문: 표적 E2E(중복게재 정답) · 골든 100 비퇴행 · 거부형 12 오폭 0 · 게이트 6/6 · 유닛.
