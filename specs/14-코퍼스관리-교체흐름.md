# Spec 14 — 코퍼스 관리: 구조 기반 트리 + 개정본 '교체' 흐름

> 2026-08-04 · 운영자: "교체하는 방식으로 가면 내가 문서를 찾아서 교체하는 페이지가 있어야 하나?
> 지금 코퍼스 관리 탭은 문서가 중구난방으로 나와서 그걸 하기엔 복잡해. 구조 md 기반으로 보이게
> 하고 교체 옵션을 잘 설정하면 되지 않을까. 신규는 구조 잘 잡고 구조 md 업데이트 및 적절한
> 위치에 추가되게. kordoc parser면 뭐든 md 변환 가능할 텐데 — 최대한 자동화하자."
> 관련: docs/20·21(코퍼스 관리) · docs/61 K1(kordoc 어댑터) · docs/24(표 무결성).

## 0. 실측 진단 — "중구난방"의 정체

| 사실 | 확인 위치 |
|---|---|
| 업로드 승인 문서는 **무조건 `0000_미분류`** 로 들어간다 | `app_api.corpus_upload_approve` — `sub = "20_규정원문/0000_미분류"` 고정 |
| 규정번호→폴더 자동 배치는 **CLI에만** 있다 | `01_hwp_to_md.py`(파일명 4자리 → 분류 폴더) |
| 분류 표가 **두 곳**에 있다(정본 없음) | `20_규정원문/README.md` 표 · `01_hwp_to_md.py` 상수 |
| 목록이 **평면**이다(폴더 개념 없음) | `AdminCorpus.tsx` — 필터 칩 + 평면 리스트 |
| **교체 개념이 없다** — 업로드는 언제나 '새 문서' | 승인 시 `_slugify`가 충돌하면 `-2` 접미를 붙여 **중복 생성** |
| 업로드 변환기는 hwp-hwpx-parser(표 깨짐 경고) | `app_api._convert_upload` → `01c.extract_hwp` |
| kordoc(+`kordoc_adapt --check`)는 **상위법령에만** 쓰인다 | `01y_uplaw_ingest.py` · `kordoc_adapt.py` |

즉 개정본을 업로드하면 **기존 문서를 대체하지 않고 미분류에 사본이 하나 더 생긴다.**
같은 규정의 두 판본이 함께 색인되면 답변이 어느 쪽을 인용할지 운에 맡기게 된다 — ⛔절대규칙 1이
막으려는 상황 그 자체다. 이것이 이 spec의 존재 이유다.

## 1. 원칙

1. **구조 md가 정본**(`20_규정원문/README.md`의 분류 표) — 사람이 그 표를 고치면 배치 규칙이 바뀐다.
   코드는 표를 파싱해 쓰고, 파싱 실패 시 현재 상수로 폴백(fail-safe).
2. **교체는 교체다** — 개정본 업로드는 새 파일이 아니라 기존 문서의 판올림. 백업 필수.
3. **⛔ 자동 확정 없음** — 배치·매칭·차이 요약까지 자동, **승인은 사람**(볼트 절대 규칙 유지).
4. **변환은 결정적으로 검증** — `kordoc_adapt --check`(형식만 바꾸고 내용 불변 증명)를 통과해야 편입.

## 2. 설계

### A. 구조 정본화 (`tools/vault_structure.py`)
`20_규정원문/README.md`의 분류 표를 파싱 → `{첫자리: 폴더명}`. `01_hwp_to_md`·`app_api` 공용.
새 폴더가 필요하면 **표에 한 줄 추가**하면 된다(코드 수정 불필요).

### B. 신규 편입 자동 배치
승인 시 규정번호(파일명 4자리 → 본문 머리 `NNNN-한글`) → A의 표로 폴더 결정.
번호를 못 찾으면 `0000_미분류` + `90_관리/미분류_분류제안.md`에 후보 기록(기존 파일 재사용).

### C. 교체 흐름 (핵심)
```
업로드 → 변환(kordoc → adapt --check) → **기존 문서 매칭**
   매칭 키: ① 규정번호 4자리(정확) ② 규정명 완전일치 ③ 제목 유사도(후보 제시·사람 선택)
→ 차이 미리보기: 조문 단위 추가/삭제/변경 N건 + 변경 조문 목록(본문 diff는 상위 5건)
→ [교체 승인]  ⛔ 사람만
   · 기존 파일 백업(`90_관리/_backup/<slug>-<YYYY-MM-DD>.md`)
   · 본문 교체 + 프론트매터 갱신(개정일·원본파일) + **검수상태 → 미검수**
   · 재색인 스테일 표시(`reindex_stale`) → 관리자가 ⟳ 재색인
→ 감사 로그(`CorpusAudit` action="replace")
```
⚠ 교체 단위는 **파일 1개**이고 **전문 개정본만** 받는다. 부분 개정문(신·구조문 대비표)은
교체가 아니라 §G의 '개정 반영' 흐름으로 간다 — 아래 실측을 보라.

### G. 개정안(신·구조문 대비표) — 실제로 올라오는 형식 ⭐

**2026-08-04 실측.** 운영자가 실제로 넣을 개정 파일을 받아 열어보니 전문 개정본이 아니었다.
「위임전결규정 개정(안)」(2026.7.15.)은 개정이유 + 대비표뿐이고 별표 매트릭스 본문은 이렇게 적혀
있었다:

```
<td>1.기본계획~27. 홈페이지 운영</td><td>생략</td>   ← 335규칙 본문이 문서에 없다
<td><공통사항><br>- 좌동 -<br><연구업무><br>- 좌동 -  ← 나머지는 "좌동"
```

이 파일로 `replace()`를 돌리면 **651줄 규정이 51줄 요약본으로 덮이고 `approval.json` 335규칙이
사라진다.** §3이 "부분 개정문은 대상 아님"이라 적어두었지만 **거부할 수단이 없었다.**
운영자 지시("앞으로도 이런 파일을 넣게 될 거야")에 따라 이 형식을 1급 입력으로 받는다.

- **판별**(`corpus_amend.classify`, LLM 0회) — 전문 / 개정안 / 혼합 / 불명.
  **강신호**(대비표 제목·`현행|개정(안)` 표머리)만 단독 판정 근거이고, 약신호(개정이유·좌동·
  개정(안) 제목)는 혼자서 못 막는다. ⚠ 관문이 정상 업무를 막으면 사람이 관문을 꺼버린다.
- **관문** — `replace()` 첫 줄에서 `replaceable()`. 실패 시 `replace_blocked` 로그 + 중단.
- **해독**(`parse`) — 개정이유·시행일(부칙 원문에서만)·대비표 행(현행|개정(안)|비고).
  셀 안에 표가 또 있어 **깊이를 세는 파서**가 필수다(정규식 한 방이면 셀이 뭉개진다).
- **위치 짚기**(`propose`) — 각 현행 줄을 볼트 문서에서 찾아 **줄 번호**를 준다. 가운뎃점
  이형(`·/･/‧`)은 정규화해 흡수한다. 실측: 위임전결규정 649줄을 정확히 지목했다.
- ⛔ **자동 적용 없음** — 모듈에 쓰기 경로가 아예 없다(회귀가 소스를 grep해 지킨다).
  "좌동"이 무엇을 가리키는지, "생략"된 매트릭스가 어떻게 바뀌는지는 사람만 안다.
  생략/좌동/별표 행은 **경고를 달아 노출**한다(조용히 넘기면 사람이 못 본다).

### D. 구조 트리 UI
평면 목록 → **분류 폴더 트리**(접기/펼치기, 폴더별 문서 수·미검수 수).
각 행: 제목 · 규정번호 · 개정일 · 배지(검수/재색인 필요) · 액션 `[교체] [제외] [열기]`.
공용 스킨 재사용(BrowseShell·ResultRow·PagedList — 화면별 CSS 사본 금지 관례).
검색은 유지 — 접힌 폴더 안의 문서가 걸리면 그 폴더를 펼쳐 보여준다.

### E. 변환기 kordoc 승격
업로드 경로를 kordoc + `kordoc_adapt`로 전환(현행 hwp-hwpx-parser는 폴백).
이득: **표를 HTML로 보존**(현재 "표 깨짐 가능" 경고의 주원인 해소) + `--check`로 내용 불변 증명.
⚠ kordoc은 Node CLI라 부재 환경에서는 자동 폴백해야 한다(설치 여부 런타임 감지).

### F. 재색인 후속 자동화
현재 재색인 워커는 `백업 → 01p(별지) → 02(청킹·임베딩)`까지다. **파생 인덱스는 그대로 남는다**
(`article_status`·`clause_xref`·`defterms`·`deadlines`·`approval`·`journey_freshness`).
→ 워커 끝에 파생 인덱스 재생성을 붙인다(전부 결정적·LLM 0회, 순서 `01b→01i→01j→01k→01k2→01m→01n`).
부분 실패는 로그만 남기고 재색인 자체는 성공으로 둔다(검색은 이미 최신이므로).

## 3. 하지 않을 것

- 개정문(부분) 자동 병합 — 어느 조문을 어떻게 바꿀지 LLM이 판단하게 두지 않는다(⛔절대규칙 1·2).
  §G는 **판별·해독·위치 짚기까지**다. 대비표 글자를 옮기고 볼트에서 그 자리를 찾아주는 것이
  자동의 끝이고, 반영은 사람이 한다.
- 자동 검수완료 전환 — 교체 후에는 항상 `미검수`.
- 폴더 자유 편집 UI — 구조는 md 표에서 바꾼다(정본 하나 유지).
