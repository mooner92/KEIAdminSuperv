# Spec 06 — 금액 룰 엔진: "이 금액이면 무엇을 해야 하나" 결정적 판정

> 2026-07-26 · 사용자 방향 "깊이 파고드는 레벨" 2순위. 행정 절차의 절반은 **금액 구간의 함수**
> (전결권자·일상감사·수의계약·심의)인데 지금은 사용자가 여러 규정을 직접 조합한다.
> ⛔ 설계 원칙: **LLM은 판정하지 않는다** — 판정은 룰 테이블의 결정적 조회, LLM은 서술만.
> (절대규칙 1과 정합 — 환각이 구조적으로 불가능한 경로)

## 0. 실측 전제 (2026-07-26 진단 — 이 스펙의 출발점)

**`value_store.json`이 0행인 진짜 원인**: 코드 버그가 아니라 **frontmatter `검수상태: 검수완료`인
문서가 볼트에 0개**다(01q 실행 로그: "미검수 제외 688문서 · 0행". ⚠ grep으로 111개가 잡히는 것은
본문 속 안내 문구 오탐 — frontmatter는 전부 미검수). 01q의 적재 조건(검수완료+비손상 표)은 ⛔무환각
원칙상 옳으므로 **조건을 완화하지 않는다**. ⟹ 이 스펙은 두 트랙으로 분리:

- **트랙 A(즉시)**: 이미 구조화·검증된 인덱스(approval 335규칙)만으로 판정기 1차 가동
- **트랙 B(검수 동반)**: 금액 한도 표(일상감사·수의계약·심의)를 **사람 검수 → value_store 적재**로
  점진 확장 — 검수 워크플로가 본질이라 서두르지 않는다

## 1. 딛고 서는 데이터

| 소스 | 내용 | 상태 |
|---|---|---|
| `approval.json`(01n) | 전결 335규칙 — **금액 구간 32규칙 실측**("200만원 이하→실·팀장 · 200만~1,000만→부서장 · …") | ✅ 즉시 사용 가능 |
| `value_store.json`(01q) | 검수완료 표의 수치 행 | ⛔ 0행 — 트랙 B에서 채움 |
| conflict_audit 실사례 | 일상감사 하한 100만원(내부감사규정 별표1)·업무추진비 50만원 등 | 검수 1순위 후보 |
| `deadlines.json` | 절차별 기한 | ✅ 부속 표시용 |
| byeolji_manifest | 절차별 필요 서식 | ✅ 부속 표시용 |

## 2. 사용자 스토리

1. "**소모품 370만원 구매**" → 전결: 부서장/센터장(가지급금 200만~1,000만 구간) · 일상감사: 대상 여부
   (트랙 B 검수 후) · 관련 서식·기한 링크. **모든 값에 [규정 별표 원문행] 근거 첨부.**
2. "법인카드로 **60만원 업무추진비** 결제" → 전결 + ⚠일상감사 경계(ERP 안내 60만 vs 규정 50만 —
   실충돌 2건이 바로 이 지점: 룰 엔진은 **충돌을 숨기지 않고 병기**한다).
3. 챗봇: "300만원 수의계약 가능해?" → 룰 조회 결과를 근거 블록으로 첨부, LLM은 서술만.

## 3. 설계

### 3-1. 룰 계층 — `tools/01r2_amount_rules.py` (신규, 결정적 추출)
- 입력: `approval.json`(트랙 A) + `value_store.json`(트랙 B, 생기는 대로 자동 합류)
- 파싱: 업무 문자열의 금액 구간(`(\d[\d,]*)(만원|억원?) *(이하|초과|이상|미만)` 및 "A 초과 ~ B 이하"
  쌍)을 **구간 객체**로 정규화: `{min, max, min_incl, max_incl}`. 실패 항목은 rules에 넣지 않고
  `unparsed[]`로 분리(⛔ 어설픈 추측 금지 — 32규칙 전수 수동 대조가 관문).
- 산출: `tools/index/amount_rules.json` =
  `{ 업무키: { 구분, 업무경로, 구간[]: {range, 전결권자, 협의, 원장결재, 근거(원문행·규정·조)} } }`
- **구간 무결성 검사 내장**: 같은 업무의 구간이 겹치거나 구멍이 있으면 빌드 실패(경고 아님 —
  룰 엔진의 오답은 환각보다 위험하다).

### 3-2. 판정기 — 순수 함수(`tools/amount_judge.py`)
```
judge(업무키, 금액, 직급?) → { 전결권자, 협의, 원장결재, 근거[], 부속: {서식[], 기한[], 관련규정[]} }
```
- 경계값 정책: 원문 표현 그대로("이하"=포함, "초과"=비포함) — 경계 금액 질문("정확히 200만원이면?")
  이 가장 흔한 실수 지점이라 **유닛 테스트를 경계값 중심으로**.
- 미커버 구간·미파싱 업무 → `판정불가` 반환(그럴듯한 근사 ⛔).

### 3-3. 화면 — 결재선 판정기(/approval) 확장 (신규 페이지 아님)
- 기존 화면에 **금액 입력 1칸** 추가(공용 스킨 유지): 금액을 넣으면 335규칙 목록이 **해당 구간만**으로
  좁혀지고, 카드에 "왜 이 전결인가"(구간·근거 원문행) 표시.
- 부속 패널: 관련 서식(미리보기 패널 재사용)·기한(기한 사전 행 재사용)·관련 규정 링크.
- 플래그: `amount_judge`(기본 off).

### 3-4. 챗봇 연동 — `amount_route`(defterm_route와 동형)
- 감지: 금액 토큰 + 절차 키워드(구매·계약·집행·법인카드·전결·감사…) → judge() 결과를 근거 블록
  첨부(`amount_route` 배지). ⚠ 수치 게이트(P0-1)와의 상호작용: judge 근거의 금액은 허용집합에
  포함시켜 이중 경고 방지.
- 토글 `RAG_AMOUNT_ROUTE`(기본 off — 골든 A/B 후).

### 3-5. 트랙 B — 검수 워크플로(별도 착수 판단)
- /admin 신뢰 탭에 "금액 표 검수 큐": conflict_audit high 항목(일상감사 100만·업무추진비 50만 등)
  이 1순위 후보. [검수 확정] 시 해당 **표 블록 단위**로 frontmatter가 아닌 `표검수` 마커 부여 검토
  (문서 전체 검수완료보다 현실적 — 01q 조건을 "문서 검수완료 **또는** 표검수 마커"로 확장).
- ⛔ 검수 확정은 사람만(기존 원칙 그대로). 이 트랙은 규모가 있어 **별도 스펙으로 분리 예정** —
  본 스펙 범위는 A트랙 + B트랙의 데이터 계약 정의까지.

## 4. 검증 관문
1. 유닛: 구간 파싱(32규칙 전수 스냅샷 대조) · 경계값(이하/초과/이상/미만 각각) · 겹침/구멍 빌드 실패.
2. 실사례 회귀: "가지급금 370만원 → 부서장/센터장" 등 5건 수동 정답표.
3. 챗봇 A/B: amount_route on/off 골든 100 비퇴행 + 신뢰 게이트 6/6(특히 수치 게이트 이중경고 없음).
4. 실렌더: verify-approval-amount.mjs(금액 입력→구간 필터·근거 표시).
