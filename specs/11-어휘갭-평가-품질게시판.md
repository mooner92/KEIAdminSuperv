# A부. 어휘 갭 평가 — "쉬운 시험" 문제

## A0. 문제의 구조

현 출제: 청크 → LLM이 그 청크에서 질문+골든 생성. **질문 어휘 ⊂ 문서 어휘**가 구조적으로
보장된다 → 검색이 거의 항상 이긴다 → 검색실패가 과소측정된다(08-02 실측 검색실패 2/60뿐).
그런데 실사용 실패는 대부분 어휘 갭이다(과거 실측: "명패 여분?"·"중복게재?" — 정답 문서가
top-5 미회수. 별칭 사전을 보류한 이유도 "문서어 시험에선 검색실패가 희귀해서"였다 —
**측정이 문제를 안 보이게 만들고 있었던 것**).

## A1. 핵심 설계 — 골든은 유지, 질문만 눈 가리고 다시 쓰기

```
1단계(기존): 청크 → {질문₀, 골든}          ← 골든은 원문 verbatim(채점 키)
2단계(신설): 질문₀ → 패러프레이저 LLM       ← ⛔ 원문·골든을 주지 않는다(blind)
             "규정 용어를 모르는 직원이 같은 것을 묻는 말로 바꿔라"
             → 질문₁ (일상어)
채점: 골든 불변 → 기존 채점기 그대로       ← 채점 가능성 보존이 이 설계의 전부
```

**결정적 게이트(동어반복 필터의 반전)**: 질문₁과 원문 청크의 내용어 2-그램 겹침이
**상한을 넘으면 패러프레이즈 실패로 폐기**(문서어가 남아 있다는 뜻). 기존 필터가
"질문이 골든을 되읽으면 안 됨"이었다면, 일상어 문항은 "질문이 문서 어휘를 쓰면 안 됨" —
같은 도구의 방향만 뒤집는다. + 기존 결함 사전(question_defects)·검수자 그대로 통과해야 함.

**문항 스키마 확장**: 필드 `어휘층` = `문서어`(기존) | `일상어`(2단계 산출).
같은 골든을 공유하는 문서어/일상어 쌍은 `쌍id`로 연결 — **같은 정답을 두 어휘로 물었을 때
결과 차이가 곧 어휘 갭의 크기**다.

## A2. 실사용 어휘의 유입 — 문서 없이 만드나? (질문에 대한 답: 절반만)

"문서 없이 생성"은 절반만 맞다. 세 경로를 구분한다:

- **경로 ⓐ 일상어 패러프레이즈(A1)** — 골든이 있어 **정답률 채점 가능**. 주력.
- **경로 ⓑ 무골든 커버리지 프로브** — 페르소나·상황만으로 질문 생성(문서 안 봄).
  골든이 없어 정답 채점은 불가 — 대신 **회수·거부만 측정**(근거 회수 여부, 거부율).
  용도가 다르다: 정확도가 아니라 **콘텐츠 갭 탐지**(물었는데 답할 문서가 없는 영역).
  주말 대량 회차의 일부(예: 50문항)로만 편성, 게시판에 별도 표기(정답률 분모에서 제외).
- **경로 ⓒ 실사용 시드** — 이미 있는 k-익명 집계(인기 키워드·거부 질문 통계, docs/12 P2.5)를
  출제 시드로 주입: "직원들이 실제로 '연말정산'을 많이 묻는다 → 그 주제의 일상어 문항을
  우선 생성". ⛔ 개인 채팅 원문을 눈으로 읽는 경로는 만들지 않는다(관리자도 본문 미열람
  원칙 유지) — 집계 통계만 시드로 쓴다.

## A3. 이 데이터로 무엇이 열리나 (쌓는 이유)

1. **어휘 갭이 숫자가 된다**: "문서어 92% vs 일상어 78%" — 갭 14%p가 개선 대상 지표.
2. **보류했던 별칭 사전이 측정 가능해진다**: 일상어 문항에서 검색실패가 유의미하게 나오면,
   별칭 사전·검색 라벨 확장을 A/B로 입증할 표본이 생긴다(이전 보류 사유 해소).
3. 페어 설계라 **회귀 추적이 정밀**: 같은 골든의 문서어는 맞고 일상어만 틀리면 100% 검색 문제.

## A4. 배분(주말 500 기준 제안)

| 어휘층 | 비중 | 채점 |
|---|---|---|
| 문서어(기존) | 45% | 전체 채점 |
| 일상어(신설) | 40% | 전체 채점(골든 공유) |
| 무골든 프로브 | 10% | 회수·거부만 |
| 거부형(기존) | 5% | 거부 여부 |

평일 200은 문서어 55%/일상어 40%/거부형 5%(프로브는 주말만 — 사람 검토가 필요한 산출물이라).

# B부. 품질 게시판 개편 — 하루 60 → 최대 1,500 시대

## B0. 문제

- 하루 최대 3회차(날짜·b·c) — 현 게시판은 날짜 1키 전제.
- 문항 1,500건을 평면 나열하면 아무도 안 본다.
- 약점 매트릭스(주제×유형 누적)는 지금도 **즉석 파이썬으로만** 존재(08-01 실측).
- 오답이 하루 수십 건 — "수술 대기 목록"과 "측정 노이즈"가 섞여 보인다.

## B1. 정보 구조 — 3층

```
1층 오늘 요약(히어로): 일 단위 합산 정답률 + 코호트 2종 + 어휘갭 1종
   - 회차(날짜·b·c)는 합산이 기본, 회차별은 펼침. ⚠ 합산 시 재시험 중복 문항은 최신 판정 기준
2층 추이·지도:
   - 추이 그래프: 전체·재시험·일상어 3선(재시험이 개선 증명선 — 시각적으로 최상단 강조)
   - 약점 매트릭스 상설화: 주제×유형 누적 미정답률(즉석 계산의 정식화, 표본 8회 미만은 회색)
   - 어휘 갭 패널: 문서어 vs 일상어 정답률 + 쌍 불일치 목록(같은 골든, 다른 결과)
3층 문항 브라우저:
   - 공용 스킨 재사용(BrowseShell+BrowseFilter+PagedList — 화면별 CSS 사본 금지 관례)
   - 필터: 날짜/회차·판정·실패유형·어휘층·주제·코호트
   - 기본 뷰 = "수술 대기"(검색실패·생성환각만 — 골든품질·부분정답은 기본 접힘:
     노이즈와 수술감을 섞지 않는 게 이 화면의 존재 이유)
```

## B2. 데이터 계약(daily_publish 개편)

- `web/public/quality/daily/<date>.json` 유지(회차별) + **신설 `web/public/quality/day/<YYYY-MM-DD>.json`**(회차 합산) + `matrix.json`(누적 약점 매트릭스 — 매 실행 재계산).
- 합산 규칙 명시: 같은 hash가 하루 여러 회차에 나오면 **최신 회차 판정**만 집계(이중 계상 금지).
- 무골든 프로브는 `probe: true`로 분리 — **정답률 분모에 절대 불포함**(분모 오염 = 측정 조작).
- 게시판 공개 원칙 유지: 질문 텍스트는 표시하되 답변 본문·사용자 정보 없음(기존과 동일).

## B3. 비목표

- 실시간 대시보드·별도 DB — 정적 JSON + 클라이언트 렌더 유지(현 구조로 충분).
- MLflow UI의 대체 — 게시판=사용자·운영자 열람용, MLflow=실험 비교용(specs/10 역할 구분 유지).
- 골든 보수 UI — CLI(golden_repair) 유지, 게시판은 후보 링크만.
